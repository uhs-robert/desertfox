# Hints

Area: hints, grab and actions.
READMEs: `src/content/hints/README.md`, `src/content/grab/README.md`, `src/content/site_actions/README.md`, `src/content/lib/README.md`, `src/devtools/README.md`, `src/background/README.md`.
Source: `src/content/hints`, `src/content/grab`, `src/content/site_actions`, `src/devtools`, `src/background`.

### Hints

- Candidates come from one query per filter (all, every, clickable, buttons, inputs, links, prose, scrollable, media, images): a selector plus an optional test, such as `prose` keeping elements with a text node of their own. The search reaches open shadow roots and, through Firefox's `openOrClosedShadowRoot`, closed ones.
- An IntersectionObserver batch finds visible candidates. An `elementFromPoint` check removes covered ones.
- Labels render in a closed shadow root. All layout reads happen before any write.
#### Typed text narrows hints

- Typed text narrows hints. `/` switches hint mode from typing a label to typing text, for every filter and action. In label mode Space turns rapid mode on or off, Tab turns overlapping labels forward and Shift-Tab back (see Label stacking). In a narrowed `drop` pass of a grab, the first Tab labels every element instead, and later Tabs turn labels. In text mode every one-character key is text and Space is part of it, so a query can hold several words. Hints keep their letter labels, but only for display.
- The matches rank by `rank.ts`: a whole first word scores 8, a whole later word 4, a first-word prefix 6, a later prefix 2 and a substring 1, summed over the query words (each must match) and divided by the log of the text length, so a short text wins a tie. Ties keep page order. The best match is active and shows with swapped colors, Tab and Shift-Tab move the active hint, Enter picks it, and a single remaining match picks at once. A key that matches nothing is dropped, as in label mode. In text mode `/` is text.
- Backspace trims the text, and on empty text it returns to label mode with every label back. The key that enters or leaves text mode never picks. The text of a hint is its visible text, else `aria-label`, `title`, the `alt` of a picture in it, or an input value, cut to 400 characters. The name list is shared with the link copy list and the next-page search (`name_candidates`), and a password value is never read. It is read once, on the first `/`. A rapid rebuild starts in label mode.
- The `text` param is only a launch filter and does not start text mode, so the labels stay typable. Tab, Shift-Tab, Enter and Space are bound in the hint keymap to the hidden command `hint.key` (the `hint.key` values keep their names, only the label-mode meaning of Space and Tab changed), so the content script holds them while the hints bundle loads. `/` has a row in the same keymap for its which-key label only, because the content script already holds every one-character key. The bundle sink takes them first once hint mode is open, so rebinding them changes nothing, and unbinding one only drops that hold.
- While hint mode is open a key line shows at the bottom right, where the mode badge sits (the badge is hidden in hint mode). It reads `/: type text · Space: rapid · Tab: turn labels` in label mode (`Space: stop rapid` once rapid is on, no Space part for an action that never repeats, and `Tab: every element` in place of `Tab: turn labels` in the narrowed target pass of a grab) and `Enter: pick · Tab: next · Backspace: labels` in text mode. The words are fixed, not read from the keymap. The `hint_key_line` setting (default on) hides it. A match that typed text made unique picks after a 300 ms grace with hint mode still open.
- The keys that arrive in the grace are dropped, so the rest of a typed word never runs as normal keys or as labels of the next round. Enter picks at once, and Escape in the grace cancels the pick.
#### Grab

- `;g` and `;G` are modifiers (like `;2`) that set the `grab` and `grab_move` actions of `hint`, so `;gb` grabs a button and `;ga` any element. The default group is `;gg` and `;Gg`, the `draggable` filter: `draggable="true"` elements, range inputs, ARIA sliders, scrollbars and separators, `aria-grabbed` and sortable handles, library handles, and any element that sets a grab, move or resize cursor where it starts or `touch-action: none` (which pointer-driven cards set). A widget with none of these signs and no role, such as a plain div thumb with the default cursor or a SortableJS item (native before its first press, or in fallback mode), is not in the group: reach it with `;ga` (the `every` filter). A link, image or plain button is in the group only when it sets `draggable`. The `links` filter is refused for both grabs by the `value_when` rule. `hint_add` and `hint_remove` apply to `draggable` per site. The hints bundle hands the pick to `grab.js` the way it hands a caret pick to `caret.js`: the element goes in a window slot and the bundle's `<bundle>.mode` handler reads it.
- `;g` picks an element, then runs `hint` again for the target (the internal `drop` filter) and drives a drag from one to the other in eight steps. A macro records it as one `hint.run`, because the target hint passes a bundle-internal `nested_` arg that skips the record.
  - The `drop` filter (`src/content/lib/drop_targets.ts`) labels where the source can likely go, because a page does not declare its drop targets: the elements that share the source's tag and a class, test id, role or `draggable` (the other cards), their parents (the columns), the siblings of each ancestor of the source (an empty column, a trash box beside the board) and the marked drop places (`ondrop`, `ondragover`, `dropzone`, `aria-dropeffect`, the react-beautiful-dnd droppable ids, `.ui-droppable`, `.ui-sortable`). A pointer widget (slider, scrollbar, separator) or a source with no kin gets every element, and so does any pass that shows fewer than two places. Tab in label mode switches the labels to every element, the one guard against a place the guess missed. A page-world hook for drop listeners is not built: React and Pragmatic drag and drop listen at the root, so a hook would say little.
- `;s` swipes: it picks from the `swipeable` filter (the `draggable` signs, scroll-snap boxes, boxes that set `touch-action: pan-x` or `pan-y` but not both (Embla with its own class names) and `.swiper`, `.splide`, `.embla`, `.glide`, `.slick-list`, `.flickity-viewport` containers) and enters grab mode with `h j k l` as flings, where `l` shows the next slide. A scroll-snap box scrolls by one view with `scrollBy` and gets no pointer events. Any other target gets a pointer fling forced onto the pointer route (a short fast drag, 60% of the box in 6 steps, with a pause of at least 30 ms that grows with the box to hold about 2 px per ms, which Splide reads as one slide, never a native drag of a link or picture). Each fling releases itself. Fast keys queue, up to two waiting, and each fling finishes and settles for 350 ms before the next starts (Splide and Swiper ignore a press during the slide change, and 350 ms fits their default speed, so a slider with a slower transition can drop a fast second press). A key past the cap is dropped. The mode stays open until Escape, whose exit drops the queue and releases anything held. The New window modifier is `;n`.
- `;G` picks an element, presses it and enters grab mode. The press lands on the slider's thumb (a child with `role=slider`, else the place `aria-valuenow` gives along the box, else the middle), so a slider that reads the pointer position does not jump on grab. `h j k l` move it one step, which starts at `grab_step_px` (3 px by default, from 3, 6, 12, 24, 48, 96 or 192) on each new grab. `[` halves the step and `]` doubles it (3 to 192 px, shown in a toast), and a range input keeps its native step. Enter drops it. Escape on a range input or a draggable element puts it back to where it began first. On the pointer route Escape releases where the element is, because a move back would set a position-reading slider to the press point. The sink of grab mode passes every key to the keymap and exists for its exit, which every way out of the mode reaches: Escape, a second command, a page that goes hidden. The exit is the one place a held drag is released.
- The source picks the route, after a press with pointerdown and mousedown, because a library such as SortableJS makes its items draggable in its own pointerdown handler. A draggable source gets DragEvents with a new `DataTransfer`. A range input gets a value plus `input` and `change`, and `change` only when the value changed. Any other source gets pointer and mouse events, with no mouse events after a cancelled pointerdown. A drag always ends with its closing events, also on a cancel. The toast says that the drag ran and nothing about what the page did, because the page's reaction cannot be read.
- The events are untrusted, so a page that checks `isTrusted` ignores the drag. A drag stays inside one frame and cannot reach another tab or app, which needs real input through the native host, not yet built.
#### Label stacking

- Tab in label mode turns the stacking order of overlapping labels, and Shift-Tab turns it back. Each press reads the label boxes again, groups the boxes that cover each other, and sends the top label of each group to the bottom (Shift-Tab: the bottom one to the top), so a covered label comes to the top. Space used to turn labels. It now turns rapid mode on or off, so a user who learned Space as the turn key presses Tab instead.
- Space in label mode turns rapid mode on for the rest of the run, as `--rapid` does from the start, and a second Space turns it off. Rapid mode repeats for open in a background tab or a new window, copy (one collected list), download, delete, hover, double-click, inspect, play or pause, and a click on a button. It does not repeat for caret, visual, the grabs, `prompt`, `enter_item` and `enter_media`: Space shows "This hint action does not repeat" and hint mode stays for one pick. A pick that focuses a field (`here` or `focus` on a text field, a select or an editable) ends rapid mode, also with `--rapid` from the start, so the user can type. In text mode Space is part of the query.
#### Actions

- The actions are open, background tab, new window, start caret mode, start visual mode, copy link, copy text, copy CSS selector, copy outer HTML, select in the DevTools Inspector, delete element, focus, hover, double-click and, on a video or audio element, play or pause, mute or unmute and fullscreen. Hover sends the pointer events a mouse sends on entering (over, enter and move), from the middle of the element, so a menu or preview that a script opens appears.
- `;f` is the Focus modifier: `;fl`, `;fi`, `;fb`, `;fa`, `;ft`, `;fm` and `;fI` pick as `;l`, `;i`, `;b`, `;a`, `;t`, `;m` and `;I` do and focus the element without clicking it. `;ff` focuses a frame, `;fs` a scroll box and `;fh` a heading (the `headings` filter, short flag `-T`, labels the headings `]h` counts). `;fF` is `frame.exit` and `;fe` is `page.focus_input`, as `gF` and `gi`. A heading takes focus through `tabindex=-1`, which it sets and leaves in place, so `j` starts there. `zt`, `zz` and `zb` align the focused heading, as they align a focused field.
- The next hover, Escape, a hidden tab or another pick ends it, and a pick inside the hovered element keeps it entered. A CSS `:hover` rule does not react, because synthetic events do not set it. Double-click (`;2`, `double_click`) sends the over events, then two presses (pointerdown, mousedown, pointerup, mouseup, click) with click count `detail` 1 and 2, then `dblclick`, all from the middle of the element. The clicks are dispatched events and not `click()`, because `click()` carries no count.
- The events are untrusted, so a page that checks `isTrusted` ignores them, and Firefox selects no word for them, so on a text node under the middle point the action selects that word with `caretPositionFromPoint` and a word range from `Intl.Segmenter`. A field and a box with no text get no selection change. Links, and elements inside a link, get no label in this mode, because the first click would navigate away. The `links` filter is refused by the `value_when` rule. Rapid mode keeps hints open for several picks.
- With `copy` or `copy_text` it collects the picks into one list instead: the first pick of an entry wins, a repeat adds nothing, and every pick rewrites the clipboard (and the `"a` register) with the whole list, one entry per line, so the list is right at Escape and survives a navigation. The toast counts the entries. `;Y` is `hint --copy --links --rapid` ("Copy several link URLs"). The `prompt` action (short `-L`, the `;:` modifier, so `;:l` and `;:a`) puts the address of the pick in the command line for editing.
- The `command` param (default `open`, valid only with `prompt`, a command name and flags by a pattern, so no pipe, no chain, no quote) is the text typed before the address, and the content script writes `<command> <address>` with the address single-quoted when the line would split or misread it. It is a prefix the user sees and edits, never a command string the extension runs: Enter submits the line through the one validator like any typed line.
- The line opens in the frame that ran the pick, and the `hint.run` answer stays pending until Enter or Escape, as for `;u`. An element with no address refuses with "This element has no web address", and `rapid` is ignored. The `media` filter labels visible `video` and `audio` elements, and skips the cover test because site controls lie over a player. `;m` runs `play_pause` on the pick, through the conditional `action` default for `filter=media`.
- Fullscreen shows the player box, the outermost ancestor with the size of the element, so site controls and subtitles stay, and a second pick leaves fullscreen. A hidden `<audio>` has no box and gets no hint, and a player in a cross-origin iframe is out of reach unless the hints run with `--all-frames`. The `images` filter labels an `img`, an image button and a box with a CSS background image, each rendered at least 24 px on both sides, and skips the cover test because a card lays a stretched link over its picture.
- Inline `svg` gets no label, because it has no address. `;I` opens the pick in a new tab, through the conditional `action` default for `filter=images`. Copy and open use the address of the element itself, never an ancestor's: for an image in a link, the `images` filter gives the picture and the `links` filter gives the `href`. An image address is `currentSrc`, then `src`, then a lazy `data-src` resolved against the page, and a web address wins over an inline placeholder.
- Under the `images` filter a CSS background image wins over the `href` of its own link. A `blob:` address, or a `data:` address over 8 KB, counts as no address. A short `data:` image can be copied but not opened, because Firefox refuses a `data:` URL in `tabs.create` ("Illegal URL", checked in Firefox 159), so open actions skip it and show no label for it. Under another filter, a copy of a picture or media element with no address refuses with "This element has no web address".
- `;u` opens the command line with `hint --custom `, so a typed CSS selector labels its matches. The selector is the verbatim main param of `hint`, so the line hands it over exactly as typed: a selector with spaces or double quotes (`.card a`, `a[href="/x"]`) needs no quoting, and a quote typed around it stays in the value. Flags go before it, and a selector that starts with `-` needs `--` first. The long flag `--filter custom` does not parse: an enum is set by its value as a flag.
- The `every` filter (short `e`, bound to `;a`) labels each visible element with a size, except a wrapper of one element child and no text of its own, and a link, button or label is exempt from that skip.
- The eight `;y` yank keys are plain `hint.run` bindings with a fixed action and filter, so they have no filter step and no modifier variants: `;yl` copies a link address, `;yi` the picture itself (`copy_image`, images only), `;yI` the image address, `;ym` the media address, `;yf` the frame address, `;yt` the text, `;yc` the CSS selector and `;yh` the outer HTML of any element, both with the `every` filter.
- `copy_selector` gives the shortest selector that is unique in the root of the element (the document, a shadow root or the frame's document, so it is relative to that root), preferring `#id`, then `tag`, `tag.class` or `tag:nth-of-type(n)` steps up to the nearest unique id. An id or class that looks generated (four or more digits in a row, eight or more hex digits, or a `css-`, `sc-` or `jsx-` prefix) or that needs CSS escaping is skipped.
- `copy_html` copies the whole `outerHTML` with no cap and leaves out shadow content. The toasts read `Copied selector` and `Copied HTML`. `;o` modifier (`inspect`) selects the pick in the Inspector of the tab's open DevTools, so `;oa` takes any visible element (the `every` filter, which also reaches a plain `div` or `span`), and `;ol` a link. The manifest has a required `devtools_page` (`devtools.html`), and each toolbox loads it.
- The content script sets `window.wrappedJSObject.__desertfox_pick` to the element and sends `inspect_pick`. The background relays it, by tab id, to the devtools page, which evals one constant string that deletes the property and passes the node to `inspect()`. A single eval keeps a second pick in rapid mode from being deleted between a separate select and delete. The node never travels as text, and no page data goes into an eval.
- With no toolbox open the page shows "press F12", and the pick waits 60 s in `storage.session` for the page to connect. A navigation or a closed tab drops it. The action skips the cover test, and an element in a cross-origin frame, or a pick made from a frame, is refused. After a pick, Firefox leaves focus in the Inspector, and the way back takes two keys (see firefox-behavior.md). The `;d` modifier (`download`, for images, links, media and all) saves the file at the address, so `;dI` saves a picture.
- Both send the address to the background. A copy fetches it with no Referer and with `credentials: "include"` for a tab in the default container, but with `credentials: "omit"` for a private or container tab, so it never borrows the default cookies. A picture behind a login then refuses in such a tab, and a site that blocks hotlinks refuses everywhere. The fetch times out after 20 seconds. A PNG or JPEG goes to `clipboard.setImageData` unchanged, read by its first bytes.
- Any other format, SVG included, is drawn and converted to PNG, and a GIF keeps its first frame. A copy over 20 MB is refused, and the read stops at the cap when the server sends no length. A download hands the http, https or `data:` address to `downloads.download` with the tab's private and container context and no forced file name, so the browser fetches it, streams it to disk and honors `Content-Disposition`. It needs the required `downloads` permission.
- A fetch, conversion, clipboard or download-start failure refuses with a message naming the step, and the clipboard stays as it was. The `frames` filter labels `iframe` and `frame` elements rendered at least 24 px on both sides, visible and uncovered, in the page and in same-origin frames, and never the command line frame. `;ff` focuses the pick, through the conditional `action` default for `filter=frames`, with the short flag `-E`. A subframe gets its content script on its first focus, so keys act inside it.
- A focused subframe keeps the keys and every action, and the top frame draws what does not touch the frame's own content: the command line and its list, the `/` and `?` search input, the which-key panel (the marks and registers lists too) and the toasts. The mode badge and the media panel already drew there. Hint labels, find highlights, the caret and visual marks and grab stay in the frame, because they sit on its elements. Site rules still follow the frame's own address, and which-key lists the frame's keys.
  - A bundle in the subframe asks the background to run one of its handlers in the top frame (`relay`, with the allow list in `src/shared/relay.ts`). The line drawn for a subframe gets a ticket that names it, so a command run from that line, its headings and marks lists and its page search act in the subframe. The status line shows the subframe's scroll place. When the line closes, the focus goes back to the subframe. A top frame under 120 px tall leaves the line to the subframe, and so does a top frame that does not answer.
  - The badge shows FRAME while a subframe in normal mode holds the focus. After `;ff` picks a frame, one toast in the top frame says "Keys act in this frame. gF returns to the page.", with the key bound to `frame.exit`, and only the first sentence when none is bound. Escape stays with the page and does not leave a frame.
  - A frame of another origin that takes the focus on its own is parked: the background hands the focus back to the top page through the `gF` path (`focus_page` to frame 0), so `j` scrolls the page at once and a sign-in popup frame no longer holds the keys. A frame is parked at its first focus only, when it is cross-origin to the tab's address (http and https origins), has had no click or key (`navigator.userActivation.hasBeenActive`) and does not hold a text field. The frame reports `activated` and `in_field` with `mode_changed`, a task after its focus event, because its window focus comes before its element's focus. A Tab into a frame looks the same to the frame as a focus on load, so a Tab user is parked once and the next Tab enters the frame. A frame on a field, a same-origin frame and a frame the user clicked keep the keys as before.
  - The park is a record in the tab's mode record (`parked`, and `focused_once` for every child frame that has had its first focus). The record goes with the tab and with a top page navigation, so a new page parks its frame again. A frame that navigates or reloads on its own keeps its id and stays in `focused_once`: the once-only rule lasts for the frame's lifetime, and is not keyed by the frame's address. A focus of the parked frame ends the park when it has a click or key in it, or comes after the frame was blurred: a hint that moves the focus in, or Firefox giving the focus back (which ends in frame mode, as before, and never parks a second time). A mode-change report of the same focus, which can reach the background before the blur, ends nothing. Every focus the extension moves into a frame (`;ff`, a `here` pick on a frame, a hint pick inside a frame) first marks the entry through one helper. A frame that marks names itself. The top page cannot name a frame of another site, so its mark covers the next first focus of any frame. A mark lasts 3 s and only a first focus spends it. The background asks the frame first whether it is still free (no click or key reached it), and the top page then blurs only its iframe element, so a click that lands in the hand-back or a field the page focused meanwhile is not undone. The park blurs the frame, so a popup that closes on blur closes. The field read is one task late, so a frame that focuses its field after an async step is parked as a non-field.
  - The top page hears the park in `frame_mode` (`parked`), and its `f` then labels the page and the parked frame only, through the hints collection of `hint --all-frames` limited to that frame (injection and ask by frame id). A parked frame that is gone refuses the injection, which ends the wait at once and drops the record. With no parked frame the default `frames` setting asks no frame.
  - When the focused frame hides, the focus returns to the top frame. Firefox does this itself for `display: none` and `visibility: hidden`. The top frame checks the focused frame element every 300 ms for opacity 0 and a side under 4 px, because a frame of another site cannot see its own frame element. A frame that was hidden when it got the focus and then shows, as a panel that animates open, keeps it. A frame nested in the focused frame is out of the top frame's reach.
- Hints reach into same-origin frames from the top page's own script, so those frames need no script of their own. A frame that already holds the focus when its script loads starts at once. `gF` runs `frame.exit` ("Focus top page"), which sends `focus_page` to frame 0 only, so the top page blurs its own iframe element whatever the frame's origin. It does nothing when the keys are already in the top frame.
- Open and copy of a frame use `contentDocument.URL` when readable and the `src` otherwise, and refuse with "This element has no web address" for `about:blank`, `srcdoc` and a frame with no `src`. Copying the text of a frame refuses. A frame inside a frame of another site gets no label from the top page: focus the outer frame, then press `;ff` again, or use `--all-frames`.
#### Hints across frames

- Hints across frames of other sites are opt-in: `hint --all-frames` (the `frames` param, `same_origin` by default), except for the one parked frame of a tab (see the frame mode bullets above). The frame that runs the command owns the keyboard and the typing rules. The background (`src/background/hint_frames.ts`) injects the hints bundle into every frame that takes scripts, waits up to 500 ms for each frame's count of candidates, and hands out one prefix-free label set, the top frame first. Each frame draws its own labels.
- A typed prefix and a pick go out through the background, and the owning frame runs the action. A frame that reports after 500 ms gets no labels and no later redraw. A frame outside the top viewport finds nothing visible and gets none. Escape, a hidden tab and a pick end hint mode in every frame. A same-origin or about:blank frame labels nothing itself, because its parent's walk already labels it, so each element gets one label. A focus pick or a field pick in another frame focuses that frame's window first.
- `inspect` keeps its frame refusal. `enter_media` keeps its frame refusal: no key test shows that the pin and the media keys follow focus into a frame of another site. For `caret` and `visual` the frame of the pick calls `window.focus()` and starts the mode itself, and the keys follow the focus into it (a key test shows this for a frame of another site).
- The keys typed before the labels showed go with the pick: the owner types them into the field it focuses and returns the rest, which the keyboard frame replays as normal keys. A mode that starts in the owner drops them, and one that fails to start leaves them to replay. After a hover in another frame, Escape in the keyboard frame releases the hover there, through a message to every frame of the tab. The message names the session of the pick that hovered, so a late release does not clear a newer hover.
- A copy or a `prompt` does not run in the frame of the pick: that frame answers with the text (the copy text, or the whole line for `prompt`, tracking parameters already stripped there), and the keyboard frame runs its usual copy or opens the line. So a rapid `copy` or `copy_text` keeps one list in the keyboard frame that joins the picks of every frame, the register applies, and the toast draws in the top frame.
- Text mode (`/`) ranks the hints of every frame: each frame sends the text of its candidates with its count, the background holds them in memory during the wait and returns them with the labels, and the typed relay carries the matching labels and the active one so the other frames hide the rest. With `--all-frames` the texts are a snapshot taken when the hints start, so a later page change does not show in text mode.
- A frame that ends the session before the start answer arrives is noticed by session id, so the run ends and does not enter hint mode. Known limits: keys typed during the round trip of a pick in another frame (a few milliseconds, and the same gap before a cross-frame `prompt` opens its line) run in the keyboard frame as normal keys. `copylinks` (`yL`) does not follow the flag.

### Background files for hints

Behavior of the `src/background` files for this area, moved here from `src/background/README.md`.

- `hint_frames.ts`: one label set across the frames of a tab, for `hint --all-frames`. The keyboard frame starts a session (`hint_frames_start`), the background injects the hints bundle into every frame that takes scripts, waits `HINT_FRAMES_WAIT_MS` (500 ms) for each frame's candidate count, and `assign_labels` hands out one prefix-free set, the top frame first. A frame that reports late gets no labels and no redraw. The keyboard frame sends its typed prefix and its pick here, and this relays them to the frames that own the labels. The session sits in `storage.session` (`HINT_FRAMES_STORAGE_PREFIX`), the wait only in memory, and nothing on the wait awaits a browser call, because a navigating frame can leave one unanswered. Browser calls come in through `HintFramesDeps`.
- `inspect_relay.ts`: hands a hint pick (`inspect_pick` from the `hints` bundle) to the devtools page of the picked tab. The ports sit in a map by tab id, rebuilt when the devtools pages reconnect. With no port the tab id and the pick time wait in `storage.session` (`INSPECT_PENDING_STORAGE_KEY`), and the answer is `{ ok: true, waiting: true }`. The hints bundle then shows the "press F12" notice and answers ok, so a key sequence goes on. The pick goes out when the page connects. It is dropped after 60 s, on navigation (`tabs.onUpdated` loading) and when the tab closes. Only a port named `devtools_inspect` from the extension's own `devtools.html` registers.
- `image_actions.ts`: answers `image_action` from the `hints` bundle. A copy fetches the address (cookies only for a default-container normal tab, 20 s timeout, 20 MB cap enforced while reading), sniffs the type from the first bytes and puts a PNG or JPEG on the clipboard, converting other types to PNG first. A download passes the address to `downloads.download` with the sender tab's `incognito` and `cookieStoreId`, buffering nothing. Every failure is an `Outcome` with a message, and the clipboard changes only in the last step. Browser calls come in through `ImageDeps` (wired in `browser_deps.ts`), so tests use fakes.

### Hints files for the hints bundle

Behavior of the `src/content/hints` files, moved here from `src/content/hints/README.md`.

- `main.ts`: registers the `hint` sink and the `hint.run` handler, and arms the jump list's leave watch (`src/content/lib/leave_watch.ts`), so a hint follow records the page it leaves. `hint.run` enters hint mode at once, finds the visible elements, draws labels and waits for one to be typed. Started in item mode, it asks the item bundle for the current item (`item.current`) and puts that item's targets first in the label order (`item_first`), so they get the shortest labels (`make_labels` hands those out first). The rest of the page follows in document order and every label keeps one color. Rapid rebuilds read the item again, and hints across frames stay unranked. Keys typed while it finds elements wait and replay. After an `enter_item` pick the keys typed behind it wait for the end of the leaf that started it (`leaf_end_` of the page host, read when the run starts), so a leaf that goes on with arrows after the pick, as Drive's does, finishes before the key moves on. Reads the `hint_letters` and `hint_key_line` settings from the stored config status. With `rapid`, a pick keeps hint mode and builds the hints again, so deleted or moved elements stay right, and Escape ends it. With `text`, only links whose text holds it (ignoring case) get labels. One match runs at once and ends hint mode, also with `rapid`. None shows "No link matches ...". A custom selector that does not parse shows a notice. Each run first asks the background for the frame's `hint_add` and `hint_remove` (`read_hint_selectors`) and holds the keys typed meanwhile, so they reach hint mode. A selector of those that does not parse is skipped with one notice.
- `prompt_line.ts`: the `prompt` action (`;:`). `prompt_pick` reads the address of the pick (`element_address`, a refusal when there is none) and asks the host to open the command line with `<command> <address>`, through `host.run_command_("cmdline.open", ...)`, so keys typed while cmdline.js loads stay held for the line. `quote_for_line` single-quotes an address the line would split or misread (whitespace, quotes, a backslash, a leading `-` or `@`). The pick's answer is the line's, so it stays pending until Enter or Escape. `rapid` is off for it.
- `collect_copy.ts`: rapid `copy` and `copy_text`. `collect_pick` adds the text to the session's list unless it is there, and returns the whole list (one entry per line) and the toast words. `main.ts` copies the whole list on every pick, because Escape gives no user activation to write the clipboard.
- `pick.ts`: the typing rules. Pure. The label generator is `src/shared/hints/labels.ts`. `pick.ts` has two modes. Label mode types a label: the typed letter if it continues a label, else the key's physical Latin letter (`physical` of `on_token_`, from `layout_fallback`). `/` enters text mode, where one-character keys and Space build a query from the typed text, Tab and Shift-Tab move the active hint, Enter picks it, one match picks at once, and Backspace on empty text returns to label mode. In label mode Tab and Shift-Tab make the picker answer `rotate` (forward and back), except that the first Tab widens a `drop` pass of a grab to every element (`widen_drop` in `main.ts`), and Space makes it answer `rapid`, which `main.ts` turns into a toggle of `Session.rapid` when `can_repeat` allows the action. `src/shared/hints/labels.ts` holds the pure part (`overlap_groups`, `rotate`, `rotate_back`). `main.ts` reads the hint texts (`text_of` in `candidates.ts`) on the first `/`, and every build starts in label mode. A pick that typed its last key waits 300 ms with hint mode open (`PICK_GRACE_MS` in `main.ts`) and drops the keys that arrive, so the rest of the word does not run as commands. Enter picks at once, and Escape in the grace cancels the pick. Tab, Shift-Tab, Enter and Space are bound in the hint keymap to `hint.key` (`src/commands/hint_text.ts`) only so the content script holds them during the bundle load. `/` has a row for its which-key label only, because every one-character key is held already.
- `rank.ts`: the text ranking. Pure. In text mode `rank.ts` orders the hints (`score_text`, `rank_items`: whole word over prefix over substring, first word over later words, shorter text over longer).
- `inspect.ts`: the `inspect` action (`;o`). It sets `window.wrappedJSObject.__desertfox_pick` to the element and sends `inspect_pick`. The devtools page selects it and deletes the property. The content script deletes it itself when the background gives no answer or the send fails, and after 60 s. A script in a frame refuses, because the devtools eval runs in the top window. The action skips the cover test, so an overlaid element is a target. A closed toolbox gives the "press F12" toast and the pick waits 60 s in the background.
- `view.ts`: labels in a closed shadow root. A label is filled with `--desertfox-primary`, with a 1px `--desertfox-primary` border so its size stays the same, and its text is `--desertfox-bg-core`. The letters already typed show at 60% opacity. In text mode the active hint swaps the label colors and a box shows the typed text. `add_key_line_` draws the key line at the bottom right (words built by `label_key_line` and fixed in `KEY_LINE_TEXT`, switched in `show_progress_`, and `set_rapid_` swaps the Space words), in its own node because `show_message_` wipes the container. `main.ts` adds it unless the `hint_key_line` setting is false. `rotate_overlaps_` (Tab, and Shift-Tab with `back`) reads every shown label box, groups the overlapping ones and moves the top label of each group under the others.
- `focus_fields.ts`: the pick of `page.focus_field` (`]i`, `[i`) and `page.focus_link` (`]l`, `[l`, the `LINKS` selector, same walk). The controls are the `FORM_CONTROLS` selector, found by `collect` and kept by `keep_present_found` (off-screen ones count, also inside a scrolling div, which does not clip them). The first control not above the view is judged against each scrolling box too, through `scrollport_top_of`. `place_of` finds the start (focused control, else `host.last_blurred_()`, which the content script answers when the bundle runs, else the first control not above the view) and `pick_field` moves by the count and clamps, or answers `end`, which `main.ts` turns into a notice. The control is focused with `preventScroll` and then centered in each window that holds it, when not fully in view. `gi` does not use this list.
- `click_first.ts`: the `page.click` handler. It clicks the first shown match of a selector with the hint click (`click_like_a_hint`), and answers a refusal for a bad selector or no shown match. Pure: the page, the visibility rule and the click are parameters.
- `yank_links.ts`: the list of `copy.links` (it drops tracking parameters before it merges equal addresses) (`yL`, `yl`, `:copylinks`). The page scope takes the `links` query through `collect` and `keep_present_found` (a link below the visible part of a scrolling div counts), the viewport scope takes `keep_visible_ones`. Only http, https, ftp and file addresses count, and a link to a fragment of the same page is dropped. The first link to an address wins, the list stops at 500, and the text falls back from the visible text to aria-label, title, image alt and the address. Formats are Markdown, Org and plain, one line per link. It formats the lines through `src/shared/copy/link_list.ts`.
- `insert_text.ts`: types the keys a pick queued into the field it focused, through the shared writer in `src/content/lib/field_writer.ts`. A pick that focuses a field, and `]i`/`[i`, also mark it as the entry of typed text (`src/content/lib/entry.ts`).
- Hints across frames (`--all-frames`, in `main.ts`): the frame that ran `hint` owns the keyboard and the picker. It sends its candidate count to the background (`hint_frames_start`) and draws its share of the label set that comes back. Every other frame runs the same bundle, reports its count, draws the labels it is handed, follows the typed prefix and runs the pick it owns. A frame outside the top viewport reports none. Every frame sends the text of its candidates with its count (`texts`), and the background returns all of them with the labels, so text mode in the keyboard frame ranks every frame's hints. These texts are a snapshot taken when the hints start, so a later page change does not show in text mode. The typed relay in text mode carries `matches` (labels) and `active`, and the other frames hide the labels outside them. The keys typed before the labels showed go with a pick in another frame (`keys` of `hint_frames_pick`): the owner frame types them into the field it focuses and answers `left`, which the keyboard frame replays. Keys typed during the round trip itself run in the keyboard frame as normal keys, a known limit. `caret` and `visual` start their mode in the owner frame after `window.focus()` and drop the keys typed ahead once the mode started (`enter_media` stays refused across frames). After a hover in another frame, `hint.unhover` (Escape) waits for each pending pick's answer, then sends `hint_frames_unhover` with that pick's session id, and only the frame that pick hovered releases it. A session id whose end arrived while the start answer was pending (`ended_ids`, cleared when no start waits) ends the run. A copy or a `prompt` picked in another frame does not run there: the owner frame answers the pick with the text (stripped of tracking parameters, or the whole line for `prompt`), and the keyboard frame copies it into its rapid list (`copy_of_pick`) or opens the line, so the list joins every frame and the toast draws in the keyboard frame. A pick the owner frame does not answer within 25 s (it navigated away mid-pick) ends as a gone frame, so the typed-ahead keys are released. A background that does not answer leaves the frame its own labels. See `src/background/hint_frames.ts`.
- `grab`, `grab_move` and `grab_swipe` actions (`;g` and `;G` modifiers, and `;s` with the `swipeable` filter: `is_swipeable` keeps what `is_draggable` keeps, the carousel container classes, any scroll-snap box, and a box that sets `touch-action` to one pan axis, `pan-x` or `pan-y` but not both, which is how Embla marks its container. `manipulation` and `pan-x pan-y` are left out, because resets set them on every element, and `html` and `body` stay excluded): `actions.ts` counts them with the caret actions as `starts_mode`, and `start_mode_` in `main.ts` hands the pick to the `grab` bundle (`src/content/grab/`) the way it hands a caret pick to `caret.js`. The target hint that a grab runs inside its first pick passes `nested_`, so a macro records one `hint.run` for the whole grab.

### Library files for hints (src/content/lib)

Behavior of the `src/content/lib` files that the `hints` bundle reads. `actions.ts` is also read by the `item_act`, `tree` and `next_page` bundles, and `candidates.ts` and `headings.ts` by `next_page`. `src/content/lib/README.md` lists every file in that folder.

- `candidates.ts`: one query per filter (`lists`, for `I`, labels the first shown item of each list the item bundle found, short lists and the `items` selector of a site row included (with `row_only` the row's list alone): `start_hints` asks its `item.lists` handler for the lists, and the `enter_item` pick hands the list back, with no click or focus, and starts item mode so the next step lands on it), (`buttons` takes `button`, `[role=button]` and the button-like `input` types, enabled only), a selector and an optional test for what a selector cannot say (`prose` keeps the elements with a non-blank text node of their own, so a wrapper of spans gets no hint; `every` keeps any box with a size, except a wrapper of one element child and no text of its own (a link, button or label is exempt), so `;yc` and `;yh` pick the inner element; `scrollable` keeps the boxes `is_scroll_box` accepts, see `src/content/scroll_box.ts`; `headings` keeps the elements `is_heading` accepts, the rule of `]h` (see `heading_match.ts`);  `draggable` keeps what `is_draggable` accepts: the explicit signs (`draggable="true"`, sliders, scrollbars, handles) or a grab, move or resize cursor where it starts, or `touch-action: none`; an element with no sign is reached with `every`; `media` takes `video, audio` and `main.ts` skips the cover test for it; `images` keeps an `img`, an image button or a box with a CSS background image, from 24 px on both sides (`is_image`), and skips the cover test too; `frames` keeps `iframe` and `frame` from 24 px on both sides, never the command line frame (`is_pickable_frame`), and keeps the cover test), plus "weak" candidates for `all` and `clickable`. `with_site_selectors` adds the `hint_add` matches for `all`, `clickable`, `every`, `draggable` and `drop` (marked `added`, so a weak wrapper gives way to one) and drops what sits in a `hint_remove` match for every filter but `custom`: a pointer cursor where it starts (or on any `<a>` without href), and a `tabindex=-1` item with a click-like role or inside a menu or a roving group (a tabindex 0 sibling). The walk (`collect` with `only_in_view`, set by `find_candidates`) reads each element's rect first and passes over a box wholly outside its own window and its frame (the frame clips its content), so the matches, the cursor test and the observer only see elements near the view, which keeps `f` fast on a page of tens of thousands of elements. Its shadow root and its children are still entered, so fixed or positioned content in view is found. `hint_add` matches take the same cut. When no candidate is in view but some exist, hint mode still opens and ends with the notice, as for an empty view. The viewport scope of `copy.links` calls `drop_off_screen` for the same cut. An empty box stays. A weak candidate gives way to a visible clickable element inside it or around it (checked after the visibility pass), so a page of pointer wrappers gets one hint per thing. The walk reaches open and closed shadow roots and same-origin frames. The walk stops at a frame of another site: that frame hints itself once the user focuses it and its own script starts. `name_candidates` in `candidates.ts` is the one fallback chain for an element's name (text, aria-label, title, picture alt, input value except a password).
- `visible.ts`: keeps what a person can click: inside every scrolling box, not hidden, and not under another element. Tries up to eight points per link (the middle of each line box, then the corners of the first), so a wrapped link or one part covered still counts. The boxes are clipped to the scrolling ancestors first (not body, html, or inline boxes, and each axis on its own), so a half scrolled item is probed on its shown half. A box with no area (also `display: contents`, which an IntersectionObserver ignores) falls back to its children's boxes and observes them. `anchor_box` gives the label the same fallback, and a link with no box gets a hidden label. Tested in each parent document for a framed element. Reads the page only through `PageProbe`, so tests use a fake page.
- `drop_targets.ts`: the `drop` filter of the grab target pass. `drop_targets_of(source)` returns the elements a drop can likely land on: the kin of the source (same tag, plus a shared class, `data-testid`, `role`, `aria-roledescription` or `draggable`) and their parents, the siblings of every ancestor of the source (empty columns), and the marked drop places. It returns undefined for a pointer widget or a source with no kin, and `query_for` then answers like `every`. `main.ts` also falls back to `every` when fewer than two targets show (`keeps_narrowing`, from `MIN_DROP_TARGETS` in `drop_targets.ts`), and `<Tab>` in label mode switches a `drop` session to `every` (`widen_drop`), with ` · Tab: every element` on the key line. The filter is not in the command's enum: only the grab bundle asks for it, with `drop_source_` in the args.
- `selector_of.ts`: the shortest unique CSS selector of an element for `copy_selector`. Pure: the caller passes a function that counts matches in the element's root. Skips ids and classes that look generated.
- `actions.ts`: what a picked element gets: a click, a focus, open in a place, copy the address (`copy`, the text for an element with no address, a refusal for a picture with none; `element_address` reads the element's own href, image or media source, never an ancestor's) the text (`copy_text`), the CSS selector (`copy_selector`, from `selector_of.ts`) or the outer HTML (`copy_html`), the picture (`copy_image`) or a saved file (`download`), both of which send the address to the background and never fetch it here (a missing answer from the background is a refusal), focus, delete, hover, and on media play or pause, mute and fullscreen (`player_box` in `src/content/player_box.ts` finds the element to show). A click is the whole mouse sequence (pointerover, pointerenter, mouseover, mouseenter, pointerdown, mousedown, focus, pointerup, mouseup, then `click()`), so dropdowns that open on mousedown open. A cancelled pointerdown skips the mousedown, mouseup and focus, and a cancelled mousedown skips the focus, as in a browser. A field only takes focus. `dispatch_mouse_event` (in `src/content/pointer_events.ts`, with `center_of` and the enter and leave path helpers that the item box hover shares) sends one event, with an optional click count `detail`, and is the piece the hover and double-click actions reuse. `double_click` (`;2`) sends the over and enter events, then two presses (the same press and release, `detail` 1 and 2) each followed by a dispatched `click`, then `dblclick`, and selects the word under the middle when that point is in a text node outside a field. `find_candidates` in `main.ts` drops links and their children, across shadow roots, for it. The word comes from `Intl.Segmenter` and is set as a range, so a point on a word start picks that word and a space picks nothing. `focus` gives an element with no `tabindex` attribute `tabindex=-1` first (a page's own value stays) and, for anything but a field, asks for the shared focus mark (`item.mark`) when the page's own focus style is invisible, so `;fs` shows which box a scroll key now moves. `]l`, `[l`, `]i` and `[i` ask the same way (`focus_and_mark`). `hover` (`hover.ts`) moves a pointer like a real one: pointerout and mouseout on the old element (with `relatedTarget`), leave only on the old element and ancestors that do not contain the new one, then over, enter (only on ancestors the pointer was not in), pointermove and mousemove from the middle of the new one. So hovering an item inside a hovered menu keeps the menu entered. Ancestors include the shadow host above a shadow root, and one point (the new element's middle, or where the old one was entered) serves the whole move. A click or double-click pick enters its target the same way, from the element the pointer was on, so the shadow host and menu above it get their enter events (without the move events), and the target becomes the hovered element, so the next pick or Escape leaves it and a second pick inside one menu enters the menu only once. A pick inside the hovered element makes the picked element the hovered one, so Escape still closes the menu. A pick that sends no entry (copy, delete) leaves it unentered, and a later hover of it sends the entry. A new hover, Escape (the `hint.unhover` handler, called from `mode.escape`), a hidden tab or another pick (toward its target) ends the hover. A removed element gets no events. Synthetic events do not set CSS `:hover`. `caret` and `visual` hand the element to the caret bundle (see `src/content/caret/main.ts`, `start_session`) and ignore `rapid`.
- `heading_match.ts`: which elements count as headings (`HEADINGS`, `is_heading`, `rendered_text`). A leaf with no imports from `src/content/lib`, so `candidates.ts` and `headings.ts` can both use it without an import cycle.
- `headings.ts`: the headings of the page for the `heading` command and for `page.heading` (`]h`, `[h`, and `]H`, `[H` for the last and first heading, which ignore a count and give the notice "No headings" on a page with none, and `}`, `{` for the next and previous section, see below). `step_heading` finds the headings with the same rules, `pick_heading_step` picks from the last jumped heading while it is on screen (one weak reference), else by the top of each heading from the view top (next is the first below it, previous the last above it). A count clamps and none is a notice and `scroll_to_top` moves. `scroll_to_top` takes the `top_inset` (the bottom edge of the fixed or sticky element `covering_inset` finds at the top edge of the view, 0 when it is over a third of the view) and sets it as the target scroll margin for the jump (less the scroller scroll padding, and never below the page own margin), which works in a scrolling div too. It reads the inset again after the jump and jumps once more for a taller bar, and `step_heading` counts tops from the same line. `}` and `{` (`next_block` and `prev_block`) run the same step over `is_block` instead: headings plus `p`, `pre` and `blockquote`, where a text block needs 40 characters of rendered text, a `p` inside a `blockquote` is dropped so the blockquote counts once, and anything inside navigation, footer, aside, form, dialog, a `header` that no article, aside, main, nav or section holds (the implicit banner), or the matching roles is skipped. The notices are "No next section", "No previous section" and "No sections" on a page with none. `step_heading` and `heading.go` also leave the heading and its frames in a window slot (`desertfox_heading_jump`, weak references) for `scroll.align` in the page bundle, and a `focusin` or `selectionchange` after the jump empties the slot. The `heading` command (`src/commands/heading.ts`) is the one the command line lists. `heading.list` reads the page and keeps a snapshot of the headings and their frames, `heading.go` jumps to one by its number or its text, and `heading.clear` drops the snapshot. The command line host calls the three (`src/cmdline/host.ts`). Headings are checked with `keep_present_` and not `keep_visible`: a box of real size that no overflow-hidden box clips (a scrolling div does not count, the jump scrolls it) and that `checkVisibility` (visibility and opacity) accepts (Firefox gives the content of a closed `<details>` a box, so a box test alone keeps it), wherever it sits on the page. A heading in a frame passes only when its frames pass the same rules. `heading.go` refuses with "That heading is gone" when the element left the page, and scrolls the heading and then each frame that holds it to the top, innermost first, touching nothing else.

### Grab files for keyboard drag

Behavior of the `src/content/grab` files, moved here from `src/content/grab/README.md`.

The `grab` bundle (`grab.js`): keyboard drag. `hint --grab` (`;gg`) picks an element, then a target, and drives a drag between them. `hint --grab_swipe` (`;s`) picks a swipeable element and enters grab mode as a swipe: `h j k l` fling it (`l` shows the next slide), Escape ends it. `hint --grab_move` (`;Gg`) picks an element and enters grab mode, where `h j k l` move it, `[` and `]` halve and double the step (it starts at the `grab_step_px` setting, 3 px by default, which `host.grab_step_px_()` reads from the compiled keymap), Enter drops it and Escape ends it (a range input and a draggable element go back first, a pointer drag releases where it is).

- `main.ts`: the `grab.mode` handler that takes a hint pick (the hints bundle leaves the element in `desertfox_pick_target`, as for the caret), the `grab.move`, `grab.step`, `grab.drop` and `grab.cancel` handlers, and the grab mode sink. The sink passes every key to the keymap and exists for `exit`, which every way out of the mode reaches, so a held drag always ends. `;gg` and `;Gg` pick from the draggable group (`hint --grab --draggable`); a source with no drag sign (a div thumb with the default cursor) is picked with `;ga`. The target hint of a grab is run again through `hint.run` with the internal `drop` filter and the source in `drop_source_`: it labels where the source can likely go and falls back to every element, and Tab widens it to every element (see `src/content/lib/drop_targets.ts`).
- `drag.ts`: the synthetic input, in three routes chosen by the source. A draggable element (or one inside it) gets DragEvents with a new `DataTransfer`, because mouse events never start a native drag. A range input gets a value plus `input` and `change`. Any other element gets pointer and mouse events. `release` and `abort` send the closing events (`pointerup` and `mouseup`, or `drop` and `dragend`, or `change`). A range input gets `change` only when its value differs from the start, so an abort, which first restores the start value, sends none. A pointer drag sends no mouse events at all when the page cancels `pointerdown`. An HTML5 abort sends `dragend` but no `drop`, and `dragleave` only when a drop target is under the drag. `press` lands on the slider's thumb (`press_point`), so no slider jumps on grab. `abort` puts a range value back and ends an html5 drag with no drop, and releases a pointer drag where it is. `scale_step` sets the per-drag step of `[` and `]`.

- Swipe: `snap_scroll` scrolls a scroll-snap box by one view. Any other target gets `start_fling`, a forced pointer-route drag of 60% of the box in 6 steps. The pause is at least 30 ms and grows with the box, so the speed stays about 2 px per ms, which Splide reads as one slide. The keys queue in `main.ts` (up to two waiting), each fling finishes and settles for 350 ms (`FLING_SETTLE_MS`, which fits default library speeds, so a slower transition can drop a fast second press) before the next, and the exit swaps in a new queue, so a waiting fling never starts after Escape. The `swiping` element in `main.ts` makes `grab.move` fling instead of nudge, and `grab.drop` leave the mode.

Limits: the events are not trusted, so a page that checks `isTrusted` ignores the drag. A drag stays inside one frame. A drag to another tab or app needs real input through the host and is not built. A page that calls `setPointerCapture` with the synthetic pointer fails in its own code, and the drag goes on.

### Site action files for the site_actions bundle

Behavior of the `src/content/site_actions` files, moved here from `src/content/site_actions/README.md`.

The `site_actions` bundle (`site_actions.js`, its limit is in `MAX_BYTES` in `tools/build.mjs`). The content script loads it on the first press of a command that site rows bind to keys, so these handlers stay out of `content.js`.

- `arrow.ts`: the `page.arrow` handler, bound by the shipped `arrow` site mode. Firefox ignores a script's arrow keys on its own controls, so it works on the focused element by kind: a select steps over disabled options, a range steps up or down, a radio gets a click on the next radio of its group (the browser checks it and fires `click`, `input` and `change`, which a script framework reads), and a select or range fires `input` and `change` itself. The body or no focus scrolls 50 px through the host. Any other element gets `send_key` arrows, which only page scripts read, and the page scrolls when it did not cancel the keydown. A count repeats the step inside one queue entry, one `KEY_PAIR_GAP_MS` apart. The focus lookup (deepest element through shadow roots), the scroll function and the event maker are parameters, so a test passes fakes.
- `main.ts`: registers the three handlers (`page.send_key`, `page.arrow` and `page.clipboard`) with the host. Not unit tested, it needs a DOM.

The `page.item` handler is not here: it lives in the `item` bundle (`src/content/item/`), because the move and its box do not fit this bundle's size limit.

### Library files for site actions (src/content/lib)

Behavior of the `src/content/lib` files that the `site_actions` bundle registers handlers from. The `editor` bundle also reads both.

- `send_key.ts`: the `page.send_key` handler. It sends a `keydown` and a `keyup` with a key name, a legacy key code and the modifier flags that are on (`ctrl`, `shift`, `alt`, `meta`) to the element the selector finds, or to the focused element. With `keypress` on it adds a `keypress` between them. It refuses when the selector matches nothing or does not parse. `send_key_queued` sends through one queue per page that keeps at least `KEY_PAIR_GAP_MS` (10 ms) between pairs, because Sheets applies only the first of several pairs that arrive in the same millisecond. The count arrives as the `times` param, and a call is one queue entry, so its steps all go out before the next call starts. The events are untrusted, so the content script ignores them and the key does not loop. The document and the event maker are parameters, so a test passes fakes. It holds the queue state of the page (the queue tail and the time of the last send) and is otherwise pure.
- `clipboard.ts`: the `page.clipboard` handler. It focuses the target, runs `document.execCommand` for the action and counts the action as taken when the matching event fired (a capture listener on the document, and the return value is ignored), and refuses a target that did not take focus. A paste that fired no event falls back to `paste_through_clipboard_api`, which reads `navigator.clipboard` (rich data with `read`, else `readText`) and dispatches an untrusted `paste` event carrying it, and refuses when the page did not cancel that event. A cut or copy that fired nothing refuses. It is otherwise pure: the document and the fallback are parameters.

### Devtools files for hints

Behavior of the `src/devtools` files, moved here from `src/devtools/README.md`.

The page that Firefox loads in each toolbox (`devtools_page` in the manifest). It builds as `devtools.js`, with its own size limit in `MAX_BYTES` in `tools/build.mjs`.

- `main.ts`: wires `run_page` to `browser.devtools.inspectedWindow` and `browser.runtime.connect`.
- `hand_off.ts`: `run_page` connects to the background with the name `devtools_inspect`, says which tab it inspects (`devtools_hello`) and, on each `devtools_pick`, evals one constant string that deletes `window.__desertfox_pick` and passes the node to `inspect()`. The string carries no page data. One eval reads and deletes together, so a second pick that lands in rapid mode is never deleted before its own message arrives, and a failed select leaves nothing on the page. Picks run one after another. A closed port is reopened after a second, which also covers a restarted background: its relay then sends the pick that waited.
- `devtools.html`: the page the manifest points `devtools_page` at. It only loads `devtools.js`.

The relay is `src/background/inspect_relay.ts`. The hints bundle sets the property (`src/content/hints/inspect.ts`).
