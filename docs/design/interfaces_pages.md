### Which-key

Which-key is a first-class surface. After a prefix key, it lists each possible next key with the label of its command. Hovering a row shows the command's intent, or the `intent` of the binding when it has one. It reads both from the registry, so a new command appears without extra work.

The label of a key comes from one rule, applied to the args the binding sets (never the defaults the validator fills in):

- A binding `label` wins. It exists in the TOML table form and on the bindings of the default keymap. On a key that runs several commands, the label sits on the first command. The binding `intent` works the same way for the hover text, and modifier variants do not inherit it.
- A key that sets a container reads as the container name, and the container named `default` reads "Default container".
- Otherwise the label is the command label. A search engine with a label in `search_engines.toml` replaces it (a child engine's label is the chain of labels on its path), and a binding with no engine uses the default engine. Then each `enum` arg the binding sets to a non-default value adds its `value_labels` phrase, in param order ("Open URL in new tab"). A `bool` set to true adds the param name ("Reload hard"). Numbers, free strings and prompted params add nothing, so the keys that set them carry a hand `label` ("Scroll left", "Zoom in a lot"). A phrase that the name of any group above the key already says, as whole words and in any case, is left out: under a group named "Search in new tab", the key reads "Google", not "Google in new tab".
- A snippet key shows the `// label:` header of its snippet.

Two keys in one group may share a label only when they run the same binding (`zi` and `z+`). The unit tests check this for every group of the default keymap and of a copy of the user config, and print each group's labels.

- In the browser it draws in a closed shadow root, styled through the CSS variables in [Styles](config.md#styles). It appears after a delay that is a setting.

### Help and palette

The help page is generated from `commands.json` and the live keymap: every command, its params, its keys and the keymap warnings. The palette is the command line with an empty prompt.

`:issue` (`help.issue`, no default key) opens the GitHub new-issue form prefilled with the extension and Firefox versions, the OS and the number of config warnings (`src/background/issue_report.ts`). The warning text stays out of the address, because a query string reaches GitHub when the form loads, before anyone reviews it. `--copy` puts the full report on the clipboard and opens the blank form. It holds the warnings word for word, at most 10 and 2 KB, with a count of the cut ones, and the user reads it before pasting. In every warning the config folder path becomes `<config dir>`, because the host reports it as an absolute path. A label that is no absolute path, such as `import`, is left alone. The command sends nothing itself.

The Site Rules page (`:help site_rules`, hash `#/site-rules?address=<address>`) lists the site rows that fit the invoking tab's address, from the stored keymap through `site_rules_view`. Each row shows its origin (yours or a shipped row's name), its pattern, the columns it sets as name and value pairs and the keys it changes with what each does instead. A column an earlier row already decides, or a key the page does not run (off, freed by pass, dropped by only, hidden by a shorter bind), is greyed with the reason; key changes are judged against the page tree from `normal_tree_for`. The list is for the tab's own address, and frames of other sites resolve against their own. Asked from the help page itself, or from the sidebar link, the page says where to run it.

The help page has a sidebar of page links on the left. In a window 40rem wide or less, the sidebar is a drawer and never a bar across the page. A bar that stays on top holds a menu button, which opens the drawer over the page. Escape, a picked link, a click outside the drawer or focus leaving it closes the drawer. Opening it focuses the current page's link, and Escape or a click outside returns focus to the menu button. The drawer starts closed on each render and is not stored.

### New tab page

- Answered: DesertFox owns the new tab page through `chrome_url_overrides`. `new_tab_page` is a web URL, which the page redirects to, or `desertfox` for the built-in page, and unset means the built-in page. `home_page = "desertfox"` opens the built-in page, even when `new_tab_page` redirects. After Firefox's one-time "Your new tab has changed" notice, its hidden Keep Changes button keeps access key K for that browser session, so Alt+K (previous tab) does nothing on about: pages until a restart. Accepting the notice once avoids it. Firefox still gives the address bar focus on Ctrl+T, so the user presses Esc or clicks the page before keys work. The page loads `content.js` by script tag and every other bundle on first use, as a website does: `executeScript` cannot reach extension pages, so the background asks the page to add the tag (`src/shared/page_bundle_tag.ts`). See [`src/newtab/README.md`](../../src/newtab/README.md).

- Answered: the built-in new tab page shows a clock and the date. `newtab_clock` is `false` (off), `true` or `"analog"` (a 12 hour analog face with no tick marks, the default) or `"digital"` (seven-segment `HH:mm` in the DSEG7 Classic font, shipped with its OFL text and declared only on this page). `newtab_clock_format` is 12 (default, with an AM or PM suffix) or 24 and applies to the digital clock only. `newtab_date` switches the date off. The page makes no network request unless the owner turns on the weather card or the IP info line (see the next answer). The page colors are var() fallbacks over the theme roles (`bg_core`, `fg_core`, `primary`, `accent`, `bg_mantle`, `border`), so a bare install shows a dark blue page and a theme restyles it once the role variables reach the page.

- Answered: the built-in new tab page can list links, recent tabs and bookmarks. `[[newtab_links]]` in `settings.toml` takes tables of `label`, `url` (http or https only) and an optional `group`, and links with the same group share a list. The settings page writes the list into `settings.toml` through a row control in the New tab group (see Settings in the file), and Reset removes every link row there; a typed `:set` refuses it, as for `site_rules`. `newtab_recent_tabs` (open tabs, last used first) and `newtab_bookmarks` (newest added first) are off by default, with `newtab_recent_tabs_max` and `newtab_bookmarks_max` rows, 8 each. The page calls the tab and bookmark APIs itself and reuses the completion's pure readers by import, so it adds no background message. It skips private tabs and lists no tabs on a private page. Every row is a card that is one anchor (icon, title and site), so hints reach it once. Card icons come from the favicon cache only, then a letter tile: the page never loads a remote icon, and it ignores a tab's own `favIconUrl`. The cache is `favicon_cache` in `storage.local` (host to a 32x32 PNG data: URL, at most 200 hosts and 6144 characters each, about 1.3 MB at most). Firefox hands the background every tab icon as a data: image in any size or format. When a load completes or the icon changes, the background redraws it through a canvas to 32x32 (`background/favicon_saver.ts`). It makes no request, saves nothing for a private tab, and stores nothing when `favIconUrl` is not a data: image. An icon that did not change is not redrawn: the saver keeps a short key of each source icon in memory (loaded once from the stored entries) and in the entry. A host is saved at most once every 3 minutes, so a page that changes its icon all the time (an unread count) costs little. A redraw that fails is not tried again until the icon changes. "Clear all history" clears the cache and the memory, including a redraw that finishes after it. There is no icon service and no layout setting. Two more lists are off by default and make no request: `newtab_closed_tabs` (`sessions.getRecentlyClosed`, newest first, a click calls `sessions.restore`) and `newtab_top_sites` (`history.search` over pages visited in the last 90 days, the lifetime visit counts of those pages added per host, the most visited page of the host stands for it), with `newtab_closed_tabs_max` and `newtab_top_sites_max` rows, 8 each. There is no `topSites` permission. A private page lists neither. `newtab_command_hint` (on) shows a button, "press <key> for the command line", that sends the same `cmdline.open` run as the key. The page draws it at once with the default key `:`, then reads the stored keymap and shows the bound key, or the plain words "open the command line" when no key is bound. The first paint never waits for the keymap, and an open new tab keeps its hint when a key changes: the next new tab shows the new key. It is not an input, so the address bar keeps the focus on Ctrl+T. Widgets that frame a user-hosted page are rejected, because `file://` cannot be framed and keys and hints do not reach inside frames.
- Answered: the Settings text link of the new tab page is now a gear icon in the top-left corner. It is one plain anchor with an accessible label, so `f` hints reach it, and it opens the Settings page of the Home document (`home.html#/settings`), the target the text link had.
- Answered: the weather card and the IP info line are the only network exceptions to "the new tab page makes no network request". Each sends nothing on a private page. The IP info line is off by default. `newtab_weather` is on by default, but the card sends nothing and reads no location until the owner accepts its "Show the weather here" button, which asks for the optional `locationInfo` data collection permission, and for the optional `geolocation` permission too when no city is set, in one prompt, and while the setting is off the page makes no request. Without the `locationInfo` consent the card is only that button, whatever city is set or stored. With it, the card needs `newtab_weather_city` or a granted position, and the page asks Open-Meteo (`api.open-meteo.com`, `geocoding-api.open-meteo.com` for a city, and `air-quality-api.open-meteo.com` once the panel opens) for the current temperature, feels-like temperature, humidity, weather code, wind speed and direction, today's high and low, UV index (today's maximum), sunrise and sunset, and the temperature, weather code and rain chance of the next 12 hours, in one request (`timezone=auto` makes the server read the time zone from the coordinates, so nothing more leaves the page). The card sits in the top-right corner of the page and shows the high and low and the wind (km/h for metric, mph for imperial). Its More button opens the rest in place under the card, and Less closes it. The panel reads top to bottom: the hours from the current one (the first column is Now), a hairline divider, UV index, sunrise and sunset in one row with small icons, a divider, and the air quality row. The panel uses only theme colors, and the air quality dot runs from the ok color through warn to error by band. The hours are one row that neither wraps nor scrolls, each a column of time, condition icon, temperature and rain chance, and as many show as the panel's width fits, never fewer than 6 (`hours_that_fit`). Opening sends only the air quality request below, and the open state is not stored. The sun times and hours follow `newtab_clock_format`, and the hours that have passed since the stored answer was made are dropped. The weather icon has an `aria-label` with the condition. On a window narrower than 32rem the card takes its own row above the clock, and up to 61rem it does so while the detail is open, because the open panel would otherwise reach the centered clock. Air quality is the one second request, to a third host: Open-Meteo's air quality API (`air-quality-api.open-meteo.com`). It starts only when the reader opens More, so a reader who never opens the panel sends nothing to it. It receives the same rounded coordinates the forecast sent, and no cookies, referrer or city text. The page asks for the US AQI when `newtab_weather_units` is imperial and the European AQI when it is metric, plus PM2.5, PM10 and ozone, and shows the index with a short band label and the pollutants as one row in the panel. It uses the same fetch and cache helper, under its own storage key (`newtab_net_cache_air`), with the same 30 minute TTL and 6 hour limit. Two opens while the request is out share one request. Closing the panel, a redraw or a stopped run while it is out leaves no late draw. A failed request draws no row and leaves the rest of the panel alone, and the next open tries again. While `newtab_weather` is off each draw deletes this key together with the forecast's, and a private page sends nothing. A request carries no cookies and no referrer (Firefox can still add an `Origin` header with the install's `moz-extension://` address, a random id that stays the same for the install, so both providers can tell requests from one install apart), waits at most 5 seconds and keeps its answer in `storage.local` for 30 minutes, one storage key per card (`src/newtab/net_widget.ts`, shared with the IP info line). A stored answer of the same kind and units shows at once, before the position read finishes, and one older than 6 hours never shows. With a position the stored answer is keyed by the rounded coordinates, so after travel the old place is replaced by a new request. A failed or slow request draws nothing, so the page never waits on it. The place comes from browser geolocation when the optional `geolocation` permission is already granted. The card asks for it only from a click on its "Show the weather here" button, never at load, and shows that button until the consent (and, with no city, the permission) is granted. A city is the place the user chose: with one set the card never reads or asks for the position, and the click asks for the consent only. A denied prompt leaves the button. Each Open-Meteo request, the air quality one included, first checks that the consent is still there, so a withdrawal while the page is open stops the later requests. Once the permission is granted the position is used when no city is set. With a city, it is geocoded and the position is not read. Coordinates are rounded to 2 decimals (about 1 km) before they leave the page, and the city text goes only to the geocoder. A private page and a page without the permission and without a city send nothing. `newtab_weather_units` is `auto` (the default), `metric` or `imperial`. Auto picks imperial (Fahrenheit, mph, US AQI) for the United States, Liberia and Myanmar and metric otherwise. For a city the country is the geocoder's `country_code`, so the request is made in that unit. For a position the request is metric, because the forecast names the time zone only in its answer, and Open-Meteo has no reverse geocoding: a time zone of one of those countries converts the answer on the page and picks the imperial air quality scale, still in one request. A fixed choice wins over both. While `newtab_weather` is off, each draw of the page deletes the stored answer, as for the IP info line. A stored answer from an older build lacks the newer fields and is fetched again once. The answer keeps the forecast's local date and offset, and a stored answer is fetched again, not shown, once the place's date has moved on, so no one sees yesterday's high and sun times after midnight. Opening More draws the hour strip again, so hours that passed while it was closed drop out. That part sends nothing.
- Answered: the IP info line (`src/newtab/ip_info.ts`) asks Cloudflare (`https://1.1.1.1/cdn-cgi/trace`) for the public IP address and the country code, and draws only those two fields as one muted line under the date, such as `203.0.113.7, Norway`. `newtab_ip_info` is off by default, and while it is off or the page is private the page sends nothing. The request goes through the same helper as the weather card: no cookies, no referrer, no redirect, 5 seconds at most, and its own storage key (`newtab_net_cache_ip`). Firefox can add the same `Origin` header as for the weather card. The stored answer draws first, each new tab then refreshes it once it is a minute old, and one older than 1 hour never shows. A stale address would defeat the line's use, checking a VPN or a network change. While `newtab_ip_info` is off, each draw of the page deletes the stored answer. "Clear all history" does not clear it yet, because the history clear hook (`src/background/history_clear.ts`) names its stores one by one and the line has no background owner. A failed request, or an answer that does not look like an address and a country code, draws nothing, and the page never waits on it. A redraw of the page stops the line's run, so a late answer neither draws nor writes the cache. The request itself discloses the address to Cloudflare, as any request does, so the setting text names the provider. There is no provider setting.
- Answered: the manifest keeps `data_collection_permissions` `required: ["none"]`, because DesertFox itself collects and sends nothing by default, and declares `optional: ["locationInfo"]` for the weather card. The card requests it with `permissions.request` from its button (with `geolocation` too when no city is set) and sends nothing without it. The page contacts Open-Meteo (including its air quality host, and that only once the panel opens) only after that consent, and Cloudflare only after the owner turns the IP info line on. The IP info line declares no category: it sends no data of its own, only the request that any fetch makes, and the privacy policy names it. The settings text names the provider and what is sent. `docs/privacy.md` is the privacy policy and the text of the addons.mozilla.org privacy field.

### Toolbar popup

The toolbar button opens a popup (`src/popup/`). Top to bottom it has a header (the icon, the DesertFox wordmark, a native host status dot and the version), a two-segment On/Off control, a site card, a Warnings (N) row with a chevron that shows only while there are warnings, a theme dropdown, a notice line, then one section with a Reload config button with an inline icon (an action, so no chevron) and one row split in three for Settings, Help and Keys (each with an inline icon), and last a Support DesertFox row with a heart icon as the footer. The host dot is filled while the bridge host is connected and hollow otherwise, and its label says no permission, connected or not connected. While the popup is open it follows `desertfox_host_connected` in `storage.session` live, and a change during a draw is kept. The bridge sets that flag when the host's ready message arrives and clears when the port drops, when the bridge turns off or reconnects, and at every background start, so a crashed host or a restarted extension never leaves it set. It is only ever set while the `bridge` setting is on, because the config host keeps no standing connection. The version is a link that opens its GitHub release page (`releases/tag/v<version>`) in a new tab beside the active one for a release version, and the releases list for a beta (four parts), whose release body is one standard line. Keys opens the Commands page of the help page. The theme dropdown lists `desktop` and the built-in and local themes. A pick sends the settings page's `change_setting` request with layer `file`, so the one validator checks the name and the pick goes into `settings.toml` and lasts (see Settings in the file). The notice says whether the file was written or updates when the native host connects. A redraw gives focus back to the control that had it, and the notice expiry changes only the notice line. A success notice clears after 4 seconds, and an error notice stays until the next action. All state lines and details start with a capital letter. Support DesertFox opens the GitHub Sponsors page (`https://github.com/sponsors/uhs-robert`) in a new tab. It is a plain link with no tracking, prompt or reminder. The site card shows the host and a state line (enabled, disabled, a rule covers it, no site on this page, or DesertFox is off), the Disable or Enable on this site button, and, only while a rule matches, a line with that rule and a link that opens Settings at `#section=settings/site-rules`, the id of the heading of the Your site rules section, which the page renders at once. The popup uses the theme's primary color as its one accent, with a hex fallback on every color, so it follows a theme change in dark and light. Off is one global switch kept in `storage.local` (`desertfox_disabled`, absent means on). While off, the background stores an empty keymap, so the content script matches no key and hides its badge, and sends every open tab to normal mode, which ends hints, the command line and insert mode. The router and the Firefox shortcut slots refuse every command. The manifest shortcut `toggle_enabled` (default `Ctrl+Alt+D`, rebindable in `about:addons`) and the popup stay live while off. The icon turns grey and the title reads "DesertFox (off)". Off differs from an all-off site rule: that rule is a start mode per matching page that a binding can leave, while off stops every key and command on every site until it is turned on. Off wins over a disabled site. "Disable on this site" appends the row `{ site = "*://*.host/*", off = true }` (host without `www.`) after the last `[[site_rules]]` row of `settings.toml` (see Settings in the file), and open tabs follow at once. It is live while no matching row sets the off column, so a page under a key rule can still be turned off, because the appended row then decides the column. "Enable on this site" removes every row for the pattern that sets nothing but `site` and `off` (an older bare row and a hand-written one too) and is live only while such a row decides the column and no other row decides it the same way. A row for the same pattern with any other column, and a row for another pattern that covers the site, stay. A `settings.d` file that sets `site_rules` does not block the clicks: the rows of the files add up, and a click writes only `settings.toml`. The click checks its page against the combined list as it would be after the write (settings.toml's rows, then each `settings.d` file's in name order), and when another rule still decides the site the other way it is refused and names the file of that rule. A popup row sits at the end of `settings.toml`, ahead of every `settings.d` row, so a `settings.d` row can refuse only an Enable. The notice says whether the file was written. The rule line shows what the matching rows set ("Pass 3 keys", "Only 2 keys", "All off", or "On, pass 1 key" under `off = false`) with that link. The card also holds "Let this site keep some keys...", which opens Settings at `#section=settings/site-rules?site=<pattern>` (the pattern the Disable button writes, encoded as one value). The Your site rules section holds a form with the site filled in, where the user presses the keys the site keeps or ticks them from the bound normal-mode keys, as removable chips with an "Edit as text" fold. Save writes one `{ site, pass }` row (`site_keys` message, `change_site_keys_in_file`): a new row goes after the last one, and the row of that exact pattern is replaced in place. Remove deletes every `{ site, pass }` row for the pattern. A row saved in the browser before the file held it goes out with it. The form never writes `only`. A row for the pattern with any other field, or an earlier row that already sets the key column for the site, refuses the Save and names that row. The row is grey while DesertFox is off, on a page with no site and while the site is disabled. Before the popup wrote the file, it saved a whole `site_rules` list in the browser that hid the file's list. The next click drops that list, even when it changes no row, and adds its popup rows that the file lacks to `settings.toml`. Its other rows were copies of the file's rows, so the file's own rows stand for them. The grey icon is a generated copy of the placeholder logo. A final logo with an off state is not yet built.

### External editor

`text.edit_external` (insert mode `<C-o>`, content command, `bridge: false`) opens the focused field's text in the editor that the native host's own config names. The extension sends only text, an extension for the scratch file, an insert flag and, from a private window, a private flag, so nothing executable crosses from the page or the extension. The `editor` bundle refuses a non-editable focus, a password field (`is_secret_field`) and text over 128 KiB (the host's cap), reads the field and asks the background. The background (`external_editor.ts`) calls `editor_start`, keeps `{ job, tab_id, token, frame_id, is_private, orphaned? }` per host job id in `storage.session`, and loops `editor_collect` (the host long-polls about 20 s and answers pending). The code is ready for a Manifest V3 event page, which restarts the background: a restart resumes every loop from storage. Under the persistent MV2 page only an add-on reload or update restarts it, and Firefox clears `storage.session` then, so a job does not survive one.

- One job per tab. A second press refuses with a toast, because closing a running editor needs a terminal-specific window class.
- A tab that closes or starts loading orphans its job. The editor stays open for the user and the loop keeps collecting, but the result goes to the unnamed register (with a toast when the tab still exists), because the page is gone. The same holds when the frame no longer takes the result: the page answers `true` only for the `token` it made, so a new page in the frame never takes a late result.
- Editors that show only part of their text (CodeMirror, Ace and Monaco, and the hidden textarea of CodeMirror 5, found by their container class) go through the clipboard. The page saves the clipboard text, sends the editor its own Ctrl+A and runs `execCommand("copy")`, and puts the saved text back before the editor opens. A marker left on the clipboard, or a copy that misses a drawn line, means the copy failed, and the page refuses as before. On return it copies again, and pastes the result only while the editor still holds the opened text. A read-back after the paste confirms the editor took it. Otherwise the result goes to the unnamed register. Only text is restored, and a toast says the clipboard was used.
- The result overwrites the field only while the field still holds the text it had at the press, checked again after the focus call. A plain input or textarea takes the value through the native setter and `input` and `change` events, and counts as refused when the field holds something else afterwards (it sanitized the text). A contenteditable takes one `insertText` over its whole content, so undo works. Otherwise the result goes to the unnamed register, and a toast says whether the field changed or refused the write, and says so only when the register took the text.
- A private tab's text goes to the private register, and is dropped with a toast when no private window is open any more, so private text never outlives its session. The host keeps the scratch file in `$XDG_RUNTIME_DIR/desertfox/editor` (memory-backed when it is tmpfs or ramfs) and sweeps files older than a day. With no usable runtime folder it falls back to `~/.cache/desertfox/editor`. It refuses a private edit there, and also when the runtime folder is not on tmpfs or ramfs, which the extension marks with `private: true`. A host that predates the field refuses too, and the toast tells the user to run `:native.update`. Private text then stays in memory but, like Firefox's own private-window memory, can reach swap. See `host/README.md`.
- A failed collect is tried again, up to three in a row with a pause. After that, or on the host's unknown-job refusal, the job is dropped and the toast shows the error. After the retries the toast also names the host's editor folder, `$XDG_RUNTIME_DIR/desertfox/editor` or `~/.cache/desertfox/editor` without that variable.
- `<C-o>` in insert mode takes Firefox's Open File shortcut (Ctrl+O) in a field, as normal-mode `<C-o>` does outside one, on every site, whether or not a host is installed. Without the host or its editor config the key shows the host's refusal as a toast and does nothing else. A user who wants Open File back in a field unbinds the key or binds another one.
- The extension of the scratch file comes from the `ext` param, else the per-site `editor_ext` setting (up to 10 letters or digits, empty for none). A failure of the host (an old host, no editor config) shows its error as a toast. There is no enable setting. The command line cannot start an edit: it takes the focus off the field.

### Background files for pages

Behavior of the `src/background` files for this area, moved here from `src/background/README.md`.

- `list_keys.ts`: answers which-key. Given a mode and a typed prefix, it walks the compiled keymap in `storage.local` and returns a title (the chain of group names, `["+Go", "+Close tabs"]`) and a row per next key: the command label and intent, or `+Name` for a longer sequence. A capture leaf shows as a `<key>` row, except under `mark.add` and `mark.jump`, where a page with marks lists them with their offsets (the caller passes them). The prefix `"` is no key of the tree, so it lists the stored registers instead (the caller passes their rows). Rows run letters, other plain keys, modifier keys, groups by name, then Escape. Given the active page, it first applies the page's `site_rules` key rule to the normal tree, then drops the keys the page cannot run, including a `site_keys` key with no engine for the page (see `availability.ts`) and the groups left empty.
- `open_help.ts`: `open_help` opens the help page at a command card in a foreground tab beside the asking tab, only for the frame whose line redeemed a ticket. An id without a card (a snippet or unknown id) opens the Commands page at its top.
- `external_editor.ts`: the external editor job of each tab. `open` starts it through `native_client.ts` (`editor_start`), keeps `{ job, token, frame_id }` in `storage.session` and loops `editor_collect`. `orphan` marks a tab's jobs when the tab closes or loads: the loop goes on and the result goes to the unnamed register (`save_text`), as it does when the frame does not take it. `orphan` also counts the tab's navigations in memory: `main.ts` stamps the count when an `editor_open` message arrives, and an `open` whose page navigated or closed before its turn refuses and starts no editor. `resume` restarts the loops after a background restart. `make_editor_ext_for` resolves the per-site `editor_ext`.

### Help files for the help page

Behavior of the `src/help` files, moved here from `src/help/README.md`.

- `src/shared/page/help_route.ts`: the pages and the hash parser. The sidebar lists Home, Settings, Quick Start, Practice, Commands, Search Engines and Styling, at `#/`, `#/settings`, `#/quick-start`, `#/practice`, `#/commands`, `#/search-engines` and `#/styling`, then Site Rules at `#/site-rules`. `#section=<page>/<slug>` shows that page at one of its sections (see `sections.ts`). `#command=<id>` shows the Commands page at that command's card (`command-<id>`), and `main.ts` scrolls to it and highlights it like an engine row. `?advanced` at the end of any of those hashes also shows the cards of commands flagged `advanced` (hidden by default, see `visible_commands_model` in `model.ts`); the Commands page has a button that sets it, and a card the hash names stays visible. An unknown hash shows Home.
- Practice page (`#/practice`, `practice_page.ts`): fifteen short lessons in order, as vimtutor teaches. Each has a goal, numbered steps, a target on the page and check lines (`practice-check-<lesson>-<name>`, `data-done`) that turn to "Done" when the page sees the step. `practice_lessons.ts` holds the lesson text and names the fastest key for each task. Its keys come from the keymap through `sentence` in `quick_start.ts`. The page opens on one welcome line, with lesson 1 right below it. Each lesson teaches a skill for any website, and a step that leaves the page names the way back before the key that leaves. The sidebar lists no sections for the page, and a lesson fills the view, so a filtered hint in a lesson stays at one letter. A 300 ms watch reads what no event tells (scroll, zoom, theme, the find highlight, open tabs) and writes the lesson in view into the address with `history.replaceState`, so the way back from `:help` or the video lands on it. That trip rebuilds the page, so `sessionStorage` keeps the leave, whose check turns done on the return, and the ids of the check lines that are done. The tab lesson moves a Settings tab opened while it is in view to just before the Practice tab, once, so the close key lands back on Practice. Like Settings, the page is not redrawn on a settings change (`main.ts`), so a theme change keeps what the reader typed, selected and where the caret is. It declares no color, so it follows the theme. The key test and the demo address the targets by their fixed `practice-*` ids.
- Site Rules page (`#/site-rules?address=<address>`, opened by `:help site_rules` from the tab it names, with the address encoded as one value; `help_route.ts` reads it before it decodes the rest of the hash): the rows of the site table that fit the address, in table order, from `site_rules_view` in `src/shared/site/site_rules_view.ts` through `model.site_rules_for`. Each row is a section with a column table and a key table. Columns draw as name and value, so a new per-site setting needs no code here. A column or key an earlier row decides, or a key the page does not run (off, freed by pass, dropped by only, hidden by a shorter bind), carries `desertfox-help-shadowed` and a reason. The two tables use `desertfox-help-site-rules` (with their own narrow-window labels), not the Commands params class. It has no sidebar sections. Without an address it says where to run the command. It lists the tab's own address only.
- `quick_start.ts`: the Quick Start text as blocks. A `{name}` in a sentence is looked up in the compiled keymap by command and args, shortest key first. A command with no key shows its command line instead, so a rebind or unbind never leaves the text wrong. An "and wait" example (`{prefix}`, `{name:wait}`) names only a key whose pause opens the which-key panel under the reader's `which_key_delay_ms` and `which_key_skip`. Practice drops a note that promises the panel when none opens. The Settings reload step takes its key from the same keymap. The key lookup itself (`BINDINGS`, `bound_key`) lives in `src/shared/bound_keys.ts`, so the new tab page uses it without the help code.
- `model.ts`: turns the help inputs (the commands, the compiled keymap, the warnings and the resolved engines) into plain rows. Key args and the `flags` column are written by the registry printer, so the page matches the command line. Tests read the rows, so no DOM is needed.
- Home: a line on what DesertFox is, links to Quick Start, Settings and Commands, the tip, and a "Problems in your setup" list only when a warning exists (its heading is `#section=home/warnings`, which the popup links). Its sidebar entry has no section list. `config_view.ts` builds the settings source line and the apply steps that the Advanced block of Settings shows.
- Settings page (`#/settings`, the target of `options_ui` in the manifest, so the add-on Preferences button opens it): one field per setting, grouped by name prefix with a one-line intro per group (`GROUPS` in `settings_model.ts`), with a plain label, the code name small below it, a one-line summary, a closed "More" fold with the long description (`SETTING_DOCS`, except site rules, which link to the design doc), a tag that reads "changed", "changed until restart" or "default" (the full layer in its tooltip, `LAYER_LABEL` and `LAYER_TITLE`) and a Reset that drops the saved and temp edit. A "Show only changed settings" checkbox above the groups sets the class `desertfox-only-changed` on the settings box. Each row carries `data-changed`, and `home.html` hides unchanged rows and the groups left empty, so the filter keeps no state and survives a refresh of the rows. A change saves at once through the `change_setting` background message, the same plan as `:set`. Settings that `:set` refuses show read-only with a note that names the live reload key (`model.keys`, read from the keymap like Quick Start). A sidebar link to a settings group turns the filter off, and Reset under the filter moves the focus to the next changed row. The order is the setting groups, then the Keys, Search engines, Aliases and Quickmarks forms, then a collapsed "Advanced" block (`details`) that holds the settings source line, the steps to keep settings in files (`:native.install` once, then `config.reload`) with a button that opens the `:native.install` panel by the same hash, the back up and restore box and the files editor. Every box has a sidebar entry, and a section link into the Advanced block opens it first.
- `settings_model.ts`: no DOM. Picks the control per setting kind (`control_of`), checks typed values with the setting's own check, and holds the session. The session keeps a draft per field and ignores a refresh for a field with a draft or an edit in flight, so a `storage.onChanged` refresh never clobbers typing or an answer. A refresh only reads, so the page's own write cannot loop. The page refreshes on a write of the config status in `storage.local` (`touches_settings` in `src/shared/storage_watch.ts`), which every edit ends with, and `main.ts` stops the listener before it renders another route.
- The `font_family` and `font_family_mono` fields are text inputs with a datalist of the installed font names (`list_font_names` message, answered from the background's cache, so the page never probes) and a preview line (`desertfox-settings-preview`) set in the typed family as you type. The datalist matches the whole text, so it suggests the first name of a list only.
- `site_keys_model.ts`, `site_keys_page.ts`: the "Let this site keep some keys" form in the Your site rules section (`.desertfox-site-keys`, drawn empty by `settings_view.ts`). The model has no DOM: the site, the keys as chips, the pick list (the bound normal-mode keys from `list_bindings`, filtered), the text fold, and the refusal that `key_column_refusal` gives. It sends `site_keys` to save or, with `keys` null, to remove, and reads the rules in force itself, so it follows the row of the typed site. The page binds a capture box with `create_key_capture` from `keys_page.ts`. `help_route.ts` reads `#section=settings/site-rules?site=<pattern>` into `Route.site_keys`, and `main.ts` mounts the form with it, draws the page again when such a link arrives on the open Settings page, and focuses the capture box.
- `settings_page.ts`: draws the fields and wires events to the session. Text fields check as you type and save when left. `settings_view.ts` draws the group headings, so section links work before the list loads. It also draws the Your site rules section after General: a heading with the id `settings-site-rules`, which the popup's rule line links to, an Edit rules link to the files editor in Advanced, and the box that `settings_page.ts` fills with a table of one row per stored rule (site, effect in words from `site_rule_effect.ts`). When the saved layer still holds a `site_rules` list (an older popup's Disable on this site wrote it there, and the start has not moved it into settings.toml yet: a profile without the host or a folder, or a list the files build refuses), the rules carry a Saved here badge, a note says file edits do not apply, and a Reset button clears the saved list through the session's reset. The setting stays a read-only row of the session, so the changed-only filter treats the box like any other row. The page gets the settings through the `list_settings` message and the engine names from the config it already loads, and never imports the registry.
- `keys_model.ts`, `keys_page.ts`: the "Keys" section of Settings, the first form after the setting groups. `keys_model.ts` has no DOM: the binding list, the filter, one open row editor with a draft per row (kept across a refresh and a redraw), the 250 ms check through `check_binding` (the page takes the background's spelling of the keys from its answer), and Save, Remove and Reset through `change_keymap`. A save on other keys moves the binding and sends the text the row had when the editor opened, so the background refuses the move when another tab changed the old key. A row with several steps is read-only. `keys_page.ts` draws one table per mode, with the editor under the open row, and holds `create_key_capture`: the one window `keydown` listener that `main.ts` registers before `content.js` loads. It acts only while the capture box has focus, and the box binds on focus and unbinds on blur and when the section is torn down. `main.ts` mounts the section, follows storage for it, fills the datalist (command names, aliases, snippets from `list_snippets`) and stops it on the next route.
- `engines_model.ts`, `engines_page.ts`: the "Search engines" section, after Keys. The model has no DOM: the engines of the browser layer, the add form (name, address with `{query}`, keyword, key letter) and its local check while typing (`src/shared/engine_fields.ts`, the same one the background runs at Save). The background builds the whole config at Save and refuses what the build refuses. The starter button adds the sample engines whose names no file or layer table uses. The page refreshes on `touches_settings`.
- `pairs_model.ts`, `pairs_page.ts`: the "Aliases" and "Quickmarks" sections, after Search engines. One model and page serve both: a `PairsKind` names the messages, the labels and the local field check, and the background judges the save. A quickmark row from `quickmarks.toml` can be replaced but not removed. The quickmark rows also follow the `M` store key, because `M` writes it without a publish.
- `themes_model.ts`, `themes_page.ts`: the "Import a theme" box under the Appearance settings. The model has no DOM: it parses the pasted or picked scheme at every keystroke (`parse_base16`), so the preview and the problems are live, suggests a name, and sends a save or a remove. A save over a taken name waits for the user to answer Replace or Keep. The page reuses `picker` from `transfer_page.ts` and draws the preview from the scheme's role tokens on its own stage, so the page around it keeps the theme in force.
- `transfer_model.ts`: no DOM. The state of the "Advanced: back up and restore" section: it reads a picked zip or folder (checking each `File.size` against the zip limits before it reads the file), asks the background for the preview, and holds which snippets the user ticked, none at first, and builds the text of the review's reach block (`reach_block`). `commit` sends only the ticked snippets with the code the preview showed. Every commit outcome ends the review and reloads the installed list. It also builds the two export zips, `desertfox-config.zip` and `desertfox-snippets.zip`, from the `export_config` answer. It also exports and imports `desertfox-sessions.json` (`export_sessions`, `import_sessions`), with no review step.
- `transfer_page.ts`: draws the section: export buttons (settings, snippets, sessions, in two rows with a caption each), a zip picker, a sessions file picker and a `webkitdirectory` folder picker, the consent screen (first what the import reaches, then each snippet's full code, `matches` and `requires`, and the warning that a snippet can use every DesertFox permission) and the installed snippets with Remove.
- `host_start_model.ts`, `host_start_page.ts`: the banner at the top of Settings while a host start waits on the user (`desertfox_host_start_pending`, which `main.ts` follows in storage). It lists the files the config folder would replace, add or drop, and offers Export settings (the transfer section's export), Use the files in the folder and Keep what Firefox has. A choice sends the digests the banner showed, so the background refuses an answer to an older question.
- `files_model.ts`, `files_page.ts`, `file_templates.ts`: the "Advanced: edit files" section. It lists the stored files (`config_files` read), opens one in a text box and saves through `config_files` save, which the background applies like an import but as the user's own config. A new file starts from a short commented template. A refused save keeps the text and lists every build problem. A snippet save shows the same consent card as an import (`snippet_card` from `transfer_page.ts`) and sends the code back as `accepted`; an edit voids the tick.
- Search Engines page: the guide from `docs/search_engines.md` (browser steps first, the file route after), then every resolved engine in tree order with label, URL, needed slots, fallback and the file and level that set each field. `engine.show <name>` opens the page at `#engine=<name>`, which `help_route.ts` maps to this page, and `main.ts` scrolls to the row.
- `blocks.ts`: the block list type, including `tip`, the callout on Home and Commands. `quick_start.ts` writes it (`tip_block`) so its command line key follows the keymap, and `dom.ts` (`block_node`) adds the "Tip" label. It has no dismiss control. `tools/render_docs.ts` turns the guide's markdown subset into blocks at build time (it fails on any other markdown) and `tools/build.mjs` writes `dist/search_engines_guide.json`. `main.ts` fetches it.
- `dom.ts`: the DOM toolkit the pages share (`el`, `inline_node`, `code_block_node`, `copy_code_and_confirm`, `table_of`, `new_tab_link`). It imports no page. `block_node` draws a block and `page_link` links to a page. Every page file imports the toolkit from it.
- `sections.ts`: the section model. `page_sections` lists each page's sections, the Settings section titles, and `section_anchor`, `section_hash` and `section_heading` name them. It imports no renderer.
- `sidebar.ts`: the sidebar and the narrow-window drawer. Each page gets a sidebar group: a link, a chevron button and a list of section links. Going to a page opens its group, the others start closed, and each chevron toggles its own group. A toggled group keeps its state across renders, in memory only. It also holds the "you are here" mark (`mark_current_section`) and the support card, and clears the changed-only filter when a section link needs a hidden group.
- One renderer per page, each drawing with DOM calls. Command text never goes through `innerHTML`. A `code_block` (drawn by `code_block_node` in `dom.ts`) gets its own themed box with the fence language as a label and a Copy button. `page_sections` (in `sections.ts`) builds the section list for every page, and the headings take their ids from the same list. `main.ts` scrolls to the section heading and focuses it.
- `user_css_gate.ts`: `create_user_css_gate` keeps the user CSS sheet off the page while the import review, the files editor's consent card or the grant panel is on screen. Each of those views shows `USER_CSS_PAUSED_NOTE`, so the reader knows why their styling went.
- `grant_panel.ts`: the panel `:permissions.grant <permission>` and `:native.install` open (`#grant/<permission>?<nonce>`, a new nonce each time so a tab already on the page sees a hash change and shows it again after Close). It sits outside the body, because the router rebuilds the body on each route. Its button asks for the permission and must stay inside the click handler, since Firefox grants an optional permission only from a click. For `nativeMessaging` it also shows the `curl` command for this build's channel (`src/shared/native_host.ts`) and, on a release build, the "Install and keep the native host updated" button, which saves `host_auto_update` through a `change_setting` message and installs nothing. `main.ts` calls `mount_grant_panel` with the user CSS gate, which hides user CSS while the panel shows.
- `home.html`: the page and its styles. It links `src/shared/page_base.css` first, which holds the fallback palette, so the page only reads the `--desertfox-` variables and never declares a color. The theme sheet and `style.css` come after and win. The page also sets the extension icon as its tab favicon. It loads `content.js` by script tag, because `moz-extension://` pages do not match `<all_urls>`. That gives the page `j`, `k`, `gg` and the mode badge. Every other bundle loads on first use, as on a website. `executeScript` cannot reach extension pages, so the background recognizes a request from an extension page and asks `help.js` to add the `<script src>` tag (`listen_for_bundle_requests` in `src/shared/page_bundle_tag.ts`). The answer comes after the script has run.
- At 40rem or less the sidebar is a drawer (the `@media (max-width: 40rem)` block in `home.html`). `render_help` adds a top bar with a menu button and a backdrop, both hidden above the breakpoint, and `wire_drawer` opens and closes it. The open flag is a class on `.desertfox-help`, so each render starts closed. `main.ts` registers `close_drawer_on_escape` in the capture phase before `content.js` loads, so Escape closes the drawer and never reaches the key flow.
- `settings_page.ts` draws `newtab_links` as a list of rows (label, address, group) in the New tab group (`link_list` control), saved as a whole list.

`STYLE_VARIABLES` and `STYLE_CLASSES` in `model.ts` list the public styling surface. The variables come from the theme role list, so a new role shows on the Styling page with a meaning the compiler forces you to write. Add a surface's class names there when it ships.

Look: the page styles read `var(--desertfox-*)` only, including the `accent`, `info`, `ok`, `warn` and `error` roles (fallbacks in `page_base.css`). A command card has a head row (title left, `key_caps` right, a muted dash and an `aria-label` of "no keys" when unbound), the description, the usage line and the params table, which stays open because a hint or Tab cannot reach closed content. `commands_view.ts` sets `data-accent` on each card, cycling over the command groups, and the stylesheet maps it to a bar color. Warnings use `warn`, errors `error` and the "changed" tag `ok`. The control rules (inputs, selects, textareas, the key capture box that wears `desertfox-settings-input`, and buttons with their hover and disabled states) sit entirely inside `:where()`, so a control needs no class and any class rule wins over them. Heading sizes are in `em`, so they follow the body size a theme sets in `--desertfox-font`. The `font_scale` setting multiplies the text size only (`--desertfox-font-scale`), never the root, and `font_family` and `font_family_mono` set `--desertfox-font-family` and `--desertfox-font-family-mono` (key caps). The sidebar link of the section on screen carries `aria-current="location"` (`mark_current_section` in `sidebar.ts`). One scroll listener and a `ResizeObserver` on the page column queue the mark once per frame, it writes only on change, and the sidebar scrolls only when the current link changes. Quick Start draws a key it names with `key_caps` (the `keys` inline kind in `blocks.ts`), and a command line or setting name stays inline code. The root is 16px up to 1600px wide. Above that it grows in a straight line to 18px at 3440px, and the column cap (60rem at 1600px, at most 110rem) grows with it, so a wide screen gets bigger text and a wider column. Prose (`p`, `li`, the tip) stays within 80ch, so a long line never forms. At or under 40rem the window is a drawer, as above.

### Shared files for pages

Behavior of the `src/shared` files for this area, moved here from `src/shared/README.md`.

- `icon_cache.ts` (in `page/`): the favicon cache. See its entry under "New tab files for the new tab page".
- `page_base.css`: the base sheet of the help and new tab pages, copied to `dist/` and linked first in both html files. It holds the fallback palette (including the accent, info, ok, warn and error roles), the type and spacing tokens, the key cap, card and pill styles, and a 15px root size. The help page overrides it with 16px, which its layout is measured in. Every fallback sits in `:where(:root)`, at zero specificity, so a theme or `style.css` rule always wins. Pages add their own colors only as `var(--desertfox-*)`, never as a declaration.
- `key_caps.ts`: `key_caps(text)` draws a key sequence (`gt`, `<Space> g t`, `<C-x>`) as a row of `kbd.desertfox-keycap`. It reuses `parse_sequence`, and a word the notation refuses stays as one literal cap.

### New tab files for the new tab page

Behavior of the `src/newtab` files, moved here from `src/newtab/README.md`.

- `main.ts`: reads the `new_tab_page` setting through `resolve_new_tab_page` (`src/shared/config.ts`). A web URL redirects with `location.replace`, so the content script runs on that site as on any page. Anything else draws the built-in page, and so does `newtab.html?builtin`, which `home_page = "desertfox"` opens.
- `render.ts`: draws the built-in page: the clock, the date and the lists, each on unless its setting is `false`. `main.ts` draws through `follow_settings` (`src/shared/storage_watch.ts`), so a settings change redraws the page: the new page is built off screen and swaps in, the old clock stops first (`run_ticker` returns its stop), and only the first draw may redirect for `new_tab_page`. `newtab_clock` is analog for `true` or `"analog"` and digital for `"digital"`. A 1 second tick moves the hands and rewrites the date, so a tab left open past midnight shows the new day.
- `lists.ts`: the rows under the clock: `[[newtab_links]]` by group, then Recent tabs and Bookmarks, each hidden unless `newtab_recent_tabs` or `newtab_bookmarks` is true (`newtab_*_max` rows, default 8). It runs the tab and bookmark readers of the completion (`src/shared/completion/tab_rows.ts`) on the page, with no background message, so it filters on its own: private tabs never show, and a private page lists no tabs. Recent tabs sort by `lastAccessed`, bookmarks by date added. A recent tab row switches to its tab. A reader that fails drops its list. Each row carries its host (without `www.`) and an `icon_url` that is only ever a data: URL from the favicon cache for that host, or none, which draws a letter tile. A tab's own `favIconUrl` is ignored, so the page loads no remote icon.
- `widgets.ts`: the rows of Recently closed (`newtab_closed_tabs`) and Top sites (`newtab_top_sites`), both off by default, `newtab_*_max` rows, 8 each. Closed tabs come from `sessions.getRecentlyClosed` through the completion's `closed_tab_rows`, and a click restores the session. Top sites come from `history.search` over pages visited in the last 90 days: the lifetime visit counts of those pages add up per host, and the host's most visited page is the link. Neither lists anything on a private page. `render.ts` also draws the `newtab_command_hint` button, which runs `cmdline.open` through a `run` message, whatever key is bound. It first names the default key `:`, then `cmdline_key.ts` reads the bound key from the stored keymap (`src/shared/bound_keys.ts`) and the button shows it, or "open the command line" with no key when none is bound. A redraw waits for that read before it swaps in, and an open page does not follow a rebind. It is a button, not an input, so the address bar keeps its focus.
- `net_widget.ts`: the one fetch-and-cache helper for cards that use the network. `fetch_text` sends no credentials and no referrer, waits 5 s and returns undefined on any failure. `load_cached` keeps one `storage.local` key per card (`newtab_net_cache_<name>`), shows a stored value of the same key at once, fetches only past the TTL and keeps the stale value when a refresh fails, up to `max_age_ms`. `peek_cached` reads a slot by key prefix, for a card that draws before it knows its full key. It checks no setting and no privacy, so each card must do both first. `stoppable_net` wraps an env so a stopped run sends nothing and writes no cache. `ip_info.ts` and `weather.ts` use it.
- `weather.ts`: the weather card (`newtab_weather`, default on, Open-Meteo). Nothing is read or fetched while it is off, a private page does nothing, and without the optional `locationInfo` data collection consent it is only the permission button and sends nothing. With the consent and neither a city nor a granted position it is the same. Each request first checks the consent again. `newtab_weather_units` is `auto` by default: the geocoder's country for a city, else the forecast's time zone for a position (the request is metric, and a US, Liberia or Myanmar zone converts the answer on the page), imperial for those three and metric otherwise. The place is the geocoded `newtab_weather_city`, else the browser position when the optional `geolocation` permission is granted, else a "Show the weather here" button that requests the consent (and the permission, when no city is set) from its click and sends no request. A city shows no button once the consent is granted. Coordinates are rounded to 2 decimals. A failure draws nothing. `render.ts` starts it without awaiting. The card sits in the top-right corner, outside the centered column: the icon and temperature, then feels like, today's high and low, humidity, the rain chance of the current hour (left out when Open-Meteo gives none), the wind and a More button, from one forecast request. A draw with the setting off deletes the stored answer (`forget_weather`). A redraw or a location grant stops the run with `stoppable_net`. A stored answer holds the forecast's local date and offset and counts as stale once the place's date moves on. Opening More draws the strip again from the stored hours and starts the air quality request. The open state of the detail is read back from the old More button, so the second draw of a stored then fresh value keeps it. `weather_icon.ts` draws the line icon from the weather code, with `role="img"` and the condition as its label.
- `weather_detail.ts`: what the More button opens: the strip of hours from the current one (the first column reads Now, each column is time, condition icon, temperature and rain chance with a thin bar), a hairline divider, then UV index (today's maximum), sunrise and sunset side by side with small icons, plus the compass point and the 12 or 24 hour text. Hours before the place's current hour are dropped, and the strip is hidden under 3 hours. The strip is one row of columns (time, icon, temperature, rain chance) with no wrap and no scroll, and `hours_that_fit` picks 6 to 11 of them from the window width and zoom at each open. It is plain text, so hints and Tab reach only the button.
- `air_quality.ts`: the air quality row in the More panel, from Open-Meteo's air quality API (`air-quality-api.open-meteo.com`). Opening More starts it and nothing earlier does, so a panel never opened sends nothing. It asks about the forecast's rounded coordinates (`Weather` keeps `latitude` and `longitude` for this), for the US AQI when units are imperial and the European AQI when metric, plus PM2.5, PM10 and ozone. The row shows the index with a short band label. The row sits under its own divider: the index with a dot colored for its band (`air_level`, theme colors only), the band name, and PM2.5, PM10 and ozone as smaller values. `make_air_loader` runs through `load_cached` under its own key `newtab_net_cache_air` (30 minute TTL, 6 hour limit) on the run's `stoppable_net`, and shares one request per place and units, so two quick opens send one. The row draws only while its panel is open and on the page and the run is live, so a close, a redraw or a stop leaves no late draw. A failure draws no row and the rest of the panel stays. `forget_weather` deletes this key with the forecast's when the setting is off.
- `ip_info.ts`: the opt-in IP info line (`newtab_ip_info`, default off, Cloudflare `1.1.1.1/cdn-cgi/trace`). It draws one muted line under the date, such as `203.0.113.7, Norway`, and reads nothing else from the answer. Nothing is fetched while it is off or on a private page, a failure or an answer that does not look right draws nothing, and the cache lives under its own key `newtab_net_cache_ip`: it draws first and refreshes at most once a minute, and a draw with the setting off deletes it. `render.ts` starts it without awaiting and stops it with the page on a redraw.
- `tile.ts`: one card per row, icon box, title and host, with the whole card as the one anchor, so a hint labels it once. The icon is an `img` (a data: image only) that swaps to the letter tile when it fails to load. The letter tile is a `color-mix` of `--desertfox-primary` and `--desertfox-bg-mantle`, so it follows the theme. The grid in `newtab.html` is two 14rem columns, one on a narrow window, and fills row by row, so DOM order is visual order.
- `src/shared/page/icon_cache.ts`: the favicon cache, `favicon_cache` in `storage.local`: entries of host, a 32x32 PNG data: URL and a short key of the tab icon it was redrawn from. At most 200 hosts (the oldest saved drops first) and 6144 characters per icon, so the cache stays under about 1.3 MB. `src/background/favicon_saver.ts` fills it from the shared `tabs.onUpdated` listener in `src/background/main.ts`. Firefox gives the background each tab icon as a data: image, and the saver redraws it through a canvas to 32x32. Nothing is fetched, and a `favIconUrl` that is not a data: image stores nothing. The saver loads the stored keys into memory once, so an unchanged icon costs no read and no decode, also after a restart. A host is saved at most once per 3 minutes. One redraw per host runs at a time, and a failed redraw is not tried again until the icon changes. A save of an unchanged entry writes nothing, a full storage warns once, a private tab saves nothing, and a save that began before "Clear all history" is dropped (`src/background/history_clear.ts`). Writes queue so two saves that finish together both land. There is no other forget path to wire it into. The storage is passed in, so the module needs no browser global. The new tab page reads the cache.
- `clock.ts`: the 12 hour SVG clock without ticks. Hand angles keep growing past 360 so the CSS transition never rewinds at a wrap.
- `digital_clock.ts`: the digital clock, `HH:mm` in seven-segment digits, with an AM or PM suffix when `newtab_clock_format` is 12 (the default). `fonts/` holds the font, DSEG7 Classic by keshikan, unmodified with its SIL OFL 1.1 text. The licence reserves the name "DSEG", so do not convert or edit the file. Only `newtab.html` declares it.
- `newtab.html`: the page and its styles, and the built-in links (Getting Started and Help) as plain anchors in a fixed `nav`, and the Settings gear (an inline SVG in a plain anchor to `home.html#/settings`, top-left corner, labelled "Settings"), so hints reach them. Every bundle except `content.js` loads on first use, as on a website. `executeScript` cannot reach extension pages, so the background asks `main.ts` to add the tag (`src/shared/page_bundle_tag.ts`), and a new bundle needs no edit here.

Firefox gives the address bar focus on Ctrl+T. Press Esc or click the page before the keys work.

After Firefox's one-time "Your new tab has changed" notice, its hidden Keep Changes button keeps access key K for that browser session. So Alt+K (previous tab) does nothing on about: pages until a restart. Accepting the notice once avoids it.

`newtab.html` links `page_base.css` (`src/shared`) first, the same base as the help page, so both pages share one palette, type scale and key cap and card styles. Its rules read `var(--desertfox-*)` with no fallback and declare no color, so the theme sheet and `style.css` win. The page sets the extension icon as its tab favicon.

### Editor files for the external editor

Behavior of the `src/content/editor` files, moved here from `src/content/editor/README.md`.

The `editor` bundle (`editor.js`, its limit is in `MAX_BYTES` in `tools/build.mjs`). The background injects it into a frame on the first `text.edit_external` (`<C-o>` in insert mode).

- `main.ts`: the handler reads the focused field and refuses a non-editable focus, a password field (`is_secret_field`) and text over the host's 128 KiB cap, then sends `editor_open` to the background with a fresh token. The background answers with a refusal (a second editor in the tab, a host error), which the key shows as a toast. The edit stays in a page-local map by token, with the field and its text at the press. When `editor_done` arrives, the page answers `true` for a token it knows, so the background can send the text to the register when it does not. An unchanged field takes the result: a plain input or textarea through the native value setter and `input` and `change` events, a contenteditable through `type_at_caret` over its whole content (`delete` for an empty result). The check runs again after `focus()`. A field that changed, left the page or refused the write keeps its text, and the result goes to the unnamed register. The toast says which of the cases it was, and claims the register only once the register took the text.
- `clipboard_fallback.ts`: the path for editors that show only part of their text (CodeMirror, Ace, Monaco and the hidden textarea of CodeMirror 5, found by container class). It saves the clipboard text, writes a marker, focuses the editor's content element, sends a synthetic Ctrl+A (Cmd+A on macOS) and runs `execCommand("copy")` through `exec_clipboard_command` of `src/content/lib/clipboard.ts`. An uncancelled Ctrl+A, a copy event nobody saw, the marker still on the clipboard or a copy that misses one of the drawn lines (a keymap that binds Ctrl+A to another command), compared without whitespace or order and without the CodeMirror 6 placeholder, keeps the refusal. The saved text goes back before the editor opens, so a navigation strands nothing. Every copy that no write follows ends with an ArrowLeft, so no select-all waits for the next typed key. On return it checks the element is still on the page, copies again and compares with the opened text, writes the result to the clipboard, checks the drawn lines again, then selects all and pastes (`cut` for an empty result). A last copy reads the document back and compares it exactly, because a read-only editor sees the paste and drops it. It skips the drawn-lines check, as Ace and Monaco redraw a frame later. A failure at any step sends the result to the unnamed register. A clipboard that could not be restored refuses the open, and after a return the toast says so. Presses and returns in one frame run one at a time through `queued_in_page`. Only text is saved, so an image or HTML on the clipboard is lost, and a toast says the clipboard was used. The whole document passes through the system clipboard, where a clipboard history tool can record it.

### Which-key files for the which-key panel

Behavior of the `src/content/whichkey` files, moved here from `src/content/whichkey/README.md` and the content README.

The which-key panel: a floating list of the keys that can follow what the user has typed. It ships as the `whichkey` bundle, which the content script loads on first use.

- `whichkey/` (`content/gate.ts` ships in content.js, not the bundle, and decides which prefix changes reach the bundle. `timer.ts` runs the timer inside the bundle, `session.ts` drops answers that came too late, `panel.ts` draws): a half-typed sequence starts a timer (`which_key_delay_ms` from the compiled keymap, zero is off). The next key, a reset or a mode change cancels it and hides the panel. Backspace in a half-typed sequence drops its last key and shows the parent group, and at the first level it clears the sequence. Escape clears it at any depth. When it fires, the `whichkey` bundle asks the background for the keys that follow (`list_keys`) and draws them under a title that chains the group names (`+Go » +Close tabs`), then rows of key, arrow and label and a footer, in a floating frame in the corner above the badge (`which_key_border` picks the corners). The delay applies only to the first panel: while one is up (the timer remembers that the session drew a nonempty one), each further prefix key redraws at once, as Backspace does. A prefix that exactly matches an entry of `which_key_skip` (carried in the compiled keymap) starts no delayed open, so its panel does not open after the delay. An instant redraw (Backspace, or a panel already up) ignores the list and still shows it. `?` lists only the first keys of the mode. A new keymap cancels the timer and hides the panel. Rows past what one column holds (at most 20, 22 px each, 96 px reserved) add columns, up to 4. Shown in normal, caret, visual, media, insert and hint mode. `<A-?>` opens the first-keys panel in each of them, but insert and hint mode show no panel after a pause. Ignore and the command line have no such key. In insert mode with no field focused the chord goes to the page. The timer is pure and unit tested, the panel needs a DOM.

- `main.ts`: the bundle entry. Registers the `whichkey` handler (with a prefix it shows the panel, without one it hides it) the `help.whichkey` handler (lists the first keys of the mode) and the `whichkey.media_panel` handler (the background's open on entering the media mode, which `media_panel.ts` admits only while the frame is still in media mode and not in full screen). A second run does not register again.
- In a subframe, `main.ts` draws and erases through the top frame (`whichkey.draw`, `whichkey.erase`, relayed by the background), so the panel shows where the user looks and lists the subframe's own keys. Each message carries a count that starts at the document's start time, and `relayed_panel.ts` drops one that arrives after a newer one from the same frame, also across a new document in that frame. An erase hides only a panel the erasing frame drew, never the top frame's own. A subframe erases its relayed panel on `pagehide`. A top frame that does not answer leaves the panel in the subframe.
- `session.ts`: decides whether an answer from the background may still be drawn. It skips modes that have no keymap to list, and drops an answer when the next key arrived first or a hide came in between.
- `guarded_rows.ts`: `rows_for_page`, which `main.ts` runs on each answer. A row with a `chain` (a key guarded by `when_focus` or `when_present`, which the background cannot test) goes when no leaf of the chain holds in this frame, and shows the label of the leaf that does.
- `panel.ts`: draws the panel in a closed shadow root: the title chip in the top border, a row per key, a footer. The footer ends with a `.` line when the panel carries `repeat`.
- `style.ts`: the panel's sheet (`STYLE`). Pure text with no imports, like `layout.ts`, so DesertBird can vendor both.
- `layout.ts`: how many columns the rows need for the viewport height, and how the title chain joins and shortens (`fit_title`: whole groups drop from the start and "…" stands for them).
- `timer.ts`: starts the panel after a pause in a half-typed sequence. The next key, a reset or a mode change cancels it.

`main.ts` fills `repeat` from a second message, `read_repeat_preview`, sent beside `list_keys`. The background answers with text built in `repeat_preview` (`src/background/repeat_memory.ts`), or nothing when the `which_key_repeat` setting is off.

The data comes from `src/background/list_keys.ts`, through the `list_keys` message. It builds the `WhichKeyPanel`: the title (the chain of group names, `["+Go", "+Close tabs"]`, which the panel joins as `+Go » +Close tabs`), the rows and the border style. See `src/background/README.md`.

### Popup files for the toolbar popup

Behavior of the `src/popup` files, moved here from `src/popup/README.md`.

The toolbar popup (`default_popup`). It is a page of its own, so a click on the button never reaches `browserAction.onClicked`.

- `model.ts`: the rows, from plain inputs. No DOM, so tests read them. Row order: the on/off switch, Disable on this site, Let this site keep some keys... (`keys_for_site`: a link to the Settings form at `site_keys_hash(pattern)`, grey with its reason while DesertFox is off, on a page with no site or on a disabled site), the rule row, the warnings count (only when it is above zero), Reload config, Settings, Help, Keys, Support DesertFox. The model also holds the release link of the version (`release_url`: the tag for a release, the releases list for a beta), the theme list (`theme_options`), the host dot (`host_dot`) and the notice timer (`create_notice`: a success notice clears after 4 s, an error stays, and a newer notice cancels the older timer). Every state line and detail starts with a capital letter. `site_card` words the host and state line of the site card. The site row is grey while off, with "A rule covers it" when another row decides the page's `off` column, and with no site on a page that is not http or https. The rule row shows what the matching rows set ("All off", "Pass 3 keys", "Only 2 keys", "On, pass 1 key") and links to the Your site rules section heading of the settings page (`#section=settings/site-rules`, the id `settings-site-rules` that `src/help/sections.ts` draws on that heading). Rule edits reach open tabs at once, so the popup offers no tab reload. Reload config is a button, not a link, and is grey without the native host.
- `main.ts`: reads storage and the active tab when it opens, draws the header (icon, wordmark, host dot, version link), the two-segment On/Off control (native radio buttons, so the arrow keys move the choice), the site card (host, state line, the site button and the rule line), the outlined Warnings row with a CSS chevron, the theme dropdown, the notice line, then one section above the footer with the Reload config button (inline icon) and one row split in three for Settings, Help and Keys with inline SVG icons, and last the Support row with a heart icon, and sends the writes to the background (`toolbar_set_disabled`, `toolbar_site`, `toolbar_reload_config`). It writes nothing itself. The header carries the native host dot (it follows `desertfox_host_connected` in `storage.session` live: a listener set before the first draw keeps the latest value, and every paint reads it) and the version as a link. The theme dropdown sends `change_setting` with layer `file`: the background writes the pick into settings.toml (the browser copy, then the folder through the native host) and drops any saved or temp theme, so the pick lasts and the file stays the one source. Without the host the notice says the file updates when the native host connects. A redraw restores focus by a `data-focus-key`, and only the newest draw may paint. Settings, Help, Keys (the Commands page) and Warnings open the help page through `plan_help_tab`. Support DesertFox opens the GitHub Sponsors page in a new tab beside the active one, with no tracking. The popup themes like the help page and stays themed while off.
- `popup.html`: the page and its styles. The theme primary is the one accent, and every color has a hex fallback for the first paint.
