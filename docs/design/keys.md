## Keys and modes

The keymap is data, not code. It maps a mode and a key sequence to an invocation:

```json
{
  "normal": {
    "J": { "id": "tab.next" },
    "D": { "id": "tab.close", "args": { "side": "focus_previous" } },
    "sa": { "id": "open.search", "args": { "engine": "arch" } },
    "ca": { "id": "tab.reopen_in_container", "args": { "container": "Family" } }
  },
  "browser": {
    "<A-j>": { "id": "tab.next" },
    "<A-k>": { "id": "tab.prev" }
  }
}
```

- The extension ships a default keymap. The user config overrides it, as described in [Config](config.md#config).
- The background checks each entry against the registry when it loads. A bad entry logs a warning and is skipped, so one typo does not break the rest. The help page lists the warnings.
- Key notation is vim style: `<C-x>`, `<A-j>`, `<S-Escape>`. Sequences match through a prefix tree. A complete match runs at once, with no timeout.
### Mode parents

- A mode can name a parent mode in the default keymap (`mode_parents` in `src/shared/keys/default_keymap.ts`). The user config cannot set one. Today visual item mode (`item_visual`) has item mode as its parent, with a leave step.
- The child takes every key of its parent that it does not bind itself. Its own keys win at every node: an own key hides a parent group of the same keys, an own group hides a parent key, and two groups merge (visual item `gg` beside item `gt`). A child's tree resolves its parent's first, so a parent's own parent counts too.
- A parent key comes only when every command of it, every choice of a guard chain included, lists in its registry `modes` the mode it runs in: the parent after a leave step, else the child.
- The leave step is `mode.set` to the parent, put before each step of every key the child takes, so the key runs in the parent mode. `f` in visual item mode ends the selection, then shows the hints, and Escape from the hints returns to item mode. A key with a background step goes to the router whole, which sends the leave step back to the page first. The step carries a `leave` flag that the matcher and the runner ignore, so content.js holds no code for it.
- An empty binding in the child's section blocks the parent key there (`[item_visual] f = ""` sends f to the page and keeps the selection), and on a prefix it drops the parent's whole group under it (`";" = ""`). A user key in the parent reaches the child: `[item] f = ...` changes visual item `f`, and `[item] f = ""` removes it from both.
- The compile stores each mode's own tree, the link with its checked leave step, its blocked keys and the commands that pass the `modes` filter. These readers resolve the child trees (`src/shared/keys/mode_parents.ts`): the page reply and which-key after the row grafts and the `pass` and `only` pruning and before the `item_select` arrows rewrite, so a row's item key reaches visual item mode, and the help page, the site table view and the key editor's shadows from the stored trees. The completion keys column reads the stored trees as they are, so it lists no taken key.
- A taken key with a background step leaves visual item mode only once the router has sent the leave step back to the page, so a key typed fast behind it can still extend the selection. A later step that refuses (`J` or `gt` with one tab, `H` with no history) still ends the selection, since the leave step ran first.
- Which-key and the help page skip the leave step, so a taken key lists under its parent command (visual `f` under `hint.run`) with the parent key's label. `docs/keymap.md` gives each child one line for the keys it takes.

### Modes and insert mode

- The modes are normal, insert, ignore, hint, cmdline, caret, visual, line visual, media, grab, item and visual item. See [Caret and visual](interfaces_caret_search_marks.md#caret-and-visual) and [Grab](interfaces_hints.md#grab). Insert mode follows `focusin` and `focusout` on editable elements. Each keydown and keyup also re-reads the focused element and follows a change in whether it takes typing, because a page can change that with no focus event. A key that finds no change leaves the mode alone, so Escape holds in a frame whose body is the editor and keeps the focus.
- The case that needs the re-read: the Google Sheets cell editor holds the focus all the time and counts as a field only while a cell is being edited (see [Firefox behavior](../firefox-behavior.md#the-google-sheets-cell-editor-sheets-cell-editor)). `i` enters insert mode with no field, in every frame of the tab, and a frame that loads later joins it.
- The background sends one message to the tab with no frame id and keeps only a flag for the hold, never a list of frames. A frame under an all-off site rule drops the message and stays in ignore mode, in both directions. Focus leaving a field does not end it. Escape in any frame returns all frames to normal, and so does a navigation. With no field focused, insert mode handles only Escape, so `<C-r>` and the other insert keys go to the browser.
- `gi` focuses the first field. A hidden input frame is a child frame of the page's own origin that the user cannot see: under 4 px on one side. Where the frame sits does not count, so an editor in a full-size frame that is scrolled out of view is not one. A page such as Google Docs types into one. While such a frame is in normal mode it blurs its own frame element, so the document that holds it gets the keys and every command, sink and panel works there.
- It hands off on each change into normal mode and when it gains the focus in normal mode, and no rule names a site. Escape hands off in the key's own turn. Every other hand-off waits one tick, so a focus move that leaves the frame for a field of the page is not cancelled. A mouse press that focuses the frame's field returns to insert mode, and so does `gi`, which picks a field in one of the page's hidden input frames ahead of the page's own visible fields.
- A frame that gains the focus again within 500 ms of a hand-off, with no insert mode between, keeps it, so a page that fights for the focus does not loop. While the page holds the focus, keys the page's editor handles in the frame (arrows and PageDown in Docs) do nothing.

### Layout fallback

- On a layout whose letters are not Latin (Cyrillic, Greek, Hebrew, Arabic and others), a plain letter whose typed character binds nothing acts as the Latin letter on its physical key (`event.code`). Shift gives upper case. A Latin letter outside ASCII, such as the Turkish `ı`, never swaps.
- A typed character that binds something never changes, so Latin layouts see no difference. A Ctrl, Alt or Meta chord has no fallback here: `token.ts` already maps it.
- A mode with a sink (hint mode) gets the typed letter and the physical one beside it. Label mode takes the typed letter when it continues a label, else the physical one, so Latin labels work on a Cyrillic layout. Text mode (after `/`) takes the typed letter only, so its filter keeps the typed text. With the setting off the sink gets no physical letter.
- The `layout_fallback` setting (default on) controls it. The compiled keymap carries `layout_fallback: false` only when off, and `key_flow` reads it on each install, so a config reload applies it.
- Only the content script applies it. A key typed before the keymap reply is held with its physical letter and replays under the rule. The command line page does not apply it: its default keymap binds no plain letter, and a letter typed in the line stays text.
- Letters only. No punctuation key was measured as needed.

### Leader and cancelled keys

- `,` is the built-in leader for DesertFox's own commands (`,r` reload, `h` help, `s` settings page, `t` toggle a setting, `i` ignore mode, `b` blur, `?` all keys, `"` registers). `<A-?>` lists the first keys in every mode except ignore and the command line (which keeps its own `<C-h>` help). In insert mode with no field focused the chord goes to the page. Space stays with the page, so pause on video sites and Space-to-scroll keep working. `,` alone runs nothing, because a key cannot be both a binding and a prefix.
- The which-key panel shows the group after the pause, and a key outside the group starts a new sequence, so `,G` scrolls to the bottom. A lone `,` in normal mode no longer reaches the page. `pass = ","` in a site rule gives it back on one site, and `<C-v>,` passes one comma. DesertFox reserves no user leader: `\` and `<Space>` are unbound by default, and a user who binds Space as a leader loses Space on the page.
- In every mode except insert, ignore, hint and cmdline, DesertFox cancels a `/` or `'` keydown that no binding takes, when focus is not in a field. Shift does not matter, but Ctrl, Alt or Meta do. Firefox starts Quick Find on these keys in page content (see [Firefox behavior](../firefox-behavior.md#firefox-defaults-not-measured)), and Quick Find competes with DesertFox's own [page search](interfaces_caret_search_marks.md#page-search). Insert and ignore mode give keys to the page, and hint and cmdline mode own theirs. Every other mode is covered, so a new mode is covered without a change.
- In caret, visual and line visual mode, DesertFox also cancels every other unbound key without Ctrl, Alt or Meta, outside fields. These are reading modes, and a site shortcut (a letter in a mail app, a digit in a video player) moves the user away from the caret. Tab and Shift+Tab, the function keys, Escape, Page Up, Page Down, Home and End still reach the page. So focus moves, Firefox's own keys work, a page dialog closes and the page scrolls. Space and Backspace stay blocked. Every chord passes too, so Ctrl+C copies a selection. Normal mode passes unbound keys, apart from `/` and `'`.
### Key editor capture

- The Keys section of the settings page edits one binding in a row editor: a capture box, a command field and a live check. The capture box is a focusable `div`, not a text field, so insert mode and the IME stay out. One window `keydown` listener in the capture phase takes the keys. `main.ts` registers it before `content.js` and the drawer's Escape handler load, so it runs first and stops the event. It acts only while the box holds focus: the box binds on focus and unbinds on blur, on a route change and on removal from the page. No other listener is added.
- Opening an editor moves the focus into the capture box. On an existing row the box shows the row's keys, and the first press replaces them. Escape cancels the capture and puts the row's keys back. Backspace drops the last key. A Clear button empties the sequence. Tab and Shift+Tab move the focus as usual, so the box never traps the keyboard. Enter saves. A modifier on its own is ignored. Saving an existing row on other keys moves it: one `change_keymap` set with `move_from` frees the old key (an empty text for a file or default binding, a dropped edit for a key only an edit binds) and binds the new one, in one change with one rollback. A row with several steps keeps its keys. Firefox keeps some chords for itself (Ctrl+T, Ctrl+W, Ctrl+N, F5) and the page never sees them. Escape, Backspace, Tab and Enter cannot be bound from the box, so the page tells the user to use the config files.
- A row with several steps shows its steps joined by ` ; ` and is read-only, because the check refuses that text. Its Remove and Reset still work. The command field offers the command line names, the aliases and the installed snippets in a native `datalist`. The check, 250 ms after the last change, is the real validator.

### Badge, toast and which-key panel

- A mode badge sits in the bottom right corner, 8 px above the bottom edge. The `mode_indicator` setting controls it: `always` (the default), `not_normal` or `off`. The `theme` setting names a theme (default `oasis_moonlight`), see [Themes](config.md#themes). Light or dark follows Firefox, and Firefox's Settings > General > Website appearance (Automatic, Light or Dark) switches it.
- A toast is one short message in the bottom right corner, framed in the color of its kind (error, warning, info or success). It disappears after `toast_error_ms` (default 6000) for an error and `toast_ms` (default 3000) for every other kind, whole milliseconds from 500 to 30000. The compiled keymap carries both values, as it does `which_key_delay_ms`, and the content script hands the one that fits the kind to the `ui` bundle with each toast.
- The which-key panel is a floating frame with a 1 px tinted border and its title set into the top border. The `which_key_border` setting picks the corners: `square` (the default), `round` or `chamfer`. The `which_key_skip` setting lists key prefixes, in keymap notation, whose panel does not open after the delay (exact match, global, checked with the key parser). An instant redraw still shows it: Backspace back to the prefix, or a key typed while a panel is already up. `?` lists only the first keys of the mode. A footer names the exit keys. Below them a `.` line shows the step `.` would repeat, as the command line that does the same (a command with no name shows its label), while the panel is open. A saved count shows too: a count that maps to an argument shows as that argument, and a repeat count, which the command line cannot spell, shows as a prefix such as `5× :scroll`. A label has no argument, so a command with no name shows either kind of count as that prefix. The `which_key_repeat` setting (default on) turns it off. The panel bundle asks the background with `read_repeat_preview` and the background reads the normal slot of the repeat memory only, so a private tab gets no line.
### Bridge and browser mode

- The `bridge` setting (default off) opens the native bridge, and `bridge_share_tabs` (default off, needs `bridge`) lets it list, activate, close and capture tabs, see [Bridge host](host.md#bridge-host). Neither changes the badge or the which-key panel: both stay in the page.
- `browser` mode holds the chords for the Firefox shortcuts. The manifest reserves a fixed number of shortcut slots, and the background assigns the chords to them with `commands.update`. A chord keeps its slot: `desertfox_slot_map` (chord to slot) is stored, a new chord takes the first free slot, a removed chord frees its slot and no later chord shifts. The first run seeds the map from the keymap order the slots had before, so no chord moves. A chord past the last free slot is refused at save and skipped with a warning at publish. The map is read and written inside the publish, in the change queue, and a failed change puts it back with the edit layers. The content script also catches these chords. If it cancels a chord, Firefox does not fire the shortcut as well, which the key test showed (see [firefox-behavior.md](../firefox-behavior.md), "Phase 1 measurements").

### Key flow and mode reports in the content script

Behavior of the key, mode and badge files in `src/content`, moved here from its README.

- `key_flow.ts`: decides per key token whether the page keeps the key (insert mode Escape in a field passes with the `escape_to_page` site setting, see `docs/design/config.md`), hands tokens to the sink of the current mode (with the key's physical Latin letter when `layout_fallback` is on), runs `browser` chords, holds plain keys until the keymap is read, a bundle has loaded or the command line has handed back the keys its frame got after the line ended, or a leaf of captured-key steps (`m`, `'`, backtick) or a leaf with a jump step (`gg`, `G`, `n`: the router records the place they leave) has run, outside fields (`holds_keys_after` in `run_leaf.ts`). A held key that the keymap then leaves unbound goes back to the page as a synthetic keydown on its original element (`replay_key.ts`), so page scripts see it. Its default action (scroll, Tab focus) is lost. Keys the command line hands back are not replayed to the page. The router checks the captured key, so the keys behind it would run first. A leaf of captured-key steps that mixes in a step that waits on the user does not hold. A leaf with a jump step holds whatever its other steps: hint mode skips the holds, so a pick there gets its keys, but keys typed before hint mode starts wait until the leaf ends. `page_hidden_` drops the captured-key hold and replays nothing. A macro replay holds keys the same way for its whole run (`replay_hold` in `main.ts`), and `drop_held_` empties the held keys when the replay fails or Escape stops it. In hint mode a new key skips the captured-key holds (`is_loading_(true)` in `bundle_host.ts`), so a pick inside a macro gets its labels, while the held keys still wait for the end. Held keys replay in order, the handed-back keys first. During a load it holds only the keys that can bind (`binds_after_` in the matcher) and gives every other key to the page at once, because a replayed key loses its default action (scroll, Tab focus). While a bundle that registers a sink loads, or a sink takes the current mode, every plain key waits, since the sink may take it. It also keeps some unbound keys from the page outside fields (`cancels_unbound_key`): `/` and `'` in the modes that do not give keys to the page or own them, so Firefox's Quick Find never starts, and every plain key but Tab, the function keys, Escape and the page scroll keys in the caret modes (`is_caret_mode`). Pure.
- `replay_key.ts`: the synthetic keydown (and keyup) that hands a replayed key to its original element, and the `isTrusted` guards of the keypress and keyup listeners. Pure.
- `cancelled_keys.ts`: the keys whose keydown was cancelled, so their keypress and keyup are cancelled too. It also cancels a keyup whose keydown this frame never saw, so a page never acts on half a press that began in another frame, except in ignore mode and while DesertFox is off, where the page gets that keyup. Pure.
- `site_mode.ts`: the site mode in force, plain state. `main.ts` swaps the matcher tree to normal plus the mode's keys (`install_tree`) when it changes, and ends it on a keymap update, a mousedown, a mode change and a key the keymap does not cancel. A mode with `sticky = true` survives a mousedown and a key the page keeps. `mode.site` and `mode.escape` set it.
- `site_rule.ts`: `all_off_step`, what an install does to the mode when the page's site rule changes. An unusable keymap never changes the mode.
- `mode_state.ts`, `page_mode.ts`: the modes and the pass-next flag. `page_mode` is the one shared instance. `fullscreen_step` is the pure rule that starts and ends the media mode with a fullscreen change, and hint and command line mode remember the mode they began in, so Escape and the end of a pick return to it.
- `mode_report.ts`: each frame reports its mode to the background on every change, at start, when its window gains focus and when its page is shown. Each report says whether the frame's own document holds the keyboard focus (`holds_own_focus`). The background answers the top frame with the mode and the id of the child frame that holds the focus (`frame_mode`), and the top frame's badge shows that mode, and that frame's count of visual item mode, in place of its own. A top frame in ignore mode gets none and shows IGNORE, so a field in a frame does not hide ignore mode.
- `badge_state.ts`, `mode_indicator.ts`, `shared/ui/mode_label.ts`: `badge_state` hands the `ui` bundle the mode, the pass-next flag, the setting, the recording name and the site mode label (only in normal mode, and it shows under `mode_indicator = not_normal` too), or nothing where no badge shows (hint and command line modes and a quiet setting, unless a macro records), so those cases load no bundle. `shared/ui/mode_label.ts` words the text (pure, with `recording @a` added while a macro records). `mode_indicator.ts` draws the badge, top frame only. It shows the mode of the frame that holds the focus (see `mode_report.ts`). A child frame's pass-next flag does not show. It follows the `mode_indicator` setting and sits 8 px above the bottom edge. Its colors are the theme tokens `--desertfox-mode-<mode>` and `--desertfox-bg-core`, picked by a `data-mode` attribute, so the light variant follows the theme sheet that `surface.ts` adds.
- `run_leaf.ts`: runs a matched leaf in the content script or sends it to the router. `holds_keys_after` says whether the keys behind it wait.

### Background files for keys and modes

Behavior of the `src/background` files for this area, moved here from `src/background/README.md`.

- `tab_item.ts`: the item mode of a tab, in `storage.session`: the frames that reported it. The first report of item starts it in every frame of the tab (a `MediaStep` with `item` set). A frame of the hold that reports a mode other than item, visual item, hint or command line ends it for every frame, and so does a new page load. An address change the page makes keeps it. `join` lets a frame that starts late into the hold through the reply to its first keymap read, and a child frame of the hold whose new document commits (`committed`, from `webNavigation.onCommitted`) is marked `rejoined`, so the normal report of its new document does not end the hold. `item_start_for` in `page_keymap.ts` answers whether a finished load starts the mode (the `item_navigator` setting for the address, off where a row binds or passes j or k) and with which row selectors, and `ask_item_start` sends the start to the top document that completed at that address, by its `documentId`. Its steps go out through the `tab_steps.ts` queue it shares with the media mode.
- `toolbar.ts`: the on/off switch. `create_toolbar` writes the flag (`DISABLED_STORAGE_KEY`), republishes, sets the icon and title, then sends every tab to normal mode on off, and on on the content script enters ignore mode again from the stored tree, on a page that `site_rules` turns off. Changes run one at a time, so the popup and the `toggle_enabled` shortcut never race. While off, `publish` stores `OFF_KEYMAP` (no modes, badge off) instead of the compiled tree, and the keymap carries `off`, the one flag the page reads (a lone keyup then passes). The router refuses every run and `shortcut_allowed` refuses every slot while off. The toggle is not a slot: `main.ts` handles its command before the slot table. `answer_toolbar_request` serves the popup's three messages (extension pages only). The Disable on this site rules (`site_pattern`, `site_state`, `site_rows_after`) are in `shared/site/site_state.ts`, and `config_setting_writes.ts` (`change_site_rule_in_file`) writes the row into settings.toml.
- `tab_modes.ts`: the mode of each tab, in `storage.local`: the mode of the child frame whose document holds the focus, else the top frame's. Ignore mode in the top frame beats a focused child frame. Reports and navigations run one at a time, and a report that changes nothing writes nothing. The start of a load forgets the mode, and so does the new page taking over, but not an address change the page makes itself. It also holds the insert hold of `tab_insert.ts` and the ignore-mode gate for Firefox shortcuts.
- `keymap_source.ts`: the compiled keymap from `storage.local`, held in memory after the first read. Every background reader of it but `strip_patterns.ts` (one `get` for the keymap and the config status) goes through `stored_keymap`. `config_store.ts` calls `drop_keymap` right after it writes the keymap, so a change event that arrives late cannot leave the old map. Many frames asking at once share one read, and `storage.onChanged` drops the copy (a read in flight at that moment is read again, not stored). Its listener is added when the module loads, ahead of the other `onChanged` listeners, so they read the new map. A storage other than `browser.storage.local` reads straight through.
- `page_keymap.ts`: answers `read_keymap`. It reads the stored keymap (through `keymap_source.ts`), resolves the site table columns for the sender (`rule_addresses_of` over `sender_at`, which takes the request's `url` in place of the load address in `sender.url`; `site_columns_for`, `normal_tree_for`, in `shared/site/site_columns.ts`), trims the normal tree, grafts the page's `keymap.<mode>` binds onto the other mode trees (`keymap_mode_trees_for`, also read by `list_keys.ts`, and skipped on an all-off page) and replies with the `PageKeymap` as a JSON string. While a macro records it also swaps the record key for `macro.stop` and adds the register name. `site_value` gives a per-site setting's value, which beats the global one (`site_zoom.ts` uses it). `top_frame_address_of` gives the top frame's address for a tab-wide value asked by a frame. `frame_site_values_for` resolves the named settings that act inside one frame against the frame's own address: `blur_on_load`, `focus_on_load` and `escape_to_page` go into the reply as `site_values`, and `hint_selectors_reply` answers the hints bundle's `read_hint_selectors` with `hint_add` and `hint_remove`. It grafts the merged `bind` column onto the normal tree (`graft_binds`, in `shared/site/site_columns.ts`) before `pass` and `only` prune it, and `off` skips the graft. A guarded bind (`when_focus`, `when_present`) keeps the leaf it replaced at the end of its `otherwise` chain, after any further choices, so the key can fall through to it.

### Handlers files for content commands

Behavior of the `src/content/handlers` files, moved here from `src/content/handlers/README.md`.

The content-side code of each command that runs in the page. One file per command group, and each command is one `ContentHandler` object with a `run(args, repeat)` function. `repeat` is true when an auto-repeat keydown started the run and false for every other source. `run` returns nothing for done, throws for failed, or returns an `Outcome` or a promise of one. A command that hands control to the user (`hint.run`, `cmdline.open`, `find.open`) stays pending until the user finishes: a pick or Enter is done, and Escape, an unrelated key or a page change is cancelled. A failed command returns its message and does not toast it, so the caller shows it once.

- `types.ts`: the `ContentHandler` type.
- `scroll.ts`: the `scroll.*` commands. It exports `scroll_target` and `end_flight` for the bundle host (`scroll_box_`). The `scroll_selector` site setting picks the target first. The pick of the whole-page scan is kept per axis and dropped on `focusin`, `pointerdown`, a failed re-check or a 1 s pause between scroll keys.
- `page.ts`: `page.blur`. It holds `blur_focused_element` and remembers the last blurred field, which the bundles read through the host. It also holds `hand_focus_to_parent`, the hand-off of a hidden input frame (`src/content/hidden_frame.ts`).
- `mode.ts`: the mode commands.
- `stop.ts`: the stop command.
- `focus.ts`: a helper that has no handler object.

How a handler is found and called:

- `src/content/handler_map.ts` maps a command id such as `scroll.lines` to its handler. It is the only id-to-code link in the content bundle.
- `src/content/run_content.ts` looks the id up. An id with no handler but with a `bundle` on the invocation runs through the bundle host, which loads the bundle first. Any other id fails. It calls `run` once per args set that the count rule gives. A thrown error also becomes a failed outcome, which the caller shows as a toast.
- The args are already checked, with defaults filled in, by the background compiler.

The count rule is not on the handler. The command definition in `src/commands` holds it, and the background compiler puts it on each `LeafStep` as `count_rule`. The definitions import only a few constants from this folder.

To add a handler:

- Write the `ContentHandler` in the file of its group, or in a new file.
- Add it to `handler_map.ts` under the command id.
- Define the command in `src/commands`, with its count rule.
- To report a success, call `show_toast` from `src/content/ui_proxy.ts`. `src/content/page/copy.ts` takes it as a parameter. To report a failure, return it as an `Outcome`.

### Keys files for keys

Behavior of the `src/shared/keys` files, moved here from `src/shared/keys/README.md`.

Key notation, the prefix tree compiler and the matcher. Pure TypeScript, no browser APIs.

- `token.ts`: the normalized key token and `event_to_token`. The compiler and the content script both use it, so a keymap sequence and a keydown meet in one form. `physical_token` gives the Latin letter on the physical key of a plain letter of another script, for the `layout_fallback` setting.
- `notation.ts`: parses a sequence such as `gx$` or `<AC-Escape>` into tokens.
- `compiler.ts`: builds the `CompiledKeymap`, gives every leaf its which-key label (the binding `label`, else the command label with the phrases of the args the binding sets, and the binding `intent` when it has one), expands `search_keys`, `container_keys` and `site_keys` (the `s/<letter>` and `S/<letter>` leaves, which carry their candidate engines in `site_search`), expands `modifiers` into variant keys that the registry validator accepts (the modifier label names the group), puts `group_names` on the branches, and warns about shadowed or unknown entries.
- `mode_parents.ts`: `resolve_mode_parents` gives each child mode its parent's keys, as "Mode parents" says, and `shown_steps` drops the leave step for a key listing. The background and the help page import it. The content script does not.
- `prune_tree.ts`: copies a mode's tree with the `pass` or `only` sequences of a `site_rules` row applied, and `frees_of` names the keys a rule hands to the page. `src/background/page_keymap.ts` and `src/shared/site/site_columns.ts` import it. The content script does not.
- `matcher.ts`: walks the tree with count prefixes and the `"<reg>` register prefix. The register keys (`"` then a name, checked with `REGISTER_KEY`) sit beside the count and not in `typed`, so a count may stand on either side of them. At a match the register fills the `register` arg of each step the compiler flagged (`LeafStep.register`). A user binding of `"` wins over the prefix. A branch with an `ANY_KEY` child takes one printable key and fills the leaf's `key` param (the capture). A character find's branch also holds a `LIVE_KEY` child, the repeat leaf, which the key flow feeds in place of the key while a find is live. `binds_after_` reads ahead without moving the walk, so key_flow can tell which keys typed during a bundle load can bind. It ships in the content script, so it stays small.
- `firefox_shortcut.ts`: turns a `browser` chord into a `commands.update` shortcut string.
- `default_keymap.ts`: the shipped keys, the source of `docs/keymap.md` (`just docs-gen`). Keys that need the user's engines or containers are left to the config. Data only, types-only imports.
- `index.ts`: re-exports `token`, `notation`, `compiler`, `matcher` and `firefox_shortcut`. `prune_tree.ts` and `default_keymap.ts` are imported directly.
