# Tabs

Area: tab sessions, groups, split view, live model, unload and reload.
READMEs: `src/background/README.md`.
Source: `src/background`.

### Tab sessions

`ts` saves the tabs of the current window under a name and `tS` opens a saved session from a list. `ts` opens the line with `session.save ` typed, and `tS` with `session.open `. The command line also has `session.delete <name>` and `session.rename <name> --to=<new>`, with no keys. The flag comes before the name because the name is the `main` param and runs to the end of the line.

- The sessions live in `storage.local` under `desertfox_sessions` as `{ version: 1, sessions: { [name]: { saved_at, tabs } } }`. A tab keeps its address, title, pinned and active flags and, when it has one, its container id and name. The array order is the tab bar order. Only `src/background/session_store.ts` reads and writes the key, and its writes run one after another, so two saves at once both land. A stored version other than 1 is refused and never overwritten, and an entry this version cannot read is kept as it is when another session changes. A write that fails, for example on quota, refuses with the cause and leaves the stored sessions as they were. Measured: 100 sessions of 50 tabs are about 1.3 MB, and `storage.local` took 400 such sessions (5 MB) without `unlimitedStorage`.
- A name is trimmed with its inner spaces joined to one, must not be empty, may not start with `-` or `@` when saved or renamed to (the line would read it as a flag or a slot, and the param schema refuses it), and is unique ignoring case. Saving an existing name updates it, keeps its display case and says so in the toast with both tab counts. Rename refuses a name another session has.
- `session.open` takes `into`: `window` (default) opens a new window, `tab` adds the tabs to the end of the current window, all discarded, and the current tab stays active. There is no replace, because it would close the user's tabs. In a new window the tabs are created in order, and every tab but the active one is created discarded, so it shows its saved title and loads on first visit. Firefox refuses `tabs.create` with `discarded` and `pinned` together, so a pinned background tab is created discarded and pinned right after. A container is found by its saved id, then by its name, else the tab opens in the default container and the toast counts it. An address off the open allow-list (see [Routing](../design.md#routing)) or one Firefox refuses is skipped and counted in the toast. When the saved active tab is one of those, the first tab that opened loads instead. The toast of a new window shows on a tab of that window. When the window closes while the tabs open, the restore stops and says so. A new window opens on `about:blank`, and that tab is removed when the session's tabs are in. The restore reads the session once at its start, so a save of the same name while it runs changes the store and not that restore.
- The settings page exports the sessions as `desertfox-sessions.json` (the stored shape, readable sessions only) and imports one. An import adds sessions and removes none. A name that is taken, ignoring case and counting entries this version cannot read, keeps both: the import arrives as `name (2)`, then `name (3)`, and a name that already ends in a suffix gets another. An imported name goes through the same rule as save (the shared `NEW_NAME_PATTERN`, with its spaces joined), so an entry named `-x` or `@x` is skipped and listed in the answer, as is an entry that is no session. A file that is not JSON or not version 1 is refused whole. A sessions file is data and not code, so no consent screen asks first. Only extension pages may send the two messages.
- Private windows refuse every session command and the list is empty there.
- The `sessions` completion source (`values: { from: "sessions" }`, `kind: "sessions"`) lists the names newest first with the tab count and age in the description column, which the background writes. It ships the whole list once per line, like the bookmarks.
- The `folders` completion source (`values: { from: "folders" }`, `kind: "folders"`) lists every bookmark folder as a path from the root, such as `Bookmarks Toolbar / Work`, with the count of bookmarks directly inside in the description column. The background builds it from `getTree` with a walk that keeps the parent chain. Folder titles are display text that Firefox localizes, so a folder is named by its path and a command re-reads the tree and looks the path up: an exact path wins, other text is a fuzzy match, and a path that two folders share is refused, as an equal tie is for `bookmark`. `bookmark.add --folder=` files a new bookmark there, and with no folder Firefox's default applies. A page that already has a bookmark refuses with a folder, because `bookmark.move` is the way to change its folder. `bookmark.move` takes the folder as its main param and `--bookmark=` for another bookmark (empty means the current page), and moves every unmanaged bookmark at that address. `bookmark.open_folder` opens the folder's own bookmarks, not those of its subfolders, in a tab (the first one active), in background tabs or in a new window, never `here`. It opens at most 25 and one toast says when the cap cut the list or an address was skipped. It skips the addresses off the open allow-list (see [Routing](../design.md#routing)), such as `place:` queries, `javascript:` bookmarklets and `about:` pages other than `about:blank`. An address that passes that filter and still fails is skipped and counted too, and the rest open. In a tab, the tabs open in the background in folder order and then the first one becomes active, so the strip keeps the folder order. When every address fails the command refuses.

### Tab range

`gv` in normal mode starts tab range mode (`tab_visual`, badge `TAB VISUAL`). Firefox's own tab selection (`tabs.highlight`) is the display, so nothing is drawn by the extension. Firefox keeps the active tab in the selection, so the anchor of the range is always the active tab and only the other end, the cursor, moves. A range that leaves the active tab out cannot exist, which is why there is no key to swap the ends.

- `tab.visual` (`src/commands/tab_visual.ts`, logic in `src/background/tab_visual.ts`) takes `start`, `down`, `up`, `first`, `last` and `end`. `j`, `k`, `gg` and `G` move the cursor through the strip in tab order (pinned tabs first, each group contiguous), skip hidden tabs and tabs of a collapsed group (the tabs Firefox's own range skips) and stop at the ends. Each move sets the selection from the anchor to the cursor with the active tab listed first, which keeps Firefox from switching tabs.
- The record `{ anchor, cursor }` of each window sits in `storage.session` (`TAB_VISUAL_STORAGE_PREFIX`). It holds the cursor because the selection alone cannot say which end is the cursor after a Ctrl-click. A window that closes drops its record.
- `tab.act` (`src/commands/tab_act.ts`) acts on the tabs Firefox shows as selected, so it also works on a selection made with the mouse. With one tab selected it acts on that tab. Actions: `close` (at most 10 tabs unless `force` is on, which `D` sets, and the focus moves to the nearest visible tab outside the range first; a range that holds every tab of the window is refused), `pin` and `mute` (every tab on when any is off, else off), `reload`, `copy` (`yy` Markdown, `yu` plain, `yo` Org, `yt` titles, the `copy.tabs` formats), `group` (`ga`, one new untitled group, `group_tabs`), `attach` (the window used last, as a bare `tab.attach`) and `bookmark` (each web tab without a bookmark, in the default folder).
- The key rows are in `TAB_VISUAL_KEYS` in `src/shared/keys/default_keymap.ts`. An action key runs `tab.act` and then `mode.set normal`, which ends the range. `d` and `D` leave out the second step, because closing the range hides the page and that ends the mode.
- The mode ends with the page. The `tab_visual` bundle holds a sink, and a tab switch or a navigation of the active tab hides the page, which calls the sink's `exit`. It sends `tab.visual end`, which clears the selection down to the current active tab when a record exists. Escape does the same. Any normal key that the mode does not bind ends the range first and then runs (mode parent with a leave step), as in visual item mode.
- Keys with no binding in the mode go to the page. A focused field keeps the range.

### Tab groups

Firefox native tab groups (`tabs.group`, 138, and `tabGroups`, 139, under `strict_min_version` 153). The `tg` keys and `tabgroup.*` commands (`src/commands/tab_group.ts`) act on the line's own tab and its group: `tabgroup.add [group]` (`tga` prompts, `tgA` starts an untitled group), `tabgroup.remove` (`tgd`), `tabgroup.close` (`tgD`, closes the group and all its tabs after moving focus to the nearest tab outside it, and refuses when the group holds every tab in the window), `tabgroup.name <title>` (`tgn`), `tabgroup.collapse` (`tgc`), `tabgroup.expand` (`tge`), `tabgroup.toggle` (`tgt`), `tabgroup.color <color>` (`tgl`, the nine Firefox colors as an enum) and `tabgroup.next` / `tabgroup.prev` (`tgj`, `tgk`, a count moves over that many groups). Marked tabs reach no command today, so there is no many-tab form.

- `tab_actions.ts` holds `group_tabs`, `ungroup_tabs` and `set_group` over an injected `GroupDeps`. A pinned tab and a list that spans windows are refused with a `RuntimeRefusal`, as is a target group of another window, because a group stays in one window.
- `next` and `prev` focus the first tab of the neighbor group in the window, ordered by each group's first tab, and wrap at the ends. From a tab in no group, `next` lands on the first group after it and `prev` on the last group before it. A collapsed target group is expanded first, so focus never lands in a hidden group. Skipping it would make a collapsed group unreachable by key.
- `add` names a group of the tab's window. A name that no group has starts a group with that title. A group is named by its title, and a title that is empty or shared by several groups of the window gets the id as a suffix (`Play #12`, `#12`), which is also how the completion lists it (`src/shared/group_name.ts`). A bare title that several groups share is refused and the refusal names the id form.
- The `groups` completion source (`values: { from: "groups" }`) lists the groups of the line's window from the live tab model, so it needs no fetch. A group is not private or normal by itself: it takes the privacy of its window's tabs.
- The manifest needs the `tabGroups` permission. Measured in Firefox 160: without it `browser.tabGroups` is absent (see `docs/firefox-behavior.md`).
- The model keeps `group_id` per tab (-1 for none) and a groups table. A patch carries `groups` and `groups_removed` only when some changed. A group event patches the table. A removed group also clears the `group_id` of its tabs in the same patch. A group move reads the tabs again, because its tabs change index and Firefox may report it as tab moves or not.

### Split view

Firefox split view shows two tabs side by side in one window. The extension API (`tabs.Tab.splitViewId`, Firefox 149) reads a split and moves within it, and creating or ending one is Firefox's alone (see `docs/firefox-behavior.md`, "Split view").

- `gp` (`tab.split_other`) moves focus to the other tab of the split the tab is in, and `gP` (`tab.split_swap`) swaps the two. Both refuse with "This tab is not in a split view" otherwise. The handlers sit in `src/background/tab_split.ts` over an injected `TabSplitDeps`. A swap is a `tabs.move` of the partner onto the tab's place, because there is no swap call.
- The `E` group (named "Pane") holds the split commands too: `Ep` is `tab.split_other` and `Es` is `tab.split_swap`, the same commands as `gp` and `gP`. `Ep` and `Es` need no browser module. The rest of the group changes the window, so it needs the browser module (see [host.md](host.md)): `En` splits with a new tab, `EN` with the next tab (`pane.split`, `pane.split --next`), `Eu` unsplits (`pane.unsplit`), `Ex` closes both tabs (`pane.close_both`), `E<` and `E>` narrow or widen the left pane by 5 percent per step with the count as the number of steps (`pane.resize`), and `Ek`, `ES` and `ED` move the focus to the page, the sidebar and DevTools (`pane.focus`). `E=` gives the two panes equal widths (`pane.equalize`). `Eh` and `El` move the focus left and right (`pane.focus_side`). `E<Space>` holds the group open, so `E<Space><<<` narrows the left pane three steps. Each sends one request through `src/background/browser_module_call.ts`. Without the module, or with the setting off, each refuses with "Needs the browser module". When the module cannot do the call, its own refusal text shows.
- The module side is `browser_module/desertfox-panes.js`. It acts only in the browser window that has the focus, on its selected tab. `En` runs Firefox's own new split flow: an open tabs picker (`about:opentabs`) beside the tab, selected. `EN` splits with the next visible tab. Both refuse a tab that is already split, pinned or hidden, and `EN` refuses when there is no next tab or the next tab is already split. Unsplit, close both, resize and focus of the other pane refuse with "This tab is not in a split view" otherwise. A resize step is 5 percent of the panel area, kept within the panel's minimum width on either side. The focus of the page needs no split. The sidebar focus goes to whatever the sidebar shows: the open panel, else the vertical tab strip, else the launcher buttons. A sidebar that shows nothing opens on the panel it showed last, or Bookmarks when none was shown, then takes the focus. The DevTools focus needs the tab's toolbox open and docked in the window, and refuses a toolbox in its own window. A private window takes the calls only when DesertFox may run in private windows. When a Firefox internal is missing, the call refuses with "Not supported in this Firefox version". The internals each call uses are in `docs/firefox-behavior.md`, "The pane calls in the browser module".
- `Eh` and `El` take the nearest thing on that side. The other pane of a split comes first, by where the panes show. Then comes DevTools docked on that side, then the sidebar on that side while it shows something. A closed sidebar refuses with "The sidebar is closed" and stays closed. So from the right pane, the sidebar on the left is two moves away. With nothing on that side the call refuses. The sidebar's side is its start or end place from `sidebar.position_start`, read against the window's direction. `E=` sets the first panel to half of the two panels together, written as a resize writes it.
- The tab model keeps `split_id` per tab (-1 for none). A tab list row of a split tab shows a split flag next to the pinned and unloaded flags.
- `tab.next`, `tab.prev` and `tab.goto` count the two tabs of a pair as two stops, so `gp` is the jump to the other pane.
- `tab.close` closes one tab, and the other tab stays and takes the focus. `tab.move` moves the pair as one unit: the move acts on the pair's first tab, the place is where the pair starts, and one step right moves the tab after the pair over it, because a move onto the partner's place would swap. Pinning one tab of a pair ends the split. A tab group command on one tab acts on both.
- A session restore loses the split. The saved tabs carry no split id, and the extension cannot create a split.

### Live tab model

- The background keeps one map of tab rows (`src/background/tab_model.ts`), built from one `tabs.query` and kept current from tab events. It stores nothing, because one query rebuilds it. Each row carries the tab's site key (`src/shared/site_key.ts`) and a favicon only when the list rule allows it. Changes batch on a 30 ms flush and go to clients on the port `desertfox_tab_model` as a snapshot, then patches (`TabRow` and the messages are in `src/shared/messages/ports.ts`).
- A patch has `removed` ids, then `upserts`, and the upserts include every row whose index shifted. `rev` counts per port, because a port sees only tabs of its own privacy. A client that sees a gap in `rev` sends `resync` and gets a new snapshot. A `resync` and each new port first read tabs, windows and containers from Firefox again and send any difference from the model as a patch, so a stale or missed event does not last until restart. An event during those reads makes it read again, up to three times.
- After that the model keeps the rows the events built until the next `resync` or new port. A row also carries its window number (the place in `windows.getAll`, as `tab.attach` counts), whether it is the window's previous tab (the `#` tab, seeded from storage at load), and its container's name, color and icon. Only an extension page may connect. `cmdline.html` is web-accessible, so a web page can frame it, and such a port must also be the frame that redeemed its tab's command line ticket.
- Other extension pages cannot be framed and skip that check. A page with a sender tab gets that tab's privacy. A page with none (a sidebar) connects as `desertfox_tab_model:normal` or `:private` (the names are in `src/shared/tab_model_port.ts`), and a port that states nothing gets no rows. A tab moving between windows reads as removed until it attaches. The command line `tab` list reads the model: its page opens the port on the first tab read, after it redeemed its ticket, and closes it with the line.
- Row marks change only when a patch arrives.

### Tab unload

- `tab.unload` and `tab.load` free and restore a tab's memory (default keys `tuu`, `tuh` and `tul` in the `tu` group, `tUh` and `tUl` in the `tU` group). They take a subject like `tab`, a `side` and a `count`. Unloading the current tab switches to the alternate tab first, else the next loaded tab, else the previous one. Audible tabs and the active tab of another window are refused, and a side or a count skips pinned tabs.
- The site of a tab is its site key (`src/shared/site_key.ts`): the host in lower case, with one trailing dot and one leading `www.` dropped and the port ignored, so `www.github.com` is `github.com` and `docs.github.com` is another site, because no public suffix list is used. An IP address and `localhost` are their own keys.
- All `file:` pages are one site, all `about:` pages are one site (`about:reader` and `view-source:` take the key of the page they wrap), each extension is one site, and `blob:`, `data:`, `javascript:` and unparsable addresses are one `other:` site. `--side=site` (short `S`, on `tab.close`, `tab.unload` and `tab.load`, with no default key) acts on the tab and every unpinned tab of the same site in the line's window. `tab.close` first moves focus to the nearest tab outside the site.
- A count is invalid with `site` on `tab.unload` and `tab.load`. A count prefix with `tab.close --side=site` is a known gap (it repeats the close), tracked in #187. `tab.load` reloads in place and keeps focus. Both report one line, such as "unloaded 3 tabs, skipped 1 (audible)". In the list, `<C-Space>` (`list.select --action=toggle`) marks or unmarks the highlighted tab row and moves down. The marks are tab ids kept in the line, so filtering keeps them and the actions include hidden marked tabs.
- A tab that closes drops out, `<Esc>` clears the marks before it does anything else, and they end with the line. `list.act` runs on the marked tabs, or on the highlighted row when none is marked: `<A-x>` closes (the highlight then goes to the first row below the closed rows, else above), `<A-m>` mutes and `<A-p>` pins (any off turns all on, else all off), and `<A-u>` unloads the loaded tabs, or loads all when none is loaded.
- The ids are fixed at the key press and go to the background in a `tab_rows_action` message that needs the line's ticket, skips ids that no longer name a tab and refuses ids of the other privacy. The list stays open and the rows show the change, with a name dimmed while unloaded. The line's own tab cannot unload this way, because the line lives in it. `<A-c>` (`list.act --action=reopen`) swaps the line to a `container:` prompt over the same line, ranking the containers by name with `default` as one entry.
- Enter reopens the marked tabs, or the tab that was highlighted when none is marked, in the previewed container, or in the one whose name was typed in full. `<Esc>` returns to the tab list with the marks, filter and highlight kept, and the `<Esc>` order above holds after that. The ids are read when Enter is pressed, so a tab that closed meanwhile drops out. The message carries the container's store id, because names can repeat.
- The background refuses a private line, an id of the other privacy and a store id it does not know. It leaves out the line's own tab and the tabs already in that container, skips a tab that fails to reopen while the rest go on, and opens no new tab as the active one, because hiding the line's tab ends the line. The note names what moved and what stayed, such as "reopened 2, 1 already there, line tab left out". A private line has no containers, so the prompt refuses there.

### Reload and clear

- `rc` (`page.reload --site`) clears one site and reloads. `rC` opens the line with `page.reload --all`, and Enter runs it, so no key press clears every site. `site` clears the cookies of the page's exact host in the tab's container, plus the parent-domain cookies the page sends (`cookies.getAll` for the page URL), then the whole HTTP cache, then asks the page to clear its own localStorage, sessionStorage, IndexedDB, Cache Storage and service workers through a fixed `tabs.executeScript` string (not a content-script message, because the content script is near its size limit). Firefox ignores `browsingData` `hostnames` for the cache and localStorage (see [firefox-behavior.md](../firefox-behavior.md), "browsingData hostnames"), which is why the cache goes whole and the page clears itself. A database the page holds open blocks its own delete and `browsingData` `indexedDB` ignores `hostnames` too, so that delete stays pending until the reload closes the connection, and the notice names IndexedDB. `all` clears every type for every site and container with one `browsingData` call. The cache call never carries a `cookieStoreId`, which Firefox rejects for it. The clear finishes before the reload (`bypassCache`), and a failed cookie or cache clear stops the reload. A page the extension cannot script (addons.mozilla.org, an error page) or a step that stalls past 3 s still reloads, and a notice names what stayed. A `file:` or `about:` page refuses a site clear before anything is cleared. `browsingData` is an optional permission, and `cookies` stays required because the container option of `tabs.create`, `windows.create` and `downloads.download` needs it. Without `browsingData`, `rc` and `rC` refuse before they clear anything and name `:permissions.grant browsingData`. That opens a Help panel, and its Allow button asks for the permission (see [Permissions](../firefox-behavior.md#permissions-optional-permissions)). The keys work at once after the grant, and a plain reload never needs them.

### Background files for tabs

Behavior of the `src/background` files for this area, moved here from `src/background/README.md`.

- `last_used_tab.ts`: the current and previous tab across every window, one pair for normal windows and one for private ones, in `storage.session`. It follows `tabs.onActivated` in the focused window and `windows.onFocusChanged`, and drops closed tabs. `tab.alternate_any_window` (`gL`, `tL`) reads it.
- `session_store.ts`: the saved tab sessions in `storage.local` (`desertfox_sessions`): a name store with `save`, `get`, `rename`, `remove` and `list`, serialized so concurrent changes do not lose one, plus `plan_restore`, which marks the one tab that loads and finds each container by id then name. `export_json` and `import_json` serve the settings page (a taken name keeps both, the import gets a ` (2)` suffix, names pass `NEW_NAME_PATTERN`, which `session.save` also uses). `commands/session.ts` does the browser calls.
- `store_turns.ts`: what the private-data stores share, and the previous-tab and window-focus stores use the queue. `create_write_queue` runs their writes one at a time. `wire_private_cleanup` puts one `windows.onRemoved` listener (and one run at start) over every store, dropping private data when no private window is open.
- `tab_discard.ts`: the one place that calls `tabs.discard`. `set_unloaded(deps, ids, unloaded, { leave_active })` skips audible tabs, the active tab of any window (except `leave_active`, which switches to the alternate, else the next, else the previous loaded tab first) and tabs already in the target state. It re-reads `discarded` after each discard, because Firefox does nothing for the active tab or a privileged page and never rejects. Load uses `tabs.reload`, which keeps scroll and form data and does not activate the tab. Returns what changed and a reason for each skip. `tab.unload`, `tab.load` and the list row key all go through it.
- `tab_actions.ts`: the one place that mutes, pins, moves and reopens tabs in a container, each over a list of ids. `tab.pin`, `tab.mute`, `tab.move` and `tab.reopen_in_container` call it with one id. Reopen handles one tab at a time in tab bar order, opening the new tab where the old one was and then closing the old one, so a failed open leaves no duplicate. It leaves a tab with no address open. `reopen_tabs_in_container` is the tab list's version: each tab settles alone and no new tab becomes active, so the line stays open. `group_tabs`, `ungroup_tabs` and `set_group` put tabs in native tab groups through `GroupDeps`, and refuse a pinned tab or tabs of several windows.
- `tab_model.ts`: the live tab model (rows also carry `group_id` and `split_id`, and a groups table follows the `tabGroups` events). One map of tab rows (with the `site_key` of each URL) built from one `tabs.query` and kept current from tab events, nothing stored. Changes batch on a 30 ms flush and go out on the port `desertfox_tab_model` as a snapshot, then patches (`rev` counts per port, `resync` asks for a new snapshot). Each row carries its favicon only when it is a `data:image/` URL of at most 32768 characters (`listed_favicon`, else empty), so the snapshot is large for many tabs with big icons. Rows also carry the window number (as `numbered_windows` counts), the previous tab (seeded from `previous_tab.ts`, then followed from `onActivated`) and the container name, color and icon, re-read on window and container events. A port sees only tabs of its own privacy (the sender tab's, else the `:normal` or `:private` suffix of the port name from `src/shared/tab_model_port.ts`, else no rows) and only an extension page may connect. A web-accessible page (`cmdline.html`) must also be the opener frame of its tab (`is_opener`), because a web page can frame it. Other extension pages cannot be framed and skip the check. A detach reads as a removal until the attach. Events during the startup query force a second query. A `resync` and each new port re-read tabs, windows and containers and patch the difference, retrying when an event arrives meanwhile.
