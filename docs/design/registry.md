## Registry

The registry lives in the background page. A command is plain data plus a handler:

```ts
define("tab.close", {
  label: "Close tab",
  intent: "Close the current tab and focus the next one, or close the tabs around it.",
  params: [
    { name: "side", type: "enum", values: ["none", "all_before", "all_after", "focus_previous"],
      default: "none", short: { all_before: "B", all_after: "A", focus_previous: "P" },
      value_labels: { focus_previous: "and focus previous" } },
  ],
  runs_in: "background",
  count: "repeat",
  run: async (ctx, { side }) => { /* side: "none" | "all_before" | "all_after" | "focus_previous" */ },
});

define("open.search", {
  label: "Search",
  intent: "Search with a keyword engine from the search engine list.",
  name: "search",
  params: [
    { name: "engine", type: "enum", values: from_engines },
    { name: "query", type: "string", main: true, default: { from: "selection" } },
    { name: "where", type: "enum", values: WHERE, default: "here",
      short: { tab: "t", background: "b", window: "w" } },
    { name: "container", type: "string", values: from_containers, short: "c",
      when: { where: ["tab", "background", "window"] } },
  ],
  runs_in: "background",
  run: async (ctx, { engine, query, where, container }) => { /* where is a union of WHERE, container is string | undefined */ },
});
```

The handler of a background command gets its args typed from `params` (`ArgsOf` in `src/shared/command.ts`). A static `enum`, or a `strict` `string` with a literal `values` list, is the union of its values. Other `string` and `key` params are `string`, `int` and `float` are `number`, and a param with `when` is an optional key. A content command has no handler in the definition, so its handler in the page reads `CheckedArgs`.

The fields follow the Oasis action library (`home/hypr/.config/hypr/lib/act/init.lua`) so the two lists have one shape:

- `id`: `group.name`, lowercase with underscores. Same pattern as Oasis actions.
- `name`: the command line name, set by hand. It is optional, and it holds no `.`. The full id always works on the command line, and it is the name of most commands: you type `tab.close`, `window.new`, `tab.pin`. Only two kinds of command get a name. The one-word commands are `open`, `search`, `paste`, `copy`, `hint`, `heading`, `find` and `github`. The family words are `tab` (switch), `bookmark` (open), `history` (open), `zoom` (set), `scroll` (lines), `mode` (set) and `help` (open), one per group, for the main action. Names are never derived from the id, because derived names collide (`tab.close` and `window.close`).
- `aliases`: more command line names. The defaults ship none.
- `label`: a short title in sentence case ("Close tab"). Which-key, the palette and completion show it. A key shows this label plus a phrase for each arg its binding sets, see [Which-key](interfaces_pages.md#which-key).
- `intent`: plain text on one line. Its first sentence is the summary that the completion list shows: it starts with a verb, takes at most 60 characters and names no other command. Later sentences are detail. Help, the status page and which-key hover show all of it. The registry rejects an empty or multi-line one, and a test holds every built-in command to the summary rule.
- `params`: typed and named. The types are `int`, `float`, `string`, `bool` and `enum`. `key` is one key press (one character, so `a`, `Z`, `'`). It takes `pattern` for the set a command accepts and no `optional`, `values` or `strict`. A command has at most one `key` param. On the command line a required `key` param is a bare word (`markadd a`), and one with a default is a flag (`--slot=a`). A param with no `default` that applies, no `optional` and no `when` is required. The order is for display only.
- Value rules, plain data that travels in `commands.json`: `min` (the smallest value of an `int`), `pattern` (the source of a regular expression that a `string` must match), `format` (`"url"`: a `string` must be an absolute address, as `URL.canParse` reads it), `strict` (a `string` with a static `values` list accepts only those values, where `values` alone is completion only) and `optional` (a `string` or `enum` may be left out or empty and then reads as `""`, in place of `default: ""`) and `value_of` (a `string` holds the value of the setting named by a sibling `strict` param, and `check_args` checks it with that setting's entry in `SETTING_SPECS`, an empty value passing). `strict` compares exactly, like an enum value. `check_args` applies them. The registry checks at define time that each sits on a param type that can carry it.
- `value_labels`: on an `enum` param with a fixed value list, a short phrase for each value ("and focus previous"). Which-key adds the phrase to the label when a binding sets that value, and completion shows it beside the value. Every key must be one of `values`, and a value that is the default in every context has no phrase. A value with no phrase reads as the raw value with spaces for underscores. The registry checks this at define time.
- `description`: one sentence for a flag, under the same rule as the first sentence of an `intent`. A string on a bool or valued param. A map from value to sentence on an enum with a fixed value list, with no entry for a value that is the default in every context. Completion shows it beside the flag. Every flag of a built-in command has one, and a test checks it. The registry checks the sentence at define time when one is present.
- `main`: the one `string` param that config and the command line take as the subject, for example the URL of `open` or the query of `search`. At most one per command.
- `short`: the one-letter flag of a param. A string for a bool or a valued param (`short: "r"` gives `-r`, `short: "c"` on a string gives `-c=Work`). A map from value to letter for an enum with a fixed value list (`{ tab: "t" }` gives `-t`). Never on `main`, `rest` or an enum with a runtime list. `-t -b -w` mean where (tab, background, window) and `-c` means container on every command that has those params. A default value gets no letter, because the printer leaves it out.
- `rest`: marks a `string` param as text with spaces. The grammar already lets the `main` value run to the end of the line.
- `when`: the param is valid only if one other param has one of the listed values. For example, `container` needs `where` to open a new tab or window, because Firefox cannot change the container of an open tab. This is the only kind of condition, apart from the default list, `value_when` and `pattern_arms` below. A command that needs more is split into two commands. A new window with no `container` keeps the container and private state of the tab that opened it, and a private tab refuses a named container.
- Default list: `default: [{ value, when }, ..., plain]`, an ordered list of arms with an optional plain value last. Each arm uses the `when` syntax, and unlike a param's own `when` it may name several params, which must all have a listed value (AND). The first arm that holds wins, else the plain value applies, else the param has no default and is required. This holds for a param with `when` too: when its `when` holds and no arm does, the param is required, so `media seek percent` needs its count while `media seek up` defaults to one. `open.url` sets `default: [{ value: "", when: { where: ["tab", "window", "background"] } }]` on `url`, so `open` with no URL is an error for `here` and opens the new tab page elsewhere. A hint `action` can default to `play_pause` for the `media` filter and to `here` otherwise. An arm may name a param that has a default list itself, the define check refuses a cycle and names its path (`action -> filter -> action`), and an arm that names several params makes the param depend on each of them. The list travels in `commands.json`. Help prints the plain value first, then each arm: `here; play_pause when filter is media`, and `background when filter is links and rapid is true` for an arm with two params. A value that is the default under only some arms keeps its flag, short, phrase and description, because it is a choice elsewhere. Flag completion hides the value that is the default for the flags already typed. The printer drops an arg equal to the default that the other args give, so `.` replays the same value. The key compiler stores the resolved default in the leaf.
- `value_when`: on an `enum` param, `{ value: { sibling: [values], ... } }`. The value is allowed only while every named sibling has a listed value (AND, as in a default arm). A value with no entry is allowed everywhere, so a new sibling value gets no restricted enum value until someone lists it. `check_args` checks the final value, explicit or default, so a combination that makes no sense is an error on the command line and never compiles into a key. A hint `action` of `background` needs a `filter` that has an address, and `mute` needs `media`. The define check refuses a key that is not one of `values`, a bad sibling, and a default arm whose value its own condition does not allow (the arm must name every sibling the rule names). The rules travel in `commands.json`.
- `pattern_arms`: on a `string` param, `[{ pattern, when }, ...]`. The final text must match the pattern of the first arm whose `when` holds (several siblings allowed, AND). Each value of a sibling, such as the `action` of `media`, so takes its own value set, which one `pattern` cannot give. With no arm holding, the plain `pattern`, if any, applies instead. A `when` param may also carry a default list: when its `when` holds and no arm of the list does, the param is required, so `media seek percent` needs its count while `media seek up` defaults to one. The arms travel in `commands.json`.
- Every static argument rule lives in the param schema, and one `check_args` applies it for the command line, key map compile, `tools/build-config` and the router. A context source (`@selection`) passes the check as a marker, so the router runs `check_args` again on the expanded text. `help` takes a page name (`quick_start`) or a command id, matched exactly. A command handler never judges argument values. It reports only runtime failures, such as a tab that is gone, a refusal from Firefox or an empty selection, and throws them as `RuntimeRefusal`. `test/registry/handler_static_rules.test.ts` fails when a background handler throws anything else on args the schema accepts.
- `default`: a value, or a context source (`{ from: "current_url" }`, `"selection"`, `"clipboard"`, `"bookmark_title"`, the title of the current page's bookmark, `"search_query"`, the query of the search results page, read back through the engines' URL templates). A context source can carry `then`, a second source read when the first has nothing: `{ from: "selection", then: "search_query" }` is the default of the `query` of `search`. The router fills a context source where it is available, so a background command can ask for the page selection.
- `runs_in`: `background` or `content`. The router sends the invocation to that side. A command never runs in both.
- `needs`: what must be true to run it. `content` means a content script in the tab. A permission name means an optional permission. The router refuses with a message instead of failing silently. A command that needs a permission only for some args (`page.reload` with `clear`) checks it in the handler and throws `RuntimeRefusal`. Either way the message names `:permissions.grant <permission>`, which opens the grant panel.
- `count`: what a numeric prefix does. `repeat` runs the command that many times. A param name fills that param, for example `tab.goto` takes the count as its `index`. `ignore` drops it.
- `repeat_limit`: the largest count prefix the router accepts, for a command whose repeats are hard to undo. It must be a positive whole number. It needs a `count` rule other than `ignore`. A bigger prefix is refused with a toast (`A count of 100 is over the limit of 20 for tab.close`) before any step of the request runs, so `.`, `3.`, macro replay and snippets refuse the same way and a sequence never runs half. A typed param count (`tab.unload --count=100`) is not a prefix and is not limited. `tab.close` and `tab.unload` carry 20. A yes/no confirmation line, so a big count can still run, is a possible follow-up.
- `bridge`: whether a program outside the browser may run the command through the bridge socket (see [Bridge host](host.md#bridge-host)). Every built-in command states it with `bridge: true` or `bridge: false`, and a test fails when one does not. The tab commands that move between tabs (not `tab.switch`, which matches a title or address and so tells a caller which tabs exist, and not `tab.close`, which closes whole sides of the tab bar: the id-addressed `activate` and `close` verbs behind `bridge_share_tabs` do both), `tab.mute`, `open.url`, `media.act`, the `scroll.*` commands and the mode commands (`mode.set`, `mode.insert`, `mode.escape`) say true. The rest say false. A hard-coded never-list wins over a true.
- `repeatable`: whether `.` can replay the command. The default is true. These commands opt out: `command.repeat`, `browser.close_all`, `browser.focus_page`, `config.reload`, `debug.perf`, `debug.restart`, `page.print`, `page.save_pdf`, `frame.exit`, `help.open`, `help.key`, `native.install`, `native.update`, `permissions.grant`, `engine.show`, `settings.set`, `settings.toggle` and `settings.unset`, and the page commands that only change a mode or open a prompt: `mode.set`, `mode.escape`, `mode.pass_next`, `hint.key`, `find.open`, `help.whichkey`, every `cmdline.*` and `list.*` command, `caret.move` and `visual.act` (a motion replays in normal mode, where it does not apply). One command opts out by its args: `page.reload` is not repeatable with `clear` set to `all`, so `.` and a macro never run a clear of every site. The `repeatable` field takes a function of the checked args for this.
- `jumps`: whether a successful run moves the view in the tab it ran in, so the router records the place it left in the jump list. Absent means false, and a command without it pays nothing. The field takes a function of the checked args: `open.url`, `open.search`, `open.anything`, `open.clipboard` and `page.follow` jump only with `where` set to `here`. `scroll.to`, `find.next`, `find.prev`, `heading.go`, `page.heading`, `mark.step` and `mark.jump` always jump. Reading and recording are in the jump list paragraph under Marks.
- `modes`: the modes where a key can run the command. The default is normal.
- `completion`: where the command line list offers the command. Absent means always. `hidden` means never, and a list of modes means only when the line was opened from one of them. Typing the name still runs the command.
- `advanced`: `true` for a rarely used command (`config.reload`, `debug.restart`, `native.install`, `native.update`). Only the help Commands page reads it: the cards stay hidden until `#/commands?advanced` (the "Show advanced commands" button sets it), and a `#command=<id>` link still shows its card. Completion, keys and which-key ignore it.
- `run`: the handler. It gets the context (tab, frame, mode) and the checked args.

Validation is strict and happens in one place, the same as `Act.resolve` in Oasis. The command line, keys, the native host and the palette all pass through it.

Define-time checks cover names and params too:

- `name` and `aliases` are unique across all commands, snippets included.
- At most one param is `main`, and it is a `string`.
- A long flag names at most one param of a command: no two enum params share a value, and no bool name repeats a value. `_` reads as `-` in a flag, and no value or bool is called `help`. Names and values are lowercase with underscores.
- A short letter is one ASCII letter, never `h`, and unique within the command.
- A `when`, and every param named in the `when` of a default arm, is a param that exists, with valid values, and never the param itself.

A set of options where at most one can apply, for example open, background tab or copy link for a hint, is one `enum` param with a value per option. Two flags from the set both set that param, so the command line rejects them together. No list of exclusions exists. This turns the hint command into five params: `action`, `filter`, `selector` (with `when: { filter: "custom" }`), `text` and the `rapid` switch.

A build step writes `commands.json` from the registry: id, name, aliases, label, intent, params, count, repeat_limit, modes, completion and advanced. Help, the palette, which-key and the native `list` verb read it. The content script does not load it.

### Background files for request routing

Behavior of the `src/background` files for this area, moved here from `src/background/README.md`.

- `message_table.ts`: the table type and `dispatch`, the one `runtime.onMessage` listener. Each entry names who may send (`from`: `page` for an extension page, with the `refused` answer for any other sender, `frame` or `tab` for a sender with a tab, `any`) and `run`. A guard that fails never runs the handler. A type no table holds gets no answer, because on the help and newtab pages other listeners answer the same message. `satisfies Handlers<keyof ToBackground>` in `main.ts` fails the typecheck when a request has no entry, and `test/background/message_table.test.ts` fails when two tables share a key, because a spread lets the last one win silently.
- `record_step.ts`: `record_step(steps, outcome, origin)`, the one call every finished request or leaf passes. It fills the `.` slot with the repeatable steps of a plain success. `page_steps` and `page_outcome` check what a page script sends.
- `router.ts`: the one entry for run requests. It first refuses a count prefix over a command's `repeat_limit`, over all steps before any runs. A content step and the open command line each wait for the content script's answer: done goes on, failed stops with one toast, and cancelled (the user left the wait) stops with none and stores no repeat. Every request ends in `record_step`. A prompt or an empty `@selection` opens the command line with the printed command. A missing required param refuses. An empty `@selection` runs the command instead when `runs_with_empty` says it can on this page, as a search on a `{query|url}` engine can. A source can carry `then`, read when the first gives nothing (`search` reads the selection, then `@search_query`). The prefill uses short flags, for example `open -t `. For a command with the `jumps` flag it reads the top frame's scroll offset first (`read_offset`, capped at 1 s) and puts the place in the jump list after the command succeeded (`record_jump`). Its pieces are `count.ts` and `refusal.ts`.
- `availability.ts`: the one check for "can this page fill what a thing needs?", shared by engines, snippets and which-key. A requirement is a list of slot expressions (`repo`, `host|title`). An engine with a fallback asks nothing. `requirement_lookup` reads the requirement of an invocation: the slots of the engine a search names, or the `requires` of a snippet. `site_engine_for` picks the engine of a `site_keys` key for a page (host in the engine's `hosts`, slots fillable), `with_site_engines` settles it before a run and names the letter when the page fits none, and `available_engine_names` is for command line completion. `runs_with_empty` tells the router whether a search runs with no query on this page: its engine, or the fallback that runs in its place, fills the URL without one.
- `bundle_loader.ts`: injects a bundle into a frame when the content script asks, once per document. For a sender under the extension origin it asks the page to add the script tag instead, because Firefox refuses `executeScript` there. It joins repeat asks, answers a failure or a missed deadline with a refusal, and checks the bundle name because the sender is a page script.
- `selection_ask.ts`: reads the selection of a frame for a `selection` context source, and the scroll offset of the top frame for a command with the `jumps` flag. The `page` bundle answers `get_selection` and `get_jump_offset` (the offset with the page's own address, so the router records nothing when another page answered), so on no answer it injects `page.js` into the frame and asks again.
- `issue_report.ts`: the body and the URL of the `:issue` report. Pure. The form body has the versions, the system and the warning count. The copy body adds the warnings word for word, at most 10 and 2 KB with a count of the cut ones, and replaces the config folder path in them with `<config dir>`.
- `snippets.ts`: the user's snippets as commands. `matches` and `requires` are checked here against the tab URL, the code runs in the top frame only, and `desertfox.run` calls come back through the `snippet_run` message with the caller's depth (limit 5).

### Commands files for the registry

The module list and the rules every definition follows, moved here from `src/commands/README.md`.

- A definition gives an id (`tab.pin`, group then verb), a label, an intent, params and `runs_in`. The first sentence of the intent is the summary that lists show: a verb first, at most 60 characters, no other command named. Every flag param has a one-sentence `description`. A registry audit test checks both. A `background` command runs here, with browser APIs. A `content` command has no `run`: `src/content/handler_map.ts` maps its id to a handler from `src/content/handlers/` (`scroll.ts`, `mode.ts`, `page.ts`, `stop.ts`), which the content script runs in the page, or the command names a `bundle`.
- State `bridge: true` or `bridge: false` on every definition. True lets a program outside the browser run the command through the bridge socket. The built-in `define` requires the field, a registry audit test checks it, and a hard-coded never-list in `src/background/bridge_run.ts` wins over a true. Say true only for a command that is safe to run with no one watching: tab navigation, media, scroll and mode commands today.
- Set the typed `name` by hand, and only for one-word commands and family words (`open`, `search`, `tab`). Every other command is typed by its dotted id. The registry rejects a duplicate name.
- A handler throws `RuntimeRefusal` (`src/shared/command.ts`) for a failure that depends on browser or config state. A bad argument value belongs in the param schema (`min`, `pattern`, `strict`, `optional`), never in a handler.
- `hint.ts`, `heading.ts`, `cmdline.ts`, `caret.ts` and `visual.ts` hold commands whose code sits in a bundle. Such a command has a `bundle` field and no `run`. The compiler and the router pass the field to the content script (`LeafStep.bundle`, `Invocation.bundle`), which loads the bundle on the first run, or refuses with `needs <label>` while the bundle registers no handler (`src/content/run_content.ts`).
- Modules by group: `tab`, `tab_group` (the `tabgroup.*` commands on the tab's native tab group, over `TabGroupDeps`), `tab_split` (`tab.split_other` and `tab.split_swap`, the other pane and swap of a split view, over `src/background/tab_split.ts`), `window` (it also holds `tab.attach`, which moves the tab to another window), `bookmark`, `history`, `browser`, `zoom`, `page`, `url`, `scroll`, `mode`, `copy` (it also holds `copy.links`, which runs in the hints bundle), `copy_tabs` (`copy.tabs`, `yT`, runs in the background: it lists the open web tabs of this window or all windows in the link-list formats of `src/shared/copy/link_list.ts`, without the tracking parameters), `config`, `native`, `settings` and `help`.
- `perf.ts` holds `debug.perf` (`:perf`, no key), which copies the timing summary to the clipboard.
- `native.ts` holds `native.install` and `permissions.grant`, which open the Help grant panel at `#grant/<permission>`, `native.update`, which calls `update_now` in `src/background/host_update.ts` and reports the result, and `browser.open_firefox_page` (`:firefox`, the `,f` keys), whose handler and page table sit in `firefox_page.ts`: it asks the native host to open an `about:` page, and without the host it copies the address.
- `issue.ts` holds `help.issue` (`:issue`, no key): it opens the prefilled GitHub new-issue form (versions, system, warning count), or with `--copy` copies the report with the warning text and opens the blank form. It sends nothing itself, and the form is the review step. The report text comes from `src/background/issue_report.ts`.
- `help.ts` builds the `:help` choices from the registry: the page names (`quick_start`) and the command ids, matched exactly, so `src/background/command_modules.ts` imports it last.
- `open.ts` holds `open.url`, `open.search`, `open.clipboard` and `open.anything`.
- `engine.ts` holds `engine.show`.
- `quickmark.ts` holds `quickmark.add` (`M<key>`), `quickmark.open` (`go<key>`, `gn<key>`), `quickmark.delete` and `quickmark.list`: the handlers take a `QuickmarkDeps` object, and the table is `quickmarks.toml` with the saved entries on top.
- `register.ts` holds `register.list` (`:registers`), which toasts the registers that hold something or one register in full.
- `session.ts` holds `session.save`, `session.open`, `session.delete` and `session.rename`: the handlers take a `SessionDeps` object with the store and the browser calls, and the new window and tab creation lives there (the store and the restore plan are in `src/background/session_store.ts`).
- `register_param.ts` holds the `register` param that the yank commands (`copy.url`, `copy.links`, `copy.tabs`, `hint.run`, `visual.act`) and `open.clipboard` share: the `"<reg>` prefix fills it.
- `text.ts` holds `text.insert`, which the typed-text recorder stores and `.` replays, and `register.paste`, which `<C-r><reg>` runs in insert mode; the code of both sits in the `text` bundle. `text.ts` also holds `text.edit_external` (`<C-o>` in insert mode), whose code sits in the `editor` bundle and whose job the background keeps (`src/background/external_editor.ts`).
- `mark.ts` holds `mark.add`, `mark.jump` and `mark.step` (`]'`, `['`), whose code sits in the `page` bundle.
- `jump.ts` holds `page.jump` (`<C-o>`, `<C-i>`), also in the `page` bundle.
- `page.focus_link` (`]l`, `[l`, in `page.ts`) runs in the hints bundle. `page.send_key` (in `page.ts`) is meant for the `bind` column of a site row, and it also backs the default `<A-Escape>` insert binding, which sends Escape to the page on any site. Its code sits in the `site_actions` bundle.
- `macro.ts` holds `macro.record` (`q<reg>`) and `macro.stop`, which drive the recorder in `src/background/macro_recorder.ts` and store the steps in the register, and `macro.play` (`@<reg>`), which runs the replay in `src/background/macro_replay.ts`.
- `media.ts` holds `media.act` (`media`), which runs the frame fan-out in `src/background/media_actions.ts`.
- `command.ts` holds `command.repeat`, which replays the stored request through a router that `src/background/main.ts` wires in.
- `settings.ts` holds `set`, `toggle` and `unset`. The pure `plan_set`, `plan_toggle` and `plan_unset` (in `src/shared/settings_plan.ts`) turn the checked params into the edits to keep (saved for a consent setting, or temp with `--temp`) and the toast that answers. `plan_set` refuses to save any other setting, but `save_in_browser` also saves `default_engine` there. The handlers publish through `change_edits` in `src/background/config_store.ts` and toast after the publish. Without `--temp`, a name in `FILE_WRITTEN_SETTINGS` goes to the settings.toml writes of `src/background/config_setting_writes.ts` instead, and the toast waits for the host write and says where the change went.
- `help_tab.ts`: `open_help_url`, which opens a help page URL beside the asking tab or navigates in place. `help.open`, `help.key`, `native.install` and `permissions.grant` share it. `help.open site_rules` adds the invoking tab's address (not the help page's) to the hash, which the Site Rules page reads. `help.key` (`:helpkey ,r`) reads the compiled keymap in normal mode through `key_command_id` in `src/background/open_help.ts` and opens the card of the command the keys run. A count or register prefix is read as the page reads it, and a key bound to several steps opens the first step's card. Key notation is checked by the param `format: "keys"`, so only an unbound sequence refuses in the handler.
- `open_target.ts`: the `where` and `container` params, `open_in` (opens a URL here, in a tab or in a window), the container lookup, `current_tab_url` and `current_page` (the page that engine slots read), and `typed_url_target` for text a person typed (`config_url_target` in `src/shared/url_build.ts` does the pure part).
- `reload_clear.ts`: the clear scopes of `reload --clear` (`site` and `all`). Firefox ignores `hostnames` for the cache, local storage and service workers, so a site clear takes only the cookies by host name.

### Registry files for the registry

Behavior of the `src/shared/registry` files, moved here from `src/shared/registry/README.md`.

The command registry and everything that reads a command definition. Pure TypeScript with no browser APIs, so the background page and Node tools share it. `tools/write_commands_json.mjs` loads it straight from source.

- `define.ts`: `create_registry` and the define-time checks. Every rejection is a `DefineError` that names the command and the field. It checks the param rules described above: `repeat_limit`, the flag names, the `short` letters, the `value_labels` and the `description`. The default arms are checked like a `when`, a cycle between defaults is refused, and each arm is checked against the `value_when` rule of its own value. Command names hold no dot. Snippet commands go through the same `define`, so they share the name check. `remove` frees a command and its words, for a reload that replaces the snippets.
- `check_args.ts`: the one validator, and the home of every static argument rule (see the param rules above). Runtime enum lists (engines, containers) arrive as an `EnumSources` argument. The value rules `min`, `pattern`, `strict`, `optional` and `value_of` live in `ParamDef` (`src/shared/command.ts`) and are applied here. It checks the final value against `value_when` (`value_rule_error` in `params.ts`) and `pattern_arms` (`pattern_arm_error` in `params.ts`). `params.ts` holds the readers: `default_of` resolves against known args, `possible_defaults` and `always_default` answer for the definition alone.
- `command_line.ts`: the one grammar for command text, text to `Invocation`. It never checks `when` or types. Call `check_args` on the result. Flags come before the subject. Pass the same `EnumSources` so the first bare word can pick from a runtime list, for example an engine name.
- `parse_binding.ts`: the same grammar for a config binding, plus the leading `:` that turns into a stored `prompt`.
- `print_command.ts`: the inverse of `command_line.ts`, an invocation back to text. It writes the engine first, flags in param order and the subject last, and leaves out args equal to the default. It checks each line by parsing it again and falls back to a `--` guard, quotes and then `--name=value` when the text would be misread. An open param prints with no value. `flags: "long"` writes the docs form, and `print_flag` writes one param as a flag.
- `usage.ts`: the usage line shown for `-h`, in the words the grammar reads, and `flag_alternatives`, the flags of one param that the help page lists.
- `summary.ts`: the summary rule. `first_sentence` cuts the text that lists show out of an `intent`. `summary_problem` and `description_problem` check it, and `summary_problems` audits one command, including a flag that has no description. The define-time check runs `description_problem` on a description that is present. A test runs `summary_problems` over every built-in command, because snippets from the user's config go through `define` and need not meet the rule.
- `commands_file.ts`: the `commands.json` content.
- `params.ts`: small readers over params shared by the files above, including which param is the subject and which takes the first bare word. `captured_key_param` finds the `key` param a binding leaves out, and `without_param` lets the rest of the args be checked before the key press.
- `index.ts`: the exports of types and helpers, and nothing else. It runs nothing at import, so a bundle that imports a helper pays only for that helper.
- `check_shape.ts`: the shape checks of the validator, every rule except the text of a setting value. The command line page imports it directly, because `check_args.ts` pulls in the setting rules, which are too big for that bundle.
- `single_quote.ts`: one word of command line text in single quotes.
- `builtin.ts`: the shared `registry` and `define`. Command modules, the background page, Node tools and tests that need the singleton import it. Never import it from a page, the content script or help: the call at import keeps `define.ts` and the setting rules in the bundle. `test/registry/bundle_free.test.ts` bundles each non-background entry and fails when one reaches `builtin` or `define`.
