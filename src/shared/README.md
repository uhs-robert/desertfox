# shared

Types and constants that fix the hand-off formats between the background page, the content script and `tools/build-config`. Besides types and constants it holds small helpers and the config, key and registry logic (`registry/`, `keys/`, `theme/`, `config_build/`, `match_pattern.ts`, `score.ts`, `site_key.ts`). Most of it is pure. Some files touch the browser or the DOM, for example `storage_watch.ts`, `icons.ts` and `theme/apply.ts`. Every other source folder may import from it, and it imports from none of them. The one exception is `config_build/schemas.ts`, which only the build tool and tests load and which reads `background/default_keymap.ts`.

- `command.ts`: a command definition, and the `commands.json` entry cut from it. Also the value lists that a command and its content handler share (`SETTABLE_MODES`, `COPY_FORMATS`, `SCROLL_TO_DEFAULT_AXIS`).
- `invocation.ts`: the `Invocation` every caller produces, and a key binding.
- `keymap.ts`: keymap data as written by the user.
- `prefix_tree.ts`: the compiled keymap stored in `storage.local` for the content script. Its `format_version` is bumped when the shape changes, and `current_keymap` hides an older one until the background recompiles at its next start. A `SiteRule` holds its `bind` as normalized key to tokens and leaf.
- `grab_steps.ts`: the grab step ladder (3 to 192 px, doubling), shared by the `grab_step_px` setting and the grab bundle.
- `messages/`: every message by channel: `content.ts` (content script and bundles to the background), `page.ts` (extension pages to the background), `tab.ts` (background to a frame) `ports.ts` (the devtools and tab model ports) and `map.ts` (each request with its answer type, one map per direction, and the request unions derived from them).
- `relay.ts`: the handlers a frame may ask the background to run in another frame of its tab (`relay` message), each with its bundle and direction: to the top frame, or to a frame named by id. The background adds the sender's `from_frame`.
- `container_store.ts`: the name and cookie store id of the container-less store, shared by the background and the `open` commands.
- `group_name.ts`: the label of a native tab group (its title, or title plus `#id` when empty or shared) and the lookup of a typed label.
- `tab_model_port.ts`: the port names of the live tab model, the plain one and its `:normal` and `:private` forms.
- `rank_port.ts`: the port between the command line page and the background for the lists that rank the history: the request (a word, a sequence number and the finder's over-fetch), the reply of at most 100 ranked rows with their scores, and the `stale` push.
- `folder_pick.ts`: `pick_by` (exact key, then best fuzzy match, a tie refused), `pick_folder` (the filing rule for a folder path), `in_folder` and `rows_in_folder` (the subtree test). The `bookmark` handlers and the command line page share them, so a typed `--folder=` filters by the rule that filing uses.
- `mark_names.ts`: the local mark keys (`a-z`, and `'` or the backtick for the previous position), the limits of the mark store and the one rule that cuts the hash off a page address.
- `mark_text.ts`: the text of a mark or quickmark in a list (address without scheme, scroll offset), which the which-key rows and the command line list share.
- `quickmark_names.ts`: the quickmark key rule (one letter or digit), the address cap and the `QuickmarkTable` type.
- `media.ts`: the messages between the background and the `media` bundle, the media actions and the step rules of speed, volume and seek.
- `bundles.ts`: the names of the scripts loaded on first use, and which mode loads which. Also `MEDIA_PANEL_HANDLER`, the handler id the background sends to `whichkey`.
- `help_route.ts` (in `page/`): the help page ids, the hash parser (`parse_route`) and the help URL builders. The popup, the background, the commands and the help page share it.
- `icon_cache.ts` (in `page/`): the favicon cache in `storage.local` (`favicon_cache`), which the background saver fills and the new tab page reads. The storage is passed in, so the module needs no browser global.
- `url_build.ts`: pure URL math. `parent_url` and `root_url`, `url_target` (text to a URL) and `config_url_target` (the same under a config's engines), the two engine fillers: `engine_search_url` for typed text and `engine_url`, which follows `fallback` when the page cannot fill the slots, and `own_pages`. The slot table and the template filler are in `engines/`.
- `page_bundle_tag.ts`: the extension pages' side of a bundle load. `listen_for_bundle_requests` adds a bundle's `<script src>` tag when the background asks, joins repeat asks and answers after the script has run.
- `registry/`: the command registry, the one validator and the command line parser. See its README.
- `engines/`: search engines as URL templates with slots, and the tree resolver. Outside the barrel. See its README.
- `keys/`: key notation, the prefix tree compiler and the matcher. See its README.
- `theme/`: the public role list (`roles.ts`), the table that fills missing roles (`derive.ts`), the theme file check (`theme_file.ts`), the base16 and base24 reader and its slot-to-role table (`base16.ts`), the fg_dim contrast clamp the Oasis build and the importer share (`contrast.ts`), the CSS token names (`tokens.ts`), the theme lookup from the `theme` name (`load.ts`, never a page or content bundle) and the font list check (`font_family.ts`) and the stored theme as CSS (`apply.ts`, for pages and lazy bundles, with the `desertfox_theme` and `desertfox_user_css` storage keys). User CSS must name a surface's inner class: variables on `:root` or `:host` do not reach inside. The extension build and `tools/build-config` share them.
- `config_build/`: the pure config build. It takes raw file text keyed by relative path and the command list, then merges, parses snippets and key bindings, and checks everything. It uses no Node API, so the extension and `tools/build-config` share it. Only the background may import it, because it pulls in `smol-toml` and `themes.ts`. See its README.
- `page_base.css`: the base sheet of the help and new tab pages, copied to `dist/` and linked first in both html files. It holds the fallback palette (including the accent, info, ok, warn and error roles), the type and spacing tokens, the key cap, card and pill styles, and a 15px root size. The help page overrides it with 16px, which its layout is measured in. Every fallback sits in `:where(:root)`, at zero specificity, so a theme or `style.css` rule always wins. Pages add their own colors only as `var(--desertfox-*)`, never as a declaration.
- `key_caps.ts`: `key_caps(text)` draws a key sequence (`gt`, `<Space> g t`, `<C-x>`) as a row of `kbd.desertfox-keycap`. It reuses `parse_sequence`, and a word the notation refuses stays as one literal cap.
- `icons.ts`: the inline SVG icons the extension pages draw (`chevron_icon`, `menu_icon`, `heart_icon`). The brand mark stays the file `icons/desertfox.svg`.
- `swallow.ts`: one helper per reason an error is dropped: `ignore_refusal`, `best_effort`, `keep_chain`, `refused_as(promise, fallback)` and the handler `warn_and_go(label)`, which logs. They replace an inline silent `.catch`, which the `no-restricted-syntax` lint rule in `eslint.config.mjs` flags. The content script imports it, so keep it free of classes and strings.
- `index.ts`: the barrel of the types and the constants that every folder may import.
- `anything_ref.ts`: the reference a finder row carries to the `anything` command, so the handler acts on the row the list showed and never ranks again.
- `config_file_path.ts`: which paths the files editor may store. The page refuses early and the background decides.
- `engine_fields.ts`: the checks of the engine form's fields. The page runs them while the user types and the background runs them again at Save.
- `font_candidates.ts`: the built-in font names (`FONT_CANDIDATES`), `probe_fonts` (keeps the names whose canvas width differs from both `monospace` and `serif`), `canvas_measure` and `merge_font_names` (dedupe, drop names `parse_font_family` refuses, sort, cap 2000). Extension pages only: the background page runs it (`background/font_names.ts`).
- `host_version.ts`: release versions of the extension and the native hosts, and the check that a host is older than the extension.
- `inspect.ts`: what the background relay and the hints bundle agree on for the Inspector handoff.
- `jump_names.ts`: the limits and the entry of the jump list, shared by its store, its step and the page.
- `load_commands.ts`: fetches `commands.json` for the help and status pages. Not for the content script.
- `media_values.ts`: the value patterns of the `media` actions. Apart from `media.ts` so the `media` bundle does not carry these texts.
- `quality.ts`: the messages between the background and the `quality` bundle.
- `register_names.ts`: the register names and the one check every register user shares.
- `score.ts`: the fuzzy scorer for every completion source. It scores like fzf version 1 and counts a dot as a word break. `rank_top` gives the first rows of `rank` with their scores.
- `send_key_limit.ts`: the most key pairs one `page.send_key` call sends.
- `setting_list.ts`: the settings page's view of every setting: typed value, top layer, kind and allowed values.
- `site_key.ts`: the key that groups tabs of one site. Each subdomain is its own site, so no public suffix list is needed.
- `table_constants.ts`: the constants the settings table reads for its defaults. They sit apart from `config.ts` so the generator can load the table when `default_settings.ts` is missing.
- `theme_names.ts`: every built-in theme name, generated by `tools/build_themes.ts` (`just themes`). It carries no colors.
- `zip.ts`: `read_zip` and `write_zip` for config export and import. The reader takes stored and deflated entries and returns a path-to-text map. It skips `__MACOSX/` and dot-file entries and drops `.` path segments. It fails the whole archive on an unsafe path (absolute, `..`, backslash), an exact duplicate, a symlink, overlapping entries, a size or count overrun, a bad checksum or text that is not UTF-8. `read_folder` puts a folder the page read (`webkitdirectory`) through the same path, junk, duplicate, count and size rules. The writer is store-only. The byte caps (1 MiB) equal the host's reply cap. Pure, so the background and help pages can both use it.
- `storage_watch.ts`: `watch_stored` (a `storage.local` key, now and at each change), `touches_settings` (a `storage.onChanged` event that says the settings in force changed: a write of the config status key `CONFIG_STATUS_STORAGE_KEY`, which every settings edit ends with, or of `FILES_CONFIG_STORAGE_KEY`, the last write of a reload) and `follow_settings`. Pages use `follow_settings(draw)` to redraw from the current settings: it calls `draw(true)` at once and `draw(false)` at each change, one at a time, and puts the scroll position and focus back after each redraw. The page keeps its own timers and listeners out of the DOM and stops the old ones in `draw`.
- `permission_grant.ts`: the optional permissions a Help panel grants, the manifest permissions behind each, the `#grant/<permission>` hash and the refusal hint.
- `native_host.ts`: the host name, the `nativeMessaging` permission, `host_channel` (a development install follows `main`, any other build its own version) `install_hashes_of` (reads `host_sha256.json`), and the two one-line install commands the Help panel shows: checked against the signed build for a release, unchecked from `main` otherwise.
- `themes.ts`: generated by `just themes` from `themes/oasis/*.css` and the repo `themes/*.toml`, every role filled. It packs each color set as an array in role order and holds about 26 KB, so only the background imports it. Do not edit.
- `match_pattern.ts`: WebExtension match patterns. The background imports the parser. Snippet `matches` use `matches_pattern`, and each `site_rules` row compiles to one regex source (`regex` of a `SiteRule` in the compiled keymap) that the background tests with `matches_any_address` against the sender's address (`page_keymap.ts`). It also holds the site table's column rules: `site_row_columns` splits a row into its `off`, key rule and per-site values, and `resolve_site_columns` lets the first matching row that sets a column decide it. `bind` and `keymap` merge key by key (`keymap` per mode). The compiler, the background and the popup share them.
- `key_test_build.ts`: `KEY_TEST_BUILD`, true only in the build the key test loads (`KEY_TEST_BUILD=1 node tools/build.mjs` defines `__KEY_TEST__`). The page-readable test attributes sit behind it, so release bundles drop them.
- `layers.ts`: the `z-index` of each surface the content script draws, bottom to top: hints, mode badge, toast, which-key panel, command line.
- `config.ts`: the merged config file and the settings in force. `apply_edits` puts the saved and then the temp browser edits over the config's settings.
- `settings_table.ts`: every setting as one row of data, its kind, values and default. The `Settings` type follows from it. Start here to add a setting.
- `settings_plan.ts`: the pure planners of `set`, `toggle` and `unset`: the edits to keep and the toast that answers. The `settings` commands and the settings page message run them.
- `settings_schema.ts`: what each setting accepts, derived from its table row. The build tool and `set` share it. The content script and the command line page must not import it.
- `settings_docs.ts`: the long description of each setting for the settings file schema, and the plain label and one-line summary for the Settings page. A `{key:name}` in the prose names the key bound to an action in `bound_keys.ts`. `key_docs.ts` fills it in: the Settings page from the live keymap, the schema from the default keymap with "by default".
- `bound_keys.ts`: which key runs a named action (`BINDINGS`, `bound_key`), read from the compiled keymap. Quick Start, the Settings docs and the new tab hint share it.
- `setting_completion.ts`: generated by `just settings-defaults` from the schema, one row per setting with its name, flags, expectation and listed values. The command line page reads it instead of the schema. Do not edit.
- `default_settings.ts`: generated by `just settings-defaults` from the table, one constant per setting. Do not edit.

The content script imports only part of this folder (types, constants, `keys/` and the small helpers it needs), to stay under its size guard. A new import into `content.js` must pass the admission rule in `AGENTS.md`, "Content script size".
