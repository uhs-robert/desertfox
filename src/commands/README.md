# commands

The command definitions. Each file is a command module: it calls `define` from `src/shared/registry/` once per command and holds the code that runs it. Keys, the command line, completion, help and which-key read the definition and never carry behavior of their own.

- A definition gives an id (`tab.pin`, group then verb), a label, an intent, params and `runs_in`. The first sentence of the intent is the summary that lists show: a verb first, at most 60 characters, no other command named. Every flag param has a one-sentence `description`. A registry audit test checks both. A `background` command runs here, with browser APIs. A `content` command's `run` is a handler from `src/content/handlers/`, which the content script runs in the page (`scroll.ts`, `copy.ts`, `mode.ts`).
- Set the typed `name` by hand, and only for one-word commands and family words (`open`, `search`, `tab`). Every other command is typed by its dotted id. The registry rejects a duplicate name.
- Modules by group: `tab`, `window` (it also holds `tab.attach`, which moves the tab to another window), `bookmark`, `history`, `browser`, `zoom`, `page`, `url`, `scroll`, `mode`, `copy` (it also holds `copy.links`, which runs in the hints bundle), `config`, `native`, `settings` and `help`. `native.ts` holds `native.install`, which opens the Help page at `#native-install`. `help.ts` builds the `:help` choices from the registry: the page names (`quick_start`) and the command ids, matched exactly, so `command_modules.ts` imports it last. `open.ts` holds `open.url`, `open.search` and `open.clipboard`. `engine.ts` holds `engine.show`. `register.ts` holds `register.list` (`:registers`), which toasts the registers that hold something or one register in full. `session.ts` holds `session.save`, `session.open`, `session.delete` and `session.rename`: the handlers take a `SessionDeps` object with the store and the browser calls, and the new window and tab creation lives there (the store and the restore plan are in `src/background/session_store.ts`). `register_param.ts` holds the `register` param that the yank commands (`copy.url`, `copy.links`, `hint.run`, `visual.act`) and `open.clipboard` share: the `"<reg>` prefix fills it. `text.ts` holds `text.insert`, which the typed-text recorder stores and `.` replays, and `register.paste`, which `<C-r><reg>` runs in insert mode; the code of both sits in the `text` bundle. `mark.ts` holds `mark.add` and `mark.jump`, whose code sits in the `page` bundle. `macro.ts` holds `macro.record` (`q<reg>`) and `macro.stop`, which drive the recorder in `src/background/macro_recorder.ts` and store the steps in the register. `command.ts` holds `command.repeat`, which replays the stored request through a router that `main.ts` wires in.
- `settings.ts` holds `set`, `toggle` and `unset`. The pure `plan_set`, `plan_toggle` and `plan_unset` turn the checked params into the edits to keep (saved, or temp with `--temp`) and the toast that answers. The handlers publish through `change_edits` in `startup.ts` and toast after the publish.
- A handler throws `RuntimeRefusal` (`src/shared/command.ts`) for a failure that depends on browser or config state. A bad argument value belongs in the param schema (`min`, `pattern`, `strict`, `optional`), never in a handler.
- `hint.ts`, `heading.ts`, `cmdline.ts`, `caret.ts` and `visual.ts` hold commands whose code sits in a bundle. Such a command has a `bundle` field and no `run`. The compiler and the router pass the field to the content script (`LeafStep.bundle`, `Invocation.bundle`), which loads the bundle on the first run, or refuses with `needs <label>` while the bundle registers no handler (`run_content.ts`).

Helpers:

- `help_tab.ts`: `open_help_url`, which opens a help page URL beside the asking tab or navigates in place. `help.open` and `native.install` share it.
- `open_target.ts`: the `where` and `container` params, `open_in` (opens a URL here, in a tab or in a window), the container lookup, `current_tab_url` and `current_page` (the page that engine slots read), and `typed_url_target` for text a person typed.
- `url_build.ts`: pure URL math. `parent_url` and `root_url`, `url_target` (text to a URL), and the two engine fillers: `engine_search_url` for typed text and `engine_url`, which follows `fallback` when the page cannot fill the slots. The slot table and the template filler are in `src/shared/engines/`.

To add a command: pick the module of its group, or add one. Call `define` with the id, label, intent and params. Import the module in `src/background/command_modules.ts`, which the commands.json build tool reads too. Put browser access in `run` and keep URL math in a pure function with a test. A command that only opens a URL is better as an engine in the user's config, and one that needs the page DOM or several steps as a snippet.
