# cmdline

The command line: press `:` and a bar opens at the bottom. Type a command, press Enter, it runs.

- `host.ts`: the `cmdline` bundle (`cmdline.js`). The first `:` injects it into the page. It mounts the iframe in a closed shadow root, sets the `cmdline` mode, keeps the keys typed before the page is ready, and sends the parsed command to the background as a `run` message from the page's own frame. It closes itself if the page has not opened in 3 s, if the page removes the bar or sends the frame elsewhere, and on Escape even when the frame is gone.
- `page.ts`, `cmdline.html`: the page in the iframe (`cmdline_page.js`). It reads the stored keymap and runs its own matcher on the `cmdline` mode, because the content script's keys cannot reach into the iframe. Enter parses the line with `parse_command_line` (flags first, then the subject; see the command line syntax in `docs/design.md`), over the commands and aliases that `open_cmdline` returns, through `word_lookup.ts`, because the registry cannot load in a page. It loads the user CSS and the `cmdline_prompt` preset (`caret`, `colon`) or custom text from the same answer after its own styles.
- `session.ts`: the text, the inline message, the completion list and the history walk, apart from the DOM. `source_ready` ranks the text again when tabs or bookmarks arrive. A parse error keeps the line open and shows the error. Tab, Up and Down preview a row in the line, Escape closes the list before the line. Pure.
- `completion/`: what the list offers. `tokenize.ts` finds the word under the caret and its class, `sources.ts` builds the command, flag, value, engine, tab and bookmark rows with the one fuzzy scorer in `src/shared/score.ts`, `keys.ts` reads the stored keymap once at open into the keys column (the keys that run a command bare, two shown then `+N`, from the line's mode and `browser`), `live.ts` fetches the tabs, bookmarks and engines from the background once per kind and drops a reply that a newer fetch or the close of the line has replaced. Pure.
- `list.ts`: draws the rows, ten at most, as a window that follows the selection. A tab row leads with a status cell (`%`, `#` and flag icons), a container mark and a favicon. Then come the name, description, args, then the keys cell, which never shrinks. Its widths are CSS in `cmdline.html`.
- `key_input.ts`: one key token to an effect, or to text when no key is bound. Pure.
- `history_cursor.ts`: Up and Down over the history with the draft kept. Pure.
- `protocol.ts`: the message shapes between the host and the page. Only `ready` and `start` use the page's window. The rest travels over a `MessageChannel` port handed over with `start`, so page scripts cannot read or forge it. The host gets a one-time ticket from the background and sends it in `start`, to the extension origin only. The page trades it for the history and commands, so a copy of `cmdline.html` that a site embeds on its own gets nothing.

The history lives in `storage.local`, kept by `src/background/cmdline_service.ts`. The page measures its panel and tells the host the height it needs with a `resize` message, so the list grows upward. The tab, bookmark and engine rows read from the background (`complete_items`), which answers only a tab whose line redeemed a ticket. Before it submits, `session.ts` runs a pre-check with `check_args`: a missing value shows the error under the line and keeps it open, and nothing goes to the background.
