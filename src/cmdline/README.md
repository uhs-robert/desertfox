# cmdline

The command line: press `:` and a bar opens at the bottom. Type a command, press Enter, it runs.

- `host.ts`: the `cmdline` bundle (`cmdline.js`). The first `:` injects it into the page. It mounts the iframe in a closed shadow root inside a top-layer popover that `mount_surface` shows last, so toasts and which-key draw below it. When a surface mounts and shows the popover again, the host gets `desertfox-restacked`, refocuses the frame and sends `refocus` so the page refocuses its input. It sets the `cmdline` mode, keeps the keys typed before the page is ready, and sends the parsed command to the background as a `run` message from the page's own frame. It closes itself if the page has not opened in 3 s, if the page removes the bar or sends the frame elsewhere, and on Escape even when the frame is gone.
- `page.ts`, `cmdline.html`: the page in the iframe (`cmdline_page.js`). It reads the stored keymap and runs its own matcher on the `cmdline` mode, because the content script's keys cannot reach into the iframe. Enter parses the line with `parse_command_line` (flags first, then the subject; see the command line syntax in `docs/design.md`), over the commands and aliases that `open_cmdline` returns, through `word_lookup.ts`, because the registry cannot load in a page. It loads the user CSS and the `cmdline_prompt` preset (`caret`, `colon`) or custom text from the same answer after its own styles.
- Search flavor: `/` and `?` open the same line with a search prompt (`start.search`). Its text is a pattern, so the page parses nothing, offers no list and keeps no history. Each edit goes to the host as `find_text`, the host calls the caret bundle's `find.live`, and the answer ("3 of 17") comes back as `find_status` into the note row. Enter sends `find_commit`. Whatever way the line ends, the host calls `find.end` with `keep` set only after Enter.
- `session.ts`: the text, the inline message, the completion list and the history walk, apart from the DOM. `source_ready` ranks the text again when tabs or bookmarks arrive. A parse error keeps the line open and shows the error. Tab, Up and Down preview a row in the line, Escape closes the list before the line. `pick(index)` takes a clicked row like Tab does. `cmdline.help` (`<C-h>`) gives a `help` effect for the selected command row, else for the typed command word, else a note. Pure.
- `completion/`: what the list offers. `tokenize.ts` finds the word under the caret and its class, `sources.ts` builds the command, flag, value, engine, tab and bookmark rows with the one fuzzy scorer in `src/shared/score.ts`, `keys.ts` reads the stored keymap once at open into the keys column (the keys that run a command bare, two shown then `+N`, from the line's mode and `browser`), `live.ts` fetches the bookmarks, engines and the like from the background once per kind and drops a reply that a newer fetch or the close of the line has replaced. It reads the tabs from `model_client.ts` instead. Pure. `model_client.ts` holds the tab model's rows from its snapshot and patches, asks for a new snapshot on a gap in `rev`, and gives the rows as the list shows them (the line's window first, `%` and `#` only there). Pure. A subject that names one list entry (`help`, `tab`, `bookmark`, window titles) completes on all its words, so `help quick` finds `quick_start`. `set`, `toggle` and `unset` complete setting names, then the values a setting lists, from `shared/settings_schema.ts`.
- `list.act` (`<A-u>`) is the row-action key. In `session.ts` it gives a `set_tab_unloaded` effect for the highlighted tab row, or a note on any other row. `page.ts` sends the message and shows only the refusal. The row's marks change when the model's patch arrives: `session.patch_tab` swaps them in place, so the list and selection stay.
- `list.ts`: draws the rows, ten at most, as a window that follows the selection. A tab row leads with a status cell (`%`, `#` and flag icons), a container mark and a favicon, then a dim window number when the list spans more than one window. Then come the name, description, args, then the keys cell, which never shrinks. An unloaded tab row has the class `desertfox-cmdline-item-discarded`, which dims its name. Its widths are CSS in `cmdline.html`. Each item carries its absolute `data-index`, and the name of a built-in command row is a help link (`data-help`, from `help_ids` in the `open_cmdline` answer). `page.ts` delegates clicks on the list: a link click sends `open_help` to the background and closes the line, a click elsewhere picks the row.
- `key_input.ts`: one key token to an effect, or to text when no key is bound. Pure.
- `history_cursor.ts`: Up and Down over the history with the draft kept. Pure.
- `protocol.ts`: the message shapes between the host and the page. Only `ready` and `start` use the page's window. The rest travels over a `MessageChannel` port handed over with `start`, so page scripts cannot read or forge it. The host gets a one-time ticket from the background and sends it in `start`, to the extension origin only. The page trades it for the history and commands, so a copy of `cmdline.html` that a site embeds on its own gets nothing.

The history lives in `storage.local`, kept by `src/background/cmdline_service.ts`. The page measures its panel and tells the host the height it needs with a `resize` message, so the list grows upward. The bookmark, open, window and engine rows read from the background (`complete_items`), which answers only the frame whose line redeemed a ticket. Before it submits, `session.ts` runs a pre-check with `check_args`: a missing value shows the error under the line and keeps it open, and nothing goes to the background.

The heading rows read from the page: the page sends `list_headings` over the port, the host calls `heading.list` in the hints bundle and answers with `headings`. `heading.go` runs from the snapshot that call took, so the host drops it (`heading.clear`) when the line closes, or after the submitted command ran. A row carries `indent`, which `list.ts` draws as padding on the name, so the highlight positions stay right.
