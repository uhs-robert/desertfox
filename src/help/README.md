# help

The help page, opened by `help.open`. It reads `commands.json`, the compiled keymap, the stored warnings and the resolved engines.

- `route.ts`: the pages and the hash parser. The sidebar lists Home, Settings, Quick Start, Commands, Search Engines and Styling, at `#/`, `#/settings`, `#/quick-start`, `#/commands`, `#/search-engines` and `#/styling`. `#section=<page>/<slug>` shows that page at one of its sections (see `render.ts`). `#command=<id>` shows the Commands page at that command's card (`command-<id>`), and `main.ts` scrolls to it and highlights it like an engine row. An unknown hash shows Home.
- `quick_start.ts`: the Quick Start text as blocks. A `{name}` in a sentence is looked up in the compiled keymap by command and args, shortest key first. A command with no key shows its command line instead, so a rebind or unbind never leaves the text wrong.
- `model.ts`: turns those three inputs into plain rows. Key args and the `flags` column are written by the registry printer, so the page matches the command line. Tests read the rows, so no DOM is needed.
- Home: the tip, the warnings, the settings in force and the steps to apply a file edit (`:native.install` once, then `config.reload`). It is read-only. A setting that differs from the default carries a tag that names its top layer: `settings.toml`, `saved` or `temp`. `config_view.ts` builds those rows.
- Settings page (`#/settings`, the target of `options_ui` in the manifest, so the add-on Preferences button opens it): one field per setting, grouped by name prefix, with its help text, a source tag for the top layer and a Reset that drops the saved and temp edit. A change saves at once through the `change_setting` background message, the same plan as `:set`. Settings that `:set` refuses show read-only with a note. An Install native host button opens the `:native.install` panel by the same hash.
  - `settings_model.ts`: no DOM. Picks the control per setting kind (`control_of`), checks typed values with the setting's own check, and holds the session. The session keeps a draft per field and ignores a refresh for a field with a draft or an edit in flight, so a `storage.onChanged` refresh never clobbers typing or an answer. A refresh only reads, so the page's own write cannot loop. The page refreshes on a write of the config status in `storage.local`, which every edit ends with, and `main.ts` stops the listener before it renders another route.
  - `settings_page.ts`: draws the fields and wires events to the session. Text fields check as you type and save when left. `render.ts` draws the group headings, so section links work before the list loads. The page gets the settings through the `list_settings` message and the engine names from the config it already loads, and never imports the registry.
- Search Engines page: the guide from `docs/search_engines.md`, then every resolved engine in tree order with label, URL, needed slots, fallback and the file and level that set each field. `engine.show <name>` opens the page at `#engine=<name>`, which `route.ts` maps to this page, and `main.ts` scrolls to the row.
- `blocks.ts`: the block list type, including `tip`, the callout on Home and Commands. `quick_start.ts` writes it (`tip_block`) so its command line key follows the keymap, and `render.ts` adds the "Tip" label. It has no dismiss control. `tools/render_docs.ts` turns the guide's markdown subset into blocks at build time (it fails on any other markdown) and `tools/build.mjs` writes `dist/search_engines_guide.json`. `main.ts` fetches it.
- `render.ts`: draws the rows with DOM calls. Command text never goes through `innerHTML`. A `code_block` gets its own themed box with the fence language as a label and a Copy button. The command usage line keeps the plain `desertfox-help-usage` look. Each page gets a sidebar group: a link, a chevron button and a list of section links. `page_sections` builds the list for every page, and the headings take their ids from the same list. Going to a page opens its group, the others start closed, and each chevron toggles its own group. A toggled group keeps its state across renders, in memory only. `main.ts` scrolls to the section heading and focuses it. Search Engines lists the guide's `###` headings and "Your engines", and `main.ts` fetches the guide before the first render. If that fetch fails, only "Your engines" is listed.
- `native_install.ts`: the panel `:native.install` opens (`#native-install?<nonce>`, a new nonce each time so a tab already on the page sees a hash change and shows it again after Close). It sits outside the body, because the router rebuilds the body on each route. Its button asks for `nativeMessaging` and must stay inside the click handler, since Firefox grants an optional permission only from a click. It shows the `curl` command for this build's channel (`src/shared/native_host.ts`). `main.ts` only calls `mount_native_install`.
- `main.ts`: loads the inputs (`commands.json` through `shared/load_commands.ts`) and renders the route in the hash, and renders again on `hashchange`.
- `home.html`: the page and its styles. The defaults use the `--desertfox-` variables. It loads `content.js` by script tag, because `moz-extension://` pages do not match `<all_urls>`. That gives the page `j`, `k`, `gg` and the mode badge. `hints.js`, `whichkey.js`, `cmdline.js` and `caret.js` load the same way, for the Quick Start keys (`caret.js` also holds page search). `executeScript` cannot reach extension pages, so each bundle registers itself on load.
- The sidebar ends with a support card linking GitHub Sponsors and Ko-fi (`support_card` in `render.ts`).
- At 40rem or less the sidebar is a drawer (the `@media (max-width: 40rem)` block in `home.html`). `render_help` adds a top bar with a menu button and a backdrop, both hidden above the breakpoint, and `wire_drawer` opens and closes it. The open flag is a class on `.desertfox-help`, so each render starts closed. `main.ts` registers `close_drawer_on_escape` in the capture phase before `content.js` loads, so Escape closes the drawer and never reaches the key flow.

`STYLE_VARIABLES` and `STYLE_CLASSES` in `model.ts` list the public styling surface. The variables come from the theme role list, so a new role shows on the Styling page with a meaning the compiler forces you to write. Add a surface's class names there when it ships.
