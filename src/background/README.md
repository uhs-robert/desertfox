# background

The background page. It loads the config, compiles the keymap, assigns the Firefox shortcut slots and routes run requests.

- `main.ts`: registers the listeners, then waits for the config.
- `startup.ts`: load, compile, publish to `storage.local`, tell open tabs. The load runs once. `publish` runs again for each `set`, `toggle` and `unset` (`change_overrides`, one at a time) and replaces the config `get_config` returns.
- `config_load.ts` also holds the live setting overrides in `storage.session` (`load_overrides`, `load_effective_config` for pages that read the config themselves) and `build_config_status`.
- `config_load.ts`, `keymap_merge.ts`, `compile.ts`: managed config over imported config, default keymap under user keymap, and the args check per binding.
- `default_keymap.ts`: the shipped keys. `docs/keymap.md` is generated from this file. Keys that need the user's engines or containers are left to the config. A binding asks for input only through `prompt`, and one that leaves out a required param without it is skipped with a warning. A binding with `prompt` compiles to a background step, and the router opens the command line with it typed in.
- `slots.ts`: `browser` chords to the 10 manifest slots.
- `repeat_memory.ts`: the request `.` replays, in `storage.session`, one slot for normal windows and one for private windows, and the check on what a page script may record.
- `window_focus.ts`: the window ids in last-focused order, newest first, in `storage.session`. `tab.attach` with no window picks from it.
- `tab_modes.ts`: the mode each tab last reported, in `storage.local`, and the ignore-mode gate for Firefox shortcuts.
- `router.ts`: the one entry for run requests. A content step and the open command line each wait for the content script's answer: done goes on, failed stops with one toast, and cancelled (the user left the wait) stops with none and stores no repeat. A prompt or an empty `@selection` opens the command line with the printed command. A missing required param refuses. An empty `@selection` runs the command instead when `runs_with_empty` says it can on this page, as a search on a `{query|url}` engine can. The prefill uses short flags, for example `open -t `. Its pieces are `count.ts` and `refusal.ts`.
- `availability.ts`: the one check for "can this page fill what a thing needs?", shared by engines, snippets and which-key. A requirement is a list of slot expressions (`repo`, `host|title`). An engine with a fallback asks nothing. `requirement_lookup` reads the requirement of an invocation: the slots of the engine a search names, or the `requires` of a snippet. `available_engine_names` is for command line completion. `runs_with_empty` tells the router whether a search runs with no query on this page: its engine, or the fallback that runs in its place, fills the URL without one.
- `list_keys.ts`: answers which-key. Given a mode and a typed prefix, it walks the compiled keymap in `storage.local` and returns a title (the chain of group names, `["+Go", "+Close tabs"]`) and a row per next key: the command label and intent, or `+Name` for a longer sequence. Rows run letters, other plain keys, modifier keys, groups by name, then Escape. Given the active page, it first drops the keys the page cannot run (see `availability.ts`) and the groups left empty.
- `bundle_loader.ts`: injects a bundle into a frame when the content script asks, once per document. It joins repeat asks, answers a failure or a missed deadline with a refusal, and checks the bundle name because the sender is a page script.
- `load_log.ts`: the last 20 bundle loads in storage, which the key test reads. Writes run one at a time and a storage failure is dropped, so the log never fails a load. Pure.
- `snippets.ts`: the user's snippets as commands. `matches` and `requires` are checked here against the tab URL, the code runs in the top frame only, and `oasisfox.run` calls come back through the `snippet_run` message with the caller's depth (limit 5).
- `cmdline_service.ts`: what the command line page asks for. `issue_cmdline_ticket` gives the host a one-time ticket for its tab, kept in `storage.session`. `open_cmdline` takes that ticket once and returns the history, the engine and container lists, the registry's commands (snippets included), the configured aliases and the user CSS, and `record_cmdline` adds a parsed line to the history (last 100, newest last, a repeat moves to the end, nothing from a private tab). Redeeming a ticket also marks the tab as an opener in `storage.session`. Tab close and the start of a navigation remove the marker.
- `open_help.ts`: `open_help` opens the help page at a command card in a foreground tab beside the asking tab, only for a tab whose line redeemed a ticket. An id without a card (a snippet or unknown id) opens the Commands page at its top.
- `complete_items.ts`: `complete_items` answers the command line page with the open tabs, the bookmarks or the engines it lists for `tab`, `bookmark` and `search`. The engines come in config order, each with its label and a yes or no for whether the line's tab page can fill it (`available_engine_names`). The page URL stays in the background. It answers only an opener tab, checks the marker again after the browser call, lists only tabs of the line's privacy, and gives an empty list when the browser call fails. The tab handler lists through the same code. `set_tab_unloaded` (the row key of the list) unloads or loads one tab of the sender's privacy through `tab_discard.ts` and answers the row as it is now, with the address and title read before the change.
- `first_install.ts`: opens the help page at Quick Start when `runtime.onInstalled` gives reason `install` and `open_quick_start_on_install` is not false. Nothing else opens it.
- `tab_discard.ts`: the one place that calls `tabs.discard`. `set_unloaded(deps, ids, unloaded, { leave_active })` skips audible tabs, the active tab of any window (except `leave_active`, which switches to the alternate, else the next, else the previous loaded tab first) and tabs already in the target state. It re-reads `discarded` after each discard, because Firefox does nothing for the active tab or a privileged page and never rejects. Load uses `tabs.reload`, which keeps scroll and form data and does not activate the tab. Returns what changed and a reason for each skip. `tab.unload`, `tab.load` and the list row key all go through it.
- `reload.ts`: the marker and the tab repair behind `config.reload`.
- `browser_deps.ts`: the only file that wires the router to Firefox calls.
- `command_modules.ts`: one import per command group. The commands.json build tool imports it, so it is the only list.

Everything except `browser_deps.ts` and `startup.ts` takes its browser access as arguments, so tests run without a browser.
