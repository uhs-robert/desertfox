# background

The background page. It loads the config, compiles the keymap, assigns the Firefox shortcut slots and routes run requests.

- `main.ts`: registers the listeners, then waits for the config.
- `startup.ts`: load, compile, publish to `storage.local`, tell open tabs. `publish` runs again for each `set`, `toggle` and `unset` (`change_edits`) and for each `config.reload` (`reload_config`) and import (`import_config`), one at a time in one queue, and replaces the config `get_config` returns. A reload and an import share one swap, `apply_files`: it replaces the snippets and the stored files config too, and puts all of it back when a step fails. While it swaps, `get_config` waits for the commit, so no command runs against half of it. A change to the saved edits goes to `autoconfig_mirror.ts`.
- `config_load.ts` also checks the file's settings against `SETTING_SPECS` and holds the browser edits: saved in `storage.local`, temp in `storage.session` (`load_edits`, `store_edits`, `load_effective_config` for pages that read the config themselves). It also holds `build_config_status`.
- `config_load.ts`, `keymap_merge.ts`, `compile.ts`: the files config `config.reload` stored, default keymap under user keymap, and the args check per binding.
- `default_keymap.ts`: the shipped keys. `docs/keymap.md` is generated from this file. Keys that need the user's engines or containers are left to the config. A binding asks for input only through `prompt`, and one that leaves out a required param without it is skipped with a warning. The exception is a required `key` param: `compile.ts` stores the step on the background side with `capture` set and moves its leaf under a branch with the child `ANY_KEY`, and the key press fills the param. A binding with `prompt` compiles to a background step, and the router opens the command line with it typed in.
- `default_site_rows.ts`: the site rows that ship with DesertFox, each with a name (`sheets` is two rows, one per Sheets address form, that bind hjkl, `gg`, the `G` chain, `<C-h/j/k/l>`, `x`, `y` and `p`, add the `visual` site mode behind `v` and `V` (the same keys with Shift held, and `x`, `y` and `p` that end it), pass `<C-a>`, `<C-x>` and `<C-v>`, and drop the parked cell editor from the fields with `editable_remove`). `compile_config` appends the rows the `default_site_rows_off` setting leaves on after the user's rows, so a user row decides each column first and `bind` merges key by key. A row whose command the registry lacks is left out without a warning.
- `toolbar.ts`: the on/off switch. `create_toolbar` writes the flag (`DISABLED_STORAGE_KEY`), republishes, sets the icon and title, then sends every tab to normal mode on off, and on on the content script enters ignore mode again from the stored tree, on a page that `site_rules` turns off. Changes run one at a time, so the popup and the `toggle_enabled` shortcut never race. While off, `publish` stores `OFF_KEYMAP` (no modes, badge off) instead of the compiled tree, and the keymap carries `off`, the one flag the page reads (a lone keyup then passes). The router refuses every run and `shortcut_allowed` refuses every slot while off. The toggle is not a slot: `main.ts` handles its command before the slot table. `answer_toolbar_request` serves the popup's three messages (extension pages only). `site_pattern`, `site_state`, `describe_columns` and `plan_site_edit` hold the Disable on this site rules over `site_rules`.
- `omnibox.ts`: the `df` address bar keyword. `create_omnibox` takes the text of Enter, parses it with the command line grammar and runs it through the router, so the one validator checks the args. It never prompts: a command with a missing value refuses with its usage, and so does text that is no command. A modified Enter (new tab, background tab) sets `where` on a command that has the param. `changed` answers `onInputChanged` with up to nine rows from the command line completer (`create_completer`, no live source, so no history rows in any window) and drops an answer that a newer keystroke passed. A parsed line goes into the command line history, except from a private window. `main.ts` wires it only when `browser.omnibox` exists.
- `slots.ts`: `browser` chords to the 10 manifest slots.
- `repeat_memory.ts`: the request `.` replays, in `storage.session`, one slot for normal windows and one for private windows. A load waits for tracked writes, and the private slot is cleared when the last private window closes.
- `record_step.ts`: `record_step(steps, outcome, origin)`, the one call every finished request or leaf passes. It fills the `.` slot with the repeatable steps of a plain success. `page_steps` and `page_outcome` check what a page script sends.
- `macro_recorder.ts`: the macro being recorded, in `storage.session` (a private key for private windows). It reads the `record_step` call beside `.`, takes every step including failed ones, and tells every tab to read its keymap again when a recording starts or stops. `macro.record` and `macro.stop` drive it.
- `window_focus.ts`: the window ids in last-focused order, newest first, in `storage.session`. `tab.attach` with no window picks from it.
- `tab_media.ts`: the media mode of a tab, in `storage.session`: the frames that reported it and the frame whose video `;M` pinned. The first report of media starts it in every frame of the tab (a `MediaStep` on). A frame of the hold that reports a mode other than media, hint or command line ends it for every frame (a `MediaStep` off to the others), and so does a new page load. An address change the page makes keeps it and drops the pin. `media enter` starts it. `join` lets a frame that starts late (first focus) into the hold, through the reply to its first keymap read.
- `tab_modes.ts`: the mode of each tab, in `storage.local`: the mode of the child frame whose document holds the focus, else the top frame's. Ignore mode in the top frame beats a focused child frame. Reports and navigations run one at a time, and a report that changes nothing writes nothing. The start of a load forgets the mode, and so does the new page taking over, but not an address change the page makes itself. It also holds the insert hold of `tab_insert.ts` and the ignore-mode gate for Firefox shortcuts.
- `router.ts`: the one entry for run requests. It first refuses a count prefix over a command's `repeat_limit`, over all steps before any runs. A content step and the open command line each wait for the content script's answer: done goes on, failed stops with one toast, and cancelled (the user left the wait) stops with none and stores no repeat. Every request ends in `record_step`. A prompt or an empty `@selection` opens the command line with the printed command. A missing required param refuses. An empty `@selection` runs the command instead when `runs_with_empty` says it can on this page, as a search on a `{query|url}` engine can. A source can carry `then`, read when the first gives nothing (`search` reads the selection, then `@search_query`). The prefill uses short flags, for example `open -t `. For a command with the `jumps` flag it reads the top frame's scroll offset first (`read_offset`, capped at 1 s) and puts the place in the jump list after the command succeeded (`record_jump`). Its pieces are `count.ts` and `refusal.ts`.
- `availability.ts`: the one check for "can this page fill what a thing needs?", shared by engines, snippets and which-key. A requirement is a list of slot expressions (`repo`, `host|title`). An engine with a fallback asks nothing. `requirement_lookup` reads the requirement of an invocation: the slots of the engine a search names, or the `requires` of a snippet. `site_engine_for` picks the engine of a `site_keys` key for a page (host in the engine's `hosts`, slots fillable), `with_site_engines` settles it before a run and names the letter when the page fits none, and `available_engine_names` is for command line completion. `runs_with_empty` tells the router whether a search runs with no query on this page: its engine, or the fallback that runs in its place, fills the URL without one.
- `macro_last_played.ts`: the register `@@` plays, in `storage.session` (a private key for private windows, cleared with the last private window).
- `macro_replay.ts`: plays a macro for `macro.play` (a count runs it that many times in one replay, `@` names the last register played, at most 10000 passes per play), one router request per step, with the page-ready wait after a navigation or tab switch, nested `@a` up to 10 levels, and Escape (`replay_stop`). It sends `replay_hold` to each tab it reaches and answers `replay_end` when the outermost replay ends. It lives in memory only: held pages drop their keys when the background is gone. `main.ts` wires it in, and a `run` from a tab the replay is not in waits for its end.
- `site_rules_view.ts`: what the site table does to one address, for the help page's Site Rules view. `site_rules_view` lists the stored rows that fit the address in table order (`site_rules_matching`), with each row's origin, name and pattern, the columns it sets as name and value pairs (so a new per-site setting shows with no code), and the keys it changes with what the key does without the row. A column or key an earlier row already decides is marked shadowed, found with `resolve_site_columns` over the earlier rows, so there is no second matching path.
- `strip_patterns.ts`: answers `read_strip_patterns` and resolves `copy.tabs` per tab. The global `strip_tracking_params` list when the address's `strip_tracking` resolves on (`site_value`), else an empty list.
- `page_keymap.ts`: answers `read_keymap`. It reads the stored keymap, resolves the site table columns for the sender (`rule_addresses_of`, `site_columns_for`, `normal_tree_for`, shared with `list_keys.ts`), trims the normal tree and replies with the `PageKeymap` as a JSON string. While a macro records it also swaps the record key for `macro.stop` and adds the register name. `site_value` gives a per-site setting's value, which beats the global one (`site_zoom.ts` uses it). `top_frame_address_of` gives the top frame's address for a tab-wide value asked by a frame. `frame_site_values_for` resolves the named settings that act inside one frame against the frame's own address: `blur_on_load` and `escape_to_page` go into the reply as `site_values`, and `hint_selectors_reply` answers the hints bundle's `read_hint_selectors` with `hint_add` and `hint_remove`. It grafts the merged `bind` column onto the normal tree (`graft_binds`) before `pass` and `only` prune it, and `off` skips the graft.
- `site_zoom.ts`: the `zoom` setting. On a tab's load it resolves the level for the tab's address (the site value, else the global one) and calls `tabs.setZoom` the first time the host gets that level in the browser session. The levels set per host sit in `storage.session`, the private windows apart, so Firefox's per-host memory carries a manual zoom to later tabs. A tab that moved on before the set is skipped, so another site's zoom memory stays.
- `list_keys.ts`: answers which-key. Given a mode and a typed prefix, it walks the compiled keymap in `storage.local` and returns a title (the chain of group names, `["+Go", "+Close tabs"]`) and a row per next key: the command label and intent, or `+Name` for a longer sequence. A capture leaf shows as a `<key>` row, except under `mark.add` and `mark.jump`, where a page with marks lists them with their offsets (the caller passes them). The prefix `"` is no key of the tree, so it lists the stored registers instead (the caller passes their rows). Rows run letters, other plain keys, modifier keys, groups by name, then Escape. Given the active page, it first applies the page's `site_rules` key rule to the normal tree, then drops the keys the page cannot run, including a `site_keys` key with no engine for the page (see `availability.ts`) and the groups left empty.
- `bundle_loader.ts`: injects a bundle into a frame when the content script asks, once per document. It joins repeat asks, answers a failure or a missed deadline with a refusal, and checks the bundle name because the sender is a page script.
- `selection_ask.ts`: reads the selection of a frame for a `selection` context source, and the scroll offset of the top frame for a command with the `jumps` flag. The `page` bundle answers `get_selection` and `get_jump_offset` (the offset with the page's own address, so the router records nothing when another page answered), so on no answer it injects `page.js` into the frame and asks again.
- `issue_report.ts`: the body and the URL of the `:issue` report. Pure. The form body has the versions, the system and the warning count. The copy body adds the warnings word for word, at most 10 and 2 KB with a count of the cut ones, and replaces the config folder path in them with `<config dir>`.
- `load_log.ts`: the last 20 bundle loads in storage, which the key test reads. Writes run one at a time and a storage failure is dropped, so the log never fails a load. Pure.
- `timing_log.ts`, `timing_summary.ts`, `timing_browser.ts`: the last 300 timings in `storage.session` (command round trips from `router.ts`, `hint.build` from the `hints` bundle through the `record_timing` message), and the pure count, median, p95 and max per name that `debug.perf` copies. The bundle loads come from `load_log.ts` at read time. A tick of records is one write, writes run one at a time and a storage failure is dropped.
- `snippets.ts`: the user's snippets as commands. `matches` and `requires` are checked here against the tab URL, the code runs in the top frame only, and `desertfox.run` calls come back through the `snippet_run` message with the caller's depth (limit 5).
- `cmdline_service.ts`: what the command line page asks for. `issue_cmdline_ticket` gives the host a one-time ticket for its tab, kept in `storage.session`. `open_cmdline` takes that ticket once and returns the line tab's window id, the all-windows setting, the history, the engine and container lists, the registry's commands (snippets included), the configured aliases and the user CSS, and `record_cmdline` adds a parsed line to the history (last 100, newest last, a repeat moves to the end, nothing from a private tab). Redeeming a ticket also marks the tab as an opener in `storage.session`, with the redeeming frame's id as the value, so only that frame is an opener (`is_opener(tab, frame)`) and the next line replaces it. Tab close and the start of a navigation remove the marker.
- `open_help.ts`: `open_help` opens the help page at a command card in a foreground tab beside the asking tab, only for the frame whose line redeemed a ticket. An id without a card (a snippet or unknown id) opens the Commands page at its top.
- `settings_message.ts`: the settings page's messages `change_setting` and `list_settings`. A change takes a typed value, runs the setting's check and goes through the same planners and `change_edits` queue as `:set`. Only a top-level extension page may send them.
- `session_store.ts`: the saved tab sessions in `storage.local` (`desertfox_sessions`): a name store with `save`, `get`, `rename`, `remove` and `list`, serialized so concurrent changes do not lose one, plus `plan_restore`, which marks the one tab that loads and finds each container by id then name. `export_json` and `import_json` serve the settings page (a taken name keeps both, the import gets a ` (2)` suffix, names pass `NEW_NAME_PATTERN`, which `session.save` also uses). `commands/session.ts` does the browser calls.
- `store_turns.ts`: what the register and mark stores share. `create_write_queue` runs their writes one at a time. `wire_private_cleanup` puts one `windows.onRemoved` listener (and one run at start) over every store, dropping private data when no private window is open.
- `external_editor.ts`: the external editor job of each tab. `open` starts it through `native_client.ts` (`editor_start`), keeps `{ job, token, frame_id }` in `storage.session` and loops `editor_collect`. `orphan` marks a tab's jobs when the tab closes or loads: the loop goes on and the result goes to the unnamed register (`save_text`), as it does when the frame does not take it. `resume` restarts the loops after a background restart. `make_editor_ext_for` resolves the per-site `editor_ext`.
- `mark_store.ts`: the local marks, per page address (the URL without the hash). The background owns them and a tab reaches them by message (`mark_set`, and `mark_jump`, which answers the stored offset and keeps the offset it left under `'` in the same turn). A normal window keeps them in `storage.local` (`MARK_STORAGE_KEY`), a private one in `storage.session` (`MARK_PRIVATE_STORAGE_KEY`), cleared as for registers. One value holds all pages, written one at a time, at most 500 pages and 2048 characters per address. The names and limits are in `src/shared/mark_names.ts`. `list_keys.ts` lists the page's marks and the global ones through `items`, `remove` drops one mark for `mark.delete`, and `clear` (in the same write queue) drops this page's marks with its `'` slot and every global mark, or every page and every global mark, for `mark.clear`. Both refuse when nothing is there to drop. Quickmarks stay. `quickmark_store.ts` has `remove` for `quickmark.delete`. `mark.list` and `quickmark.list` (`commands/mark_list.ts`, `commands/quickmark.ts`) feed the `marks` and `quickmarks` completion sources in `complete_items.ts`. An uppercase key is a global mark: the store keeps `{ url, x, y }` in an optional `globals` field, and `answer_mark_request` sets one only from a top frame on an http or https tab, with the tab's address.
- `quickmark_store.ts`: the quickmarks `M` saved, in `storage.local` (`desertfox_quickmarks`), or `storage.session` for a private window. `table` lays them over the config table, and a private window reads both areas.
- `global_mark_jump.ts`: the jump of a global mark. `find_mark_tab` picks the tab (the sender, its window by newest access, other windows, same privacy, hash ignored). The jump answers at once, then `arrive` waits for the page and pushes `mark.jump` into its top frame. An `arrivals` entry per tab lets that second jump scroll without looking at the address, so a redirect cannot loop. The push carries the entry's number and the page sends it back, so a late request of a superseded jump does nothing.
- `jump_store.ts`: the jump list, one list and cursor per window id, in `storage.session` (`JUMP_STORAGE_KEY`, and `JUMP_PRIVATE_STORAGE_KEY` for private windows, cleared as for marks). Every change reads, edits and writes inside one `create_write_queue` turn, so two fast `<C-o>` presses see each other's cursor. `push` records a place and drops the entries after the cursor, `step` moves the cursor and answers the entry (a step back from the present adds the place you are on first), `forget_window` drops a closed window's list, `hold_leaving` keeps the offset a page left, `mark_step` notes the page a jump step navigates away from, and `settle_leaving` judges the held offset in one turn. Names and limits are in `src/shared/jump_names.ts`.
- `jump_leave.ts`: records the place a page leaves when its tab goes to another page. The leave watch of the `page` and `hints` bundles sends `jump_leave` with the address the page shows as it hides (the sender's address stays the one the document loaded at after a `pushState`) and the store holds it (`hold_leaving`). The report, each address change and each end of a load judge the held offset against the tab as it is then, so the order of the events does not matter. A reload, a hash change, a redirect after the first change and a step of the list push nothing.
- `jump_step.ts`: answers `jump_push` and `jump_step`. A push records the address it names (the page a single-page app left in place), refuses another site's address and records nothing while a step is arriving in the tab. A step to the page you are on answers the offset. A step to another address goes through `address_arrival.ts` and pushes `page.jump` into the top frame of the target tab, which asks again and gets the entry the step chose.
- `page_ready.ts`: `watch_page_ready(deps, tab_id)` waits for a tab to complete and its content script to answer, in at most 10 s: `ready`, `timeout`, `gone` or `no_script`. Start it before the step that navigates.
- `register_store.ts`: the registers. The background owns them and every tab reaches them by message (`register_read`, `register_write`, and `register_yank`, which fills the unnamed register and the named one), so no page holds a copy that can go stale. A value is text or a `BoundInvocation[]`. Names come from `src/shared/register_names.ts` (`a-z`, `A-Z` appends to the lowercase register, `"`, `+` the clipboard, `_` the black hole, `/` and `/:direction` the last search). A normal window keeps them in `storage.local` (`REGISTER_STORAGE_PREFIX`). A private window keeps its own in `storage.session` (`REGISTER_PRIVATE_STORAGE_PREFIX`), apart from the normal ones, and `wire_private_cleanup` drops them when `windows.onRemoved` leaves no private window, and at start. Writes run one at a time, so two appends do not lose one. `commands/register.ts` holds `:registers`. Password text is never written here: the callers that read a field (the macro work) check the field first. No yank reads a field's live text, so none does yet.
- `sessions_transfer.ts`: answers the page messages `export_sessions` and `import_sessions` from the session store.
- `history_cache.ts`: the 8000 newest history rows, newest first, kept for history completion. It fills from `history.search` at each start of the background (the browser history is the truth, so nothing is stored). It applies `onVisited`, `onTitleChanged` and `onVisitRemoved` from `main.ts`, and holds events that arrive during the fill until it ends. An address it has not seen enters only after a one-row `history.search` lists it, because `onVisited` also fires for hidden pages (redirect sources, framed links). Firefox sends no event when only some visits of a page go, so a page can keep a too-new last visit until the next start. Under a future event page the first line after a wake gets the fallback. Before the fill ends `read` gives nothing and `complete_items.ts` searches 1000 rows instead. It holds only normal visits, because Firefox fires no event for a private one.
- `complete_items.ts`: `complete_items` answers the command line page with the bookmarks (one row per address with indexes into the folder paths, sent once), history rows, open rows, windows, bookmark folders, sessions (none for a private line), registers (those of the line's privacy) or engines it lists for `bookmark`, `history`, `open`, `tab.attach` and `search`. The `tab` list does not ask: it reads the tab model. The engines come in config order, each with its label and a yes or no for whether the line's tab page can fill it (`available_engine_names`). The page URL stays in the background. It answers only an opener tab, checks the marker again after the browser call, lists only tabs of the line's privacy, and gives an empty list when the browser call fails. The tab handler lists through the same code. Each history, bookmark, quickmark, closed-tab and tab row carries a use boost (`usage_boost`: visit count and last visit, joined by address), and `open` and the finder also get the visited hosts as site rows (`site_items`), so the page ranks by use without reading visits itself. `tab_rows_action` (the row keys of the list) closes, mutes, pins, unloads or loads the tab ids the page captured at the key press, through `tab_actions.ts` and `tab_discard.ts`. It skips ids with no tab and refuses the whole message when one id is a tab of the other privacy. `reopen` also takes a store id and reopens the tabs through `reopen_tabs_in_container`: it leaves out the line's own tab and tabs already in that container, skips a tab that fails and goes on, and refuses a private line or an unknown store id. The answer holds only a refusal text, which for a reopen names what moved and what stayed.
- `first_install.ts`: opens the help page at Quick Start when `runtime.onInstalled` gives reason `install`. Nothing else opens it.
- `tab_discard.ts`: the one place that calls `tabs.discard`. `set_unloaded(deps, ids, unloaded, { leave_active })` skips audible tabs, the active tab of any window (except `leave_active`, which switches to the alternate, else the next, else the previous loaded tab first) and tabs already in the target state. It re-reads `discarded` after each discard, because Firefox does nothing for the active tab or a privileged page and never rejects. Load uses `tabs.reload`, which keeps scroll and form data and does not activate the tab. Returns what changed and a reason for each skip. `tab.unload`, `tab.load` and the list row key all go through it.
- `media_actions.ts`: the `media` command across frames. It lists the frames, injects `media.js` into each, asks each to scan, picks the frames that act (`choose_frames`: every frame with media that plays with sound, else with any playing media, else the largest visible video) and words the one notice or refusal. A frame that refuses the script, times out or answers nothing counts as one without media. `quality` and `skip` skip the scan: each frame reports its player and the request goes to one chosen frame. Browser calls come in through `MediaDeps`.
- `media_quality.ts`: the `media_quality` rule. `tab_updated` turns a changed address (a navigation) or a finished load into one injection of `quality.js` plus a `quality_rule` message to every frame. The newest update of a tab decides, and an earlier one that is superseded sends nothing but hands its `navigated` flag on. The frame answers `read_media_quality` through `media_quality_reply` in `page_keymap.ts`.
- `quality_levels.ts`: the `quality` bundle seen from the background. `ask_quality` injects `quality.js`, collects each frame's report, picks one player (`choose_player`) and sends the request to that frame alone, and `quality_rows` makes the completion rows of `media quality ` (the fixed words, then the levels).
- `tab_actions.ts`: the one place that mutes, pins, moves and reopens tabs in a container, each over a list of ids. `tab.pin`, `tab.mute`, `tab.move` and `tab.reopen_in_container` call it with one id. Reopen handles one tab at a time in tab bar order, opening the new tab where the old one was and then closing the old one, so a failed open leaves no duplicate. It leaves a tab with no address open. `reopen_tabs_in_container` is the tab list's version: each tab settles alone and no new tab becomes active, so the line stays open. `group_tabs`, `ungroup_tabs` and `set_group` put tabs in native tab groups through `GroupDeps`, and refuse a pinned tab or tabs of several windows.
- `native_client.ts`: the client for the native host. `create_native_client(deps)` gives `read_config` and `write_autoconfig`, each one `sendNativeMessage` behind a permission check. Every failure is a `NativeHostError` (`no_permission`, `host_missing`, `host_failed`, `bad_reply`) whose message says what to do. `config.reload` and the autoconfig mirror call it.
- `host_update.ts`, `host_update_browser.ts`: the host updater. A host older than the extension (from the `release_version` in a config host reply or the bridge `ready` frame) is replaced through `self_update` (the background also sends one `read_config` at start, so a host is checked with the bridge off), with the hashes of the signed build (`host_sha256.json`). It needs `host_auto_update` consent, else shows a line that names `:native.update`. One attempt per version per 24 h, one failure toast per version, a block on a checksum mismatch. An ok update reconnects the bridge. See design.md, "Host updates".
- `bridge.ts`, `bridge_browser.ts`, `bridge_run.ts`: publish the mode to the bridge host (`desertfox_bridge`) over one `connectNative` port and answer its `run`, `list` and `theme` requests (`theme` stores the palette the desktop pushed, see `set_desktop_palette` in `startup.ts`, and only a built-in theme name passes), when the `bridge` setting is on and the `nativeMessaging` permission is granted. `bridge.ts` holds the logic with injected browser calls, `bridge_browser.ts` wires it to the browser and registers the listeners. The port counts as up only after the host's ready message, and a drop reconnects with a growing pause. A private window sends its mode and `private: true` and no id. The in-page badge and which-key panel are not affected. `bridge_run.ts` is the one path for a run from outside: parse, the command's `bridge` field and the hard-coded never-list, the one validator, a private-window check, then a router of its own that targets the focused normal window, or the normal-window tab a `tab_id` names, and records nothing for `.` or macros. It answers success or a refusal text, never data. `tab_switch.ts` holds the tab verbs (`tabs`, `activate`, `clear_preface`, `close`, `capture`, and `favicon`, which only the host asks for). Every one starts from `normal_tab`, which refuses a private-window tab with the text of a missing id, and `bridge.ts` answers them (and a `run` with a `tab_id`) only while `bridge_share_tabs` is on. `bridge_events.ts` builds the tab events the host streams to subscribers (activated, title and address, audible, removed, and `tabs_off`), gated by `bridge_share_tabs` and `normal_tab`, with title and address changes of a tab settled over 250 ms.
- `reload.ts`: the marker and the tab repair behind `debug.restart`.
- `config_reload.ts`: the pure build behind every swap: raw files to the slot to store and the config to run, and every refusal as a `ConfigRefusal` whose message names the cause and the fix. Apart from `config_load.ts` because the build pulls in `smol-toml`, and the help and new tab pages import `config_load.ts`.
- `config_import.ts`: the pure part of an import from the settings page. `read_import_source` reads the zip or folder through the zip guards, drops one shared top folder and refuses an empty result. `preview_import` lists the config files and each snippet's code, `matches` and `requires`, and the build problems, storing nothing. `checked_consent` keeps only the snippets accepted with their exact code, and `plan_import_files` puts the import's config files over the slot's, keeping the installed snippets. `answer_config_import` answers the `preview_config_import` and `commit_config_import` messages.
- `config_transfer.ts`: the settings page's export, snippet list and snippet removal. `export_files` splits the slot's files into the config files and the snippets, and adds the saved browser edits as `settings.toml` (as a file of `settings.d` that sorts after every file there, when the config has settings files of its own). `installed_snippets` parses each installed snippet's header. `answer_config_transfer` answers `export_config`, `list_snippets` and `remove_snippet`. A removal runs through `apply_files` in the change queue, so a key that binds the snippet refuses it.
- `autoconfig_mirror.ts`: writes the saved edits to `autoconfig.toml` through the host, one write at a time. A failure never reaches the edit. It warns once per kind of failure, and not at all without the permission.
- `hint_frames.ts`: one label set across the frames of a tab, for `hint --all-frames`. The keyboard frame starts a session (`hint_frames_start`), the background injects the hints bundle into every frame that takes scripts, waits `HINT_FRAMES_WAIT_MS` (500 ms) for each frame's candidate count, and `assign_labels` hands out one prefix-free set, the top frame first. A frame that reports late gets no labels and no redraw. The keyboard frame sends its typed prefix and its pick here, and this relays them to the frames that own the labels. The session sits in `storage.session` (`HINT_FRAMES_STORAGE_PREFIX`), the wait only in memory, and nothing on the wait awaits a browser call, because a navigating frame can leave one unanswered. Browser calls come in through `HintFramesDeps`.
- `inspect_relay.ts`: hands a hint pick (`inspect_pick` from the `hints` bundle) to the devtools page of the picked tab. The ports sit in a map by tab id, rebuilt when the devtools pages reconnect. With no port the tab id and the pick time wait in `storage.session` (`INSPECT_PENDING_STORAGE_KEY`), and the answer is `{ ok: true, waiting: true }`. The hints bundle then shows the "press F12" notice and answers ok, so a key sequence goes on. The pick goes out when the page connects. It is dropped after 60 s, on navigation (`tabs.onUpdated` loading) and when the tab closes. Only a port named `devtools_inspect` from the extension's own `devtools.html` registers.
- `find_scan.ts`: answers `find_scan` from the `caret` bundle. Each regex page search runs in a fresh Worker (`find_worker.ts`, its own `find_worker.js` build entry), which is stopped after 300 ms with a `timeout` answer. A newer scan from the same frame stops the older one at once (`superseded`). `regex_scan.ts` is the scan itself, pure, so tests run it without a Worker.
- `image_actions.ts`: answers `image_action` from the `hints` bundle. A copy fetches the address (cookies only for a default-container normal tab, 20 s timeout, 20 MB cap enforced while reading), sniffs the type from the first bytes and puts a PNG or JPEG on the clipboard, converting other types to PNG first. A download passes the address to `downloads.download` with the sender tab's `incognito` and `cookieStoreId`, buffering nothing. Every failure is an `Outcome` with a message, and the clipboard changes only in the last step. Browser calls come in through `ImageDeps` (wired in `browser_deps.ts`), so tests use fakes.
- `browser_deps.ts`: the only file that wires the router to Firefox calls.
- `tab_model.ts`: the live tab model (rows also carry `group_id`, and a groups table follows the `tabGroups` events). One map of tab rows (with the `site_key` of each URL) built from one `tabs.query` and kept current from tab events, nothing stored. Changes batch on a 30 ms flush and go out on the port `desertfox_tab_model` as a snapshot, then patches (`rev` counts per port, `resync` asks for a new snapshot). Rows also carry the window number (as `numbered_windows` counts), the previous tab (seeded from `previous_tab.ts`, then followed from `onActivated`) and the container name, color and icon, re-read on window and container events. A port sees only tabs of its own privacy (the sender tab's, else the `:normal` or `:private` suffix of the port name from `src/shared/tab_model_port.ts`, else no rows) and only an extension page may connect. A web-accessible page (`cmdline.html`) must also be the opener frame of its tab (`is_opener`), because a web page can frame it. Other extension pages cannot be framed and skip the check. A detach reads as a removal until the attach. Events during the startup query force a second query. A `resync` and each new port re-read tabs, windows and containers and patch the difference, retrying when an event arrives meanwhile.
- `command_modules.ts`: one import per command group. The commands.json build tool imports it, so it is the only list.

Everything except `browser_deps.ts` and `startup.ts` takes its browser access as arguments, so tests run without a browser.
