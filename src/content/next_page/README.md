# next_page

The `next_page` bundle (`next_page.js`, its own guard in `tools/build.mjs`): the `page.follow` handler of `]]` and `[[`. The content script loads it on the first press. It borrows the collect walk, the presence test and the click from `../hints/`, but does not load the hints bundle.

- `detect.ts`: the detector. It reads the page only through a `PageReader` (boxes in page coordinates, hidden, sideways scroller, fixed or sticky), so it is pure: `follow_links.ts` passes real elements and the suite in `test/fixtures/next_page/` passes saved ones. It answers what to do (`follow`, `click`, `scroll` or `none`) and does nothing itself. `detect_next_page` takes the first `rel` link, else the best next word (`rank_by_text`: a whole-word match in a text of at most five words, then an earlier pattern, a link over a button, the shorter text), passing over a control in a carousel or sideways scroller, in a media player (a box of at most one screen that holds a video) or inside one item of a repeated list (not past a `nav`, and an item of at most two screens). With nothing found, it runs the load step it is given.
- `load_more.ts`: the load step. It finds the main list (the repeated block of three or more stacked items with the most area, outside page chrome, carousels and fixed boxes) and takes the nearest lone control just below its last item: one whose text is a load word (`is_load_text`, the whole text or the word and one noun, in nine languages), else a plain button within 300 px. It never takes a toggle, a control inside an item or one in a branch of more than three controls. With no control, it answers `scroll` with the last item, but only when the list ends within half a screen of the page end, so an article or a front page does not jump.
- `follow_links.ts`: the live side. `find_next_page` gathers the `rel` links, the present links and buttons (off-screen ones count) across shadow roots and same-origin frames, and `dom_reader` reads real elements for the detector.
- `load_outcome.ts`: `wait_for_new_content` answers whether the page added an element (not a script, style or our own layer) or grew within 3 s.
- `item_after_load.ts`: after a load, moves the `page.item` box to the first item that follows the last old item still on the page (`first_item_after`), never by the old count, since a page that virtualizes drops items above. It reads and moves the box through the item bundle's `item.cursor` handler, and leaves the box when the user moved it or left normal mode during the wait.
- `main.ts`: the handler. It reads `next_patterns` or `prev_patterns` from the stored config status. A `follow` opens like a hint of the same place (`follow_like_a_hint`), and a `<link>` navigates by its address. Only `]]` in place runs the load step. After a `click` or a `scroll` the answer comes at once, and a toast says "Nothing loaded" when the wait finds nothing. The item bundle is asked for its cursor only when it has loaded, so `]]` never loads it. Not unit tested, it needs a DOM.
