# item

The `item` bundle (`item.js`, its own guard in `tools/build.mjs`): the handler of `page.item`, which the shipped `google`, `bing`, `hackernews` and `wikipedia` site rows (and `google_images` and `ddg_images`, which also bind `h` and `l`) (and a user row) bind to `j` and `k` on result pages. It loads on the first press. It lives apart from `site_actions` because the move and the box together are over that bundle's size limit.

- `pick.ts`: the pure picks and the handler. `step_from` takes the nearest item ahead (distance along the direction plus an eighth of the distance across it), looking at other rows for down and up and at the same row for left and right. `pick_item` applies a count and clamps. `place_of` finds the start: the item that holds the focus, else the last item moved to while it is on screen, else the first item not above the view. `move_item` reads the items fresh (with none found it scrolls the page by 50 px per count instead, like the plain keys, and down and up scroll the same way while the current item runs past the view edge and at the last item) (a visibility and size filter of its own, not the hint collector), moves the focus with `preventScroll`, scrolls the item to the centre when it is not fully in view, gives a non-focusable item `tabindex="-1"`, and asks for the box. A selector the browser cannot parse throws its own error. The page, the view and the callbacks are parameters, so a test passes fakes. It holds one weak reference to the last item.
- `overlay.ts`: the box around the item, in a closed shadow root on the root element with the colours of the hint labels as var() fallbacks. It follows scroll and resize with `follow_windows` from the hints folder, and clears on a `focusout` that leaves the item, on a 100 ms timer that finds the mode is no longer normal or the item gone (the same tick puts the box back on an item a layout shift moved), and never needs a stop call from the handler. It does not use `create_surface`, because that pulls the theme and storage code into the bundle: so no user theme and no top layer.
- `main.ts`: registers the handler with the host. Not unit tested, it needs a DOM.

Tests: `test/site_item.test.ts` (picks, the handler on fakes) and `test/key/p44_item_rows.mjs` (the shipped google row on a stand-in page: movement, Enter, counts, and the box through scroll, resize, blur, Escape, a mode change and a removed item).
