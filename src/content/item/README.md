# item

The `item` bundle (`item.js`, its own guard in `tools/build.mjs`): the handler of `page.item`, which the shipped result-page site rows (`ddg`, `ddg_news`, `google`, `google_videos`, `bing`, `hackernews`, `wikipedia`, `lobsters`, `archwiki`, `startpage`, `arxiv`, `stackoverflow`, `tildes` and `reddit`) (and a user row) bind to `j` and `k` on result pages. The `google_images`, `google_news`, `google_short_videos`, `google_shopping`, `ddg_images` and `ddg_videos` rows also bind `h` and `l` on their grids. It loads on the first press. It lives apart from `site_actions` because the move and the box together are over that bundle's size limit.

- `pick.ts`: the pure picks and the handler. `step_from` takes the nearest item ahead (items whose span across overlaps the current one come first: the nearest one sets the row or column, then the largest overlap across wins, else the smallest gap across), looking at other rows for down and up and at any item that overlaps in height for left and right. `pick_item` applies a count and clamps. `place_of` finds the start: the item that holds the focus, else the last item moved to while it is on screen, else the first item not above the view. `move_item` reads the items fresh (with none found it scrolls the page by 50 px per count instead, like the plain keys, and down and up scroll the same way while the current item runs past the view edge and at the last item) (a visibility and size filter of its own, not the hint collector), moves the focus with `preventScroll`, scrolls the item to the centre when it is not fully in view, gives a non-focusable item `tabindex="-1"`, and asks for the box. A down or up that only scrolls a long item draws the box on it again. A selector the browser cannot parse throws its own error. The page, the view and the callbacks are parameters, so a test passes fakes. It holds one weak reference to the last item, with the args of that move. `land_on` is the end of a move (focus, scroll, box; the ends skip the scroll), and `read_cursor` hands the last move and a `land_` on it to the `]]` load step in `../next_page/`.
- `ends.ts`: `first` and `last` of `page.item`. `list_scroller` picks the nearest ancestor of the items that may scroll (`overflow-y` auto or scroll) and holds more than it shows, else the page. `follow_end` scrolls it to the end and puts the box and focus on the end item without scrolling it into view, so gg shows the page top and G the page bottom even when that item lies off screen (by `aria-rowindex` where the list numbers its rows, else document order), at the next read when the scroll moved. It reads the list every `END_POLL_MS` and lands again on each new end item while the page draws or loads more. It stops once the end stays the same for `END_STALL_MS`, after `END_MAX_MS` or when the user leaves (`../user_left.ts`). A last row below `aria-rowcount` keeps it going past the stall time, and a match does not stop it, because Drive counts only the rows it has loaded. The clock, the pause, the overflow read and the user watch are parameters, so a test passes fakes.
- `overlay.ts`: the box around the item, in a closed shadow root on the root element with the colours of the hint labels as var() fallbacks. Under the pointer or while the item holds the focus, it covers the item plus any descendant that pokes out of it (a hover or focus zoom), reading at most 200 elements and skipping what a box inside the item clips. Otherwise, or on an item that clips its own content (an image tile), it fits the item. It follows scroll and resize with `follow_windows` from the hints folder. A 100 ms timer clears it when the mode is no longer normal or the item is gone, puts it back on an item a layout shift moved, and follows the focus: when the user moves the focus off the item (a key press, click or wheel, read with `../user_left.ts`) the box clears at the next tick, and when a page script moves it (a loader) the box moves to the row item that takes the focus after the box was drawn (and `follow_item` in `pick.ts` makes that item the start of the next move), or clears after about 1 s when none does. It never needs a stop call from the handler. It does not use `create_surface`, because that pulls the theme and storage code into the bundle: so no user theme and no top layer.
- `main.ts`: registers the handler with the host, `item.mark` (the box as the shared focus mark: the hints bundle calls it after `]l`, `[l`, `]i`, `[i` and the `;ff` hint action when the page's own style shows no focus, and it draws only if the element still holds the focus. A mark is not a `page.item` box: `shown_` stays false for it, so `]]` does not move the focus, and the 100 ms timer clears it as soon as the element loses the focus, also inside a shadow root), and `item.cursor`, which only the next_page bundle calls through `run_command_`. Not unit tested, it needs a DOM.
- `finder.ts`: the item finder, a pure read of the page through a `PageReader` (`../next_page/detect.ts`). It finds the repeated blocks (`groups.ts`) in the page's `main` (the whole page with none), merges blocks of one kind under sibling parents (a justified grid, a feed that loads in batches), and keeps those that stack in three rows and whose items mostly hold a title link (a shown link in a heading, else a shown link of 15 characters or more in the top part of the item or to the address of the item's first link (a title under a video thumbnail), else the lone link of a tile; a heading that links with a short text names a section, so its item is no card). It joins the rows of a `tr` record (a Hacker News story). A paragraph is prose, never an item. The group must span 60% of the view height, no rival of 80% of its area that does not nest with it may exist, and 5000 characters of prose around the list make it a text page, so the answer is `none`. Inside the best group it takes the deepest group that holds 10% of its area (the cards in the sections of a front page) and keeps the outer items as `sections`. The kind is `grid` when most rows hold two or more items, else `list`. `none` is the answer whenever the finder is not sure, and then the keys scroll. A time budget (`FINDER_BUDGET_MS`, 40 ms) ends the read with a `none` marked `timed_out_`. To fit the budget it reads no box of a child with no sibling of its kind and reads computed style only for the groups left after the stacking test. The article kind is not built: prose answers `none`.
- `groups.ts`: the repeated blocks, shared with the load step of `]]` (`../next_page/load_more.ts`), so `]]` and j agree on the main list. `list_groups` reads them with rules for the item size and box (the finder lets a short item count when it holds a title link, and a `tr` count with its rows). It reads no style. `plain_block` drops chrome, carousels, sideways scrollers, fixed boxes and link menus with computed style, so the callers ask it last. `main_list` takes the one with the most area that stacks in three rows.
- `dom_reader.ts`: the `PageReader` over real elements, for the finder and the detector. It reads the children, box and style of each element once per reader.
- `derived.ts`: the derived row of the document, the finder's answer kept so a press does not read the page again. It reads again when no item of the answer shows, when its first item has left the DOM or when the address changed, and never from a mutation observer. At the end of the list a down move asks `grew_`, which reads again when what follows the last item or its parent changed (a feed that loads more, a `]]` load-more), so the added items join. A `none` answer stands for 500 ms (`NONE_RECHECK_MS`), so a held j on a page with no list does not read the page 30 times a second. A run past the time budget, or one that throws (logged with `console.error`), keeps nothing: that press scrolls and the next one reads the page again. A second timeout in a row stands for 500 ms like a `none`, so a held j on a page that always overruns does not run the finder on every repeat. A kept link that left its item reads the page again. It gives the box a selector (the tag and first class of the items) to follow a page script's focus by.

A `page.item` with no `selector` reads the derived row: the items it hands over, and for each the link the finder named takes the focus. With no item in view and none moved to, it scrolls, so the first press never jumps screens down to a list. The `item_finder` setting binds j and k that way on every page through `../../background/item_finder_row.ts`, after every other row. Such a move leaves no cursor for `]]`, so the box stays put when `]]` loads more.

Tests: `test/next_page/item_marks.test.ts` (the finder on the saved pages: kind, count, coverage of the marks, precision, known misses), `test/item_derived.test.ts` (the cache), `test/item_finder_row.test.ts` (the row and the setting), `test/content/item_finder_fallback.test.ts` (the scroll when the bundle refuses), `test/key/p49_item_finder.mjs` (the setting on in a real window), `test/site_item.test.ts` (picks, the handler on fakes) and `test/key/p45_focus_mark.mjs` (the mark: shown on a page that hides its outline, not on one that shows a style, and gone on blur, Escape, a mode change and a removed link) and `test/key/p44_item_rows.mjs` (the shipped google row on a stand-in page: movement, Enter, counts, and the box through scroll, resize, blur, Escape, a click, a mode change and a removed item, a fake loader that takes the focus and hands it to another result, a part of the item that pokes out, and the box moving to the first result `]]` loads on ddg).
