# item

The `item` bundle (`item.js`, its own guard in `tools/build.mjs`): the handler of `page.item`, which the shipped result-page site rows (`ddg`, `ddg_news`, `google`, `google_videos`, `bing`, `hackernews`, `wikipedia`, `lobsters`, `archwiki`, `startpage`, `arxiv`, `stackoverflow`, `tildes` and `reddit`) (and a user row) bind to `j` and `k` on result pages. The `google_images`, `google_news`, `google_short_videos`, `google_shopping`, `ddg_images` and `ddg_videos` rows also bind `h` and `l` on their grids. It loads on the first press. It lives apart from `site_actions` because the move and the box together are over that bundle's size limit.

- `pick.ts`: the pure picks and the handler. `step_from` takes the nearest item ahead (items whose span across overlaps the current one come first: the nearest one sets the row or column, then the largest overlap across wins, else the smallest gap across), looking at other rows for down and up and at any item that overlaps in height for left and right. `pick_item` applies a count and clamps. `place_of` finds the start: the item that holds the focus, else the last item moved to while it is on screen, else the first item not above the view. `move_item` reads the items fresh (with none found it scrolls the page by 50 px per count instead, like the plain keys, and down and up scroll the same way while the current item runs past the view edge and at the last item) (a visibility and size filter of its own, not the hint collector), moves the focus with `preventScroll`, scrolls the item to the centre when it is not fully in view, gives a non-focusable item `tabindex="-1"`, and asks for the box. A down or up that only scrolls a long item draws the box on it again. A selector the browser cannot parse throws its own error. The page, the view and the callbacks are parameters, so a test passes fakes. It holds one weak reference to the last item, with the args of that move. `land_on` is the end of a move (focus, scroll, box), and `read_cursor` hands the last move and a `land_` on it to the `]]` load step in `../next_page/`.
- `ends.ts`: `first` and `last` of `page.item`. `list_scroller` picks the nearest ancestor of the items that may scroll (`overflow-y` auto or scroll) and holds more than it shows, else the page. `follow_end` scrolls it to the end and lands on the end item (by `aria-rowindex` where the list numbers its rows, else document order), at the next read when the scroll moved. It reads the list every `END_POLL_MS` and lands again on each new end item while the page draws or loads more. It stops once the end stays the same for `END_STALL_MS`, after `END_MAX_MS` or when the user leaves (`../user_left.ts`). A last row below `aria-rowcount` keeps it going past the stall time, and a match does not stop it, because Drive counts only the rows it has loaded. The clock, the pause, the overflow read and the user watch are parameters, so a test passes fakes.
- `overlay.ts`: the box around the item, in a closed shadow root on the root element with the colours of the hint labels as var() fallbacks. It covers the item plus any descendant that pokes out of it (a hover zoom), reading at most 200 elements and skipping what a box inside the item clips. It follows scroll and resize with `follow_windows` from the hints folder. A 100 ms timer clears it when the mode is no longer normal or the item is gone, puts it back on an item a layout shift moved, and follows the focus: when the user moves the focus off the item (a key press, click or wheel, read with `../user_left.ts`) the box clears at the next tick, and when a page script moves it (a loader) the box moves to the row item that takes the focus, or clears after about 1 s when none does. It never needs a stop call from the handler. It does not use `create_surface`, because that pulls the theme and storage code into the bundle: so no user theme and no top layer.
- `main.ts`: registers the handler with the host, `item.mark` (the box as the shared focus mark: the hints bundle calls it after `]l`, `[l`, `]i`, `[i` and the `;ff` hint action when the page's own style shows no focus, and it draws only if the element still holds the focus. A mark is not a `page.item` box: `shown_` stays false for it, so `]]` does not move the focus, and the 100 ms timer clears it as soon as the element loses the focus, also inside a shadow root), and `item.cursor`, which only the next_page bundle calls through `run_command_`. Not unit tested, it needs a DOM.

Tests: `test/site_item.test.ts` (picks, the handler on fakes) and `test/key/p45_focus_mark.mjs` (the mark: shown on a page that hides its outline, not on one that shows a style, and gone on blur, Escape, a mode change and a removed link) and `test/key/p44_item_rows.mjs` (the shipped google row on a stand-in page: movement, Enter, counts, and the box through scroll, resize, blur, Escape, a click, a mode change and a removed item, a fake loader that takes the focus and hands it to another result, a part of the item that pokes out, and the box moving to the first result `]]` loads on ddg).
