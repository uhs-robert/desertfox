# item

The `item` bundle (`item.js`, its own guard in `tools/build.mjs`): the handler of `page.item`, which the shipped result-page site rows (`ddg`, `ddg_news`, `google`, `google_videos`, `bing`, `hackernews`, `wikipedia`, `lobsters`, `archwiki`, `startpage`, `arxiv`, `stackoverflow`, `tildes` and `reddit`) (and a user row) bind to `j` and `k` on result pages. The `google_images`, `google_news`, `google_short_videos`, `google_shopping`, `ddg_images` and `ddg_videos` rows also bind `h` and `l` on their grids. It loads on the first press. It lives apart from `site_actions` because the move and the box together are over that bundle's size limit.

- `pick.ts`: the pure picks and the handler. `step_from` takes the nearest item ahead (items whose span across overlaps the current one come first: the nearest one sets the row or column, then the largest overlap across wins, else the smallest gap across), looking at other rows for down and up and at any item that overlaps in height for left and right. `pick_item` applies a count and clamps. `section_starts` and `pick_section` serve `}` and `{` (`next_section`, `prev_section`: the sections come from the `section` selector of the args, else from `sections_` of the derived row, and `move_item` shows "No sections in this list" with none). `place_of` finds the start: the item that holds the focus, else the last item moved to while it is on screen, else the first item not above the view. `move_item` reads the items fresh (with none found it scrolls the page by 50 px per count instead, like the plain keys, and down and up scroll the same way while the current item runs past the view edge and at the last item) (a visibility and size filter of its own, not the hint collector), moves the focus with `preventScroll`, scrolls the item to the centre when it is not fully in view, gives a non-focusable item `tabindex="-1"`, and asks for the box. A down or up that only scrolls a long item draws the box on it again. A selector the browser cannot parse throws its own error. The page, the view and the callbacks are parameters, so a test passes fakes. It holds one weak reference to the last item, with the args of that move. `land_on` is the end of a move (focus, scroll, box; the ends skip the scroll), and `read_cursor` hands the last move and a `land_` on it to the `]]` load step in `../next_page/`.
- `ends.ts`: `first` and `last` of `page.item`. `list_scroller` picks the nearest ancestor of the items that may scroll (`overflow-y` auto or scroll) and holds more than it shows, else the page. `follow_end` scrolls it to the end and puts the box and focus on the end item without scrolling it into view, so gg shows the page top and G the page bottom even when that item lies off screen (by `aria-rowindex` where the list numbers its rows, else document order), at the next read when the scroll moved. It reads the list every `END_POLL_MS` and lands again on each new end item while the page draws or loads more. It stops once the end stays the same for `END_STALL_MS`, after `END_MAX_MS` or when the user leaves (`../user_left.ts`). A last row below `aria-rowcount` keeps it going past the stall time, and a match does not stop it, because Drive counts only the rows it has loaded. The clock, the pause, the overflow read and the user watch are parameters, so a test passes fakes.
- `overlay.ts`: the box around the item, in a closed shadow root on the root element with the colours of the hint labels as var() fallbacks. Under the pointer or while the item holds the focus, it covers the item plus any descendant that pokes out of it (a hover or focus zoom), reading at most 200 elements and skipping what a box inside the item clips. Otherwise, or on an item that clips its own content (an image tile), it fits the item. It follows scroll and resize with `follow_windows` from the hints folder. In visual item mode (`selection.ts`) the same timer and scroll follow draw a mark, a 2 px outline in the item colour, on every item of the range (a pool of boxes in the same shadow root, the cursor keeping its own box too), and `visual_count_` of the host sends the size of the range to the badge, once for each change and never from a frame outside the mode, which says `VISUAL 3`. A list in a child frame relays the count to the top frame (`ui.badge_count`). A 100 ms timer clears it when the mode is no longer normal or item, when a box drawn in item mode sees the frame leave item mode, or when the item is gone, puts it back on an item a layout shift moved, and follows the focus: when the user moves the focus off the item (a key press, click or wheel, read with `../user_left.ts`) the box clears at the next tick, and when a page script moves it (a loader) the box moves to the row item that takes the focus after the box was drawn (and `follow_item` in `pick.ts` makes that item the start of the next move), or clears after about 1 s when none does. It never needs a stop call from the handler. It does not use `create_surface`, because that pulls the theme and storage code into the bundle: so no user theme and no top layer.
- `selection.ts`: the range of visual item mode (`v` in item mode, bound in `[item_visual]`). Two ends, the anchor where `v` was pressed and the cursor that `page.item` with `extend` moves (`j`, `k`, `h`, `l`, `gg`, `G`, `}` and `{`). `o` (`direction` `other_end`) swaps them. The store keeps keys and last known places, never nodes: `keys_of` takes the link address of the items when every item has its own, else `data-id`, else the row index, one scheme per read. Each read, on every key and on the 100 ms tick of `overlay.ts`, finds each end by key (a replaced node is followed, and `follow_item` makes it the start of the next move), else at its last place clamped to the list (the neighbour of a removed item). A partial loss never ends the mode. An empty list ends it back to item mode with the notice "Selection gone". Every `extend` move carries the selector, link and section of the move before it (`carry_row` in `pick.ts`), so a site row's items stay the list. `I` in the mode is `mode.set item` and the default pick. `v` is `mode.set item_visual` and then `page.item` `current` with `extend`, which lands on the current item and starts the selection there, so the store only ever starts in visual mode. The selection ends with the mode. A short finder list (under 60 percent of the view, no row selector) that the page rebuilds node by node reads as no list, which ends the mode with "Selection gone", and so can stop a range Space part way. Item mode has the same weakness in its derived row. Tests: `test/item_selection.test.ts` and `test/key/p49_item_visual.mjs`.
- `hover.ts`: `hover_at(item)` sends the events of a mouse resting on the item's thumbnail through the sender the `;h` pick shares (`../pointer_events.ts`): pointerover, pointerenter down the ancestor chain, mouseover and mouseenter, and returns the unhover. The unhover always sends the thumbnail its out and leave pair, reading the thumbnail's place again because the page has scrolled since, and also leaves a layer the page put at that point inside the item (a preview). `thumbnail` is the first image or video at least 96 px wide. The `hover` arg of `page.item` turns it on, which the box reads: it hovers about 300 ms after the last land (a held j starts nothing on the tiles it passes), and not at all for an item removed by then. It unhovers when the item changes and on `clear` (Escape, a mode change, a focus move by the user, a removed item, the end of the page-focus grace). The focus mark of `item.mark` and an item the box follows a page script's focus to never hover. A row that names its selector and sets `hover` hovers every land. The shipped item keys set it, and only an item that holds a thumbnail gets it. The `item_hover` setting (default on) puts the arg on the shipped item keys and video rows (`../../background/item_hover.ts`).
- `main.ts`: registers the handler with the host, `item.lists` (the hints bundle's `I` picker: called with `take` it hands over the lists of the last read, short ones too, with the list of the `selector` items first while a site row's items show (`row_`), then the finder's lists that share no item with it, or the row's list alone with `row_only`, and called with `region` it makes that list active, so j and k walk it even while the old list still shows. A picked list that is not the row's, with a `selector` named, is pinned: see `lists.ts`), `item.mark` (the box as the shared focus mark: the hints bundle calls it after `]l`, `[l`, `]i`, `[i` and the `;ff` hint action when the page's own style shows no focus, and it draws only if the element still holds the focus. A mark is not a `page.item` box: `shown_` stays false for it, so `]]` does not move the focus, and the 100 ms timer clears it as soon as the element loses the focus, also inside a shadow root), `item.current` (the item item mode treats as current and its link, handed to the `take` callback: the item that holds the focus, else the last one moved to; the hints bundle reads it to label the item's targets first), and `item.cursor`, which only the next_page bundle calls through `run_command_`. Not unit tested, it needs a DOM.
- `lists.ts`: the picker's lists (`lists_with_row`: the row region first, a finder list dropped when any of its items holds, is held by or equals a row item), `pick_list` (the pick: a row pick unpins, another pick pins and puts the focus on its first item, unless the list is `focus_none_`) and `args_for_pin`, which the `page.item` handler runs first: while a pin is on it removes `selector`, `link` and `section`, so the move walks the pinned list on the finder path and leaves `]]` no cursor. The pin lives in `derived.ts` (`pin_`, `unpin_`, `pinned_`): it holds the list against the hand-over to a list in view, and ends at an address change, when a read finds none of its items, at a pick of the row's list and at `item.start`. A read that times out leaves it alone. Tests: `test/site_item.test.ts` and `test/item_derived.test.ts`.
- `start.ts`: `create_item_start`, the start of item mode that the `item_navigator` setting asks for. The ask is spent at once. When the page is idle it enters the mode only if the frame is in normal mode, no field holds the focus, the user has not pressed a key or clicked since the load, and the page shows a list: the items of the row selectors the background sends, looked for every 250 ms until 5 s after the ask, or the finder's list, read once. Each look reads the gate again right before it enters.
- `finder.ts`: the item finder, a pure read of the page through a `PageReader` (`../next_page/detect.ts`). It finds the repeated blocks (`groups.ts`) in the page's `main` (the whole page with none), merges blocks of one kind under sibling parents of one kind, the same tag and first class (a justified grid, a feed that loads in batches) and batches nested in the first one's container (a load that replaces the load-more form with a frame after the last item, whatever tag its items use, never for classless items), and keeps those that stack in three rows and whose items mostly hold a title link (a shown link in a heading, else a shown link of 15 characters or more in the top part of the item or to the address of the item's first link (a title under a video thumbnail), else the lone link of a tile; a heading that links with a short text names a section, so its item is no card, unless it is an h3 to h6 that goes to another page, as a comment's author handle does). It joins the rows of a `tr` record (a Hacker News story). A paragraph is prose, never an item. The group must span 60% of the view height to be the first list or the start on load. With no long list, the largest list that starts in the first screen of `main` (two items in two rows are enough) is the answer, as a short inbox is. A shorter group that nests in no list is kept after the others as a `pick_only_` region: the first answer, the hand-over and the start skip it, and only a pick (`pick_`) makes it active, after which it stays by item identity through a re-read. Every such group that does not nest in another is a region (a feed and its rails, the Mix panel, the related videos and the comments of a watch page), and 5000 characters of prose around a region's list drop that region. The answer is the largest region's fields plus `regions`, every region from the largest down, and `none` with no region. Inside each top group it takes the deepest group that holds 10% of its area (the cards in the sections of a front page) and keeps the outer items as `sections`. A group that is the pieces of the outer items, either small boxes in nearly every one of them (a video's title and channel blocks) or no more text-titled items than the outer items that hold them (the two halves of an inbox row), is skipped. The kind is `grid` when most rows hold two or more items, else `list`. `none` is the answer whenever the finder is not sure, and then the keys scroll. A time budget (`LONG_BUDGET_MS`, 400 ms, or `FINDER_BUDGET_MS`, 40 ms; `derived.ts` picks it) ends the read with a `none` marked `timed_out_`. To fit the budget it reads no box of a child with no sibling of its kind and reads computed style only for the groups left after the stacking test. The article kind is not built: prose answers `none`.
- `aria_lists.ts`: `find_aria_lists`, the finder's pass after its own lists and before the menus (a menu that holds, or sits in, one of its items is dropped): widgets with the role `listbox`, `grid`, `feed` or `tree`, anywhere on the page, as `pick_only_` regions after the finder's own, whatever their items hold (no title-link or span rule). The items are the shown `option`, `row`, `article` or `treeitem` descendants (a `tr` with no role in a grid counts as a row), the outermost ones for all but a tree. A tree is flat: a branch is an item too, in document order, and it stands for its own label (its first child that holds no treeitem), since the branch's box covers its children. The box follows a page script's focus onto leaves only. The header row of a grid (column headers or `th` cells) is left out. A widget is skipped when it sits in a `dialog`, `role=dialog`, `role=alertdialog`, an `aria-modal` box or a `menu`, is a combobox's popup (an `aria-controls` target), has fewer than three stacked rows or items under the item size, is a grid whose rows all hold under 16 characters of text, spaces left out (a calendar: seven day numbers), or shares an item with, or sits inside an item of, a region found before it. The pass checks the clock while it walks a widget and, when the time runs out, gives no answer: the finder keeps the lists it found before the pass, and answers a timed-out `none` only when it found none, so a cut-short read is not kept as a whole answer. A widget that holds, or sits in, an item of an earlier region (a feed that is the finder's own list) is skipped with a climb, before any walk. `links` maps each item to itself, so Enter clicks the row, and the region carries `home_` (the widget, so `derived.ts` keeps it through a page that replaces its rows), `box_selector_` (the role, which the box follows a page script's focus by) and `focus_none_` when the widget or an ancestor names `aria-activedescendant`: a pick and a landing then leave the focus alone and only the box shows the item. With the focus outside the row, the 100 ms timer of `overlay.ts` clears the box at the next tick after any key, so it is gone after Enter and the next j draws it again. The action reads the last move, not the box. Tests: `test/item_aria_lists.test.ts` and `test/key/p49_item_aria.mjs`.
- `menus.ts`: the menu pass of the finder, `find_menus(reader, out_of_time)`. The candidates are `nav`, `[role=navigation]` and `aside` over the whole page (menus sit beside `main`), dropped when a header, footer, `banner` or `contentinfo` holds them or their box lies off the page (a closed drawer, a skip link). A candidate's region is its largest stack of four or more sibling items of one signature, each at least 12 by 40 px with a shown link, in three rows (`stacked_items`), so a header bar, a breadcrumb row and a pager, which lie in one row, are no menu. No text rule, no 15-character title rule and no prose check apply, and a sticky or fixed sidebar stays. A nav inside an aside that finds the same stack gives one region. Every region is `pick_only_` and comes after the lists, the short lists and the ARIA lists (a menu that holds, or sits in, an item of an ARIA list is dropped), so a spent budget loses menus first and a page of menus alone answers `none` with `regions` set.
- `groups.ts`: the repeated blocks, shared with the load step of `]]` (`../next_page/load_more.ts`), so `]]` and j agree on the main list. `list_groups` reads them with rules for the item size and box (the finder lets a short item count when it holds a title link, and a `tr` count with its rows). It reads no style. `plain_block` drops chrome, carousels, sideways scrollers, fixed boxes and link menus with computed style, so the callers ask it last. `main_list` takes the one with the most area that stacks in three rows.
- `dom_reader.ts`: the `PageReader` over real elements, for the finder and the detector. It reads the children, parent, tag, attributes, text length, box and style of each element once per reader, because each DOM call from a content script crosses a wrapper. `query_all_` finds the page's `main` with one native query per root, the shadow roots the walk opened included.
- `derived.ts`: the derived row of the document, the finder's answer kept so a press does not read the page again. It keeps one region active. The active region stays while any of its items is in view (`in_view_`: the rectangle clipped to the view and probed at its middle with `elementFromPoint` on the item's own root, so an item that a scroll box or a fixed header covers counts for nothing). When none is and another region is in view, the next press reads the page again with the long budget (so lists that loaded since the last read compete) and the region with the most area in view becomes active, the largest winning a tie. A read keeps the region that holds any item of the old active region, or has the widget (`home_`) of the old one, while that region shows, or when no region shows. A scroll alone changes nothing, because no scroll listener exists. With no region in view the active one stays and, once the answer is `NONE_RECHECK_MS` old, the page is read again with the short budget. It also reads again when the active region's first item has left the DOM or the address changed, and never from a mutation observer. A move at a list's end stops and scrolls and does not cross into another region. gg and G (`items_(true)`, and the link lookup of a landing) keep their own region through the follow, so their scroll cannot hand the follow to another list. At the end of the list, and on a down press with every item above the view, a down move and each poll of the follow of gg and G ask `grew_`, which reads again when what follows the last item or its parent, or the parent's last child, changed (a feed that loads more, a `]]` load-more), so the added items join. A press in the middle of the list never asks it, so a node after the list that changes often costs no read. The first read at an address, and a read after the kept list dropped, get the long budget, so a long page answers once and later presses walk the kept answer. An expired `none` at the same address reads again with the short budget, and keeps the old `none` when that read times out, so a held j on a long text page does not stall. Two overruns in a row put the address on the short budget for `OVERRUN_PAUSE_MS` (10 s). The overrun count starts again at a new address. A `none` answer stands for 500 ms (`NONE_RECHECK_MS`), so a held j on a page with no list does not read the page 30 times a second. A run past the time budget, or one that throws (logged with `console.error`), keeps nothing: that press scrolls and the next one reads the page again. A second timeout in a row stands for 500 ms like a `none`, so a held j on a page that always overruns does not run the finder on every repeat. A kept link that left its item reads the page again. It gives the box a selector (the tag and first class of the items) to follow a page script's focus by.

A `page.item` with no `selector` reads the derived row: the items it hands over, and for each the link the finder named takes the focus. With no item in view and none moved to, it scrolls, so the first press never jumps screens down to a list. On a derived list h and l keep their sideways scroll, and on a derived grid they step along the row. Item mode binds j, k, h, l, gg and G that way in its keymap section (`item` in `../../background/default_keymap.ts`), and a site row can bind them with a selector in its `keymap.item` column. `item.start` (`main.ts`) is the start of the mode that the `item_navigator` setting asks for: the background sends it when a load completes, and it looks for the rows' items for a while, or runs the finder once, when the page is idle. With no selector gg and G follow the end as a bound row's do, but take the focus, the box and the pin only on an end item in view after the scroll, so the next j never jumps back, and with no item they refuse, which `scroll_if_refused` in `../run_content.ts` turns into the plain scroll to the top or bottom (it does the same when the bundle cannot load). Such a move leaves no cursor for `]]`, so the box stays put when `]]` loads more.

Tests: `test/next_page/item_marks.test.ts` (the finder on the saved pages: kind, count, coverage of the marks, precision, known misses), `test/item_derived.test.ts` (the cache), `test/item_hover.test.ts` and `test/background/tab_item.test.ts` (the item hold), `test/item_hover.test.ts` (the hover events, the 300 ms wait, unhover on change and clear, and the `item_hover` setting on the rows), `test/content/item_finder_fallback.test.ts` (the scroll when the bundle refuses), `test/key/p49_item_finder.mjs` (the setting on in a real window), `test/site_item.test.ts` (picks, the handler on fakes) and `test/key/p45_focus_mark.mjs` (the mark: shown on a page that hides its outline, not on one that shows a style, and gone on blur, Escape, a mode change and a removed link) and `test/key/p44_item_rows.mjs` (the shipped google row on a stand-in page: movement, Enter, counts, and the box through scroll, resize, blur, Escape, a click, a mode change and a removed item, a fake loader that takes the focus and hands it to another result, a part of the item that pokes out, and the box moving to the first result `]]` loads on ddg).
