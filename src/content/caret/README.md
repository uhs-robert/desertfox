# caret

The `caret` bundle (`caret.js`): caret mode, visual mode and page search.

- `motion.ts`: vim motions over a plain string, a position being the index of the character under the caret. Pure. It leaves out the screen line motions `j`, `k`, `0`, `^` and `$`. `find_char` is `f`, `t`, `F`, `T` and their repeats, over the whole text, and `find_char_matches` lists every match of the character.
- `text_model.ts`: the visible page text as one string plus a map from each character to a DOM position. An empty line made by a `<br>` maps to the `<br>` in its parent. The walk stops at 4 million characters and flags the model as truncated. It follows the rendered order into open and closed shadow roots, slots and same-origin frames, up to 4 frames deep. A frame from another origin is skipped, because the content script does not start there. The model lists the trees (documents and shadow roots) its text comes from and cuts a span into one run per tree, because a Range or a style rule reaches into one tree only.
- `selection_state.ts`: the caret and anchor indexes, and one step of a motion in caret or visual mode. Pure.
- `screen_line.ts`: the screen line motions and the scroll that brings one character in view, even inside a frame or a nested scroller, asked of `Selection.modify` because only layout knows where text wraps, and the box of one character in this script's window. `j` and `k` keep a goal x across lines and pick the nearest character on the next line by measuring boxes. `Selection.modify` stays in one document and stalls on a block shadow host, so where it stalls or the step crosses a frame or a block host, `j` and `k` take the model's next or previous line. An inline host in a wrapped paragraph keeps `Selection.modify`'s screen line.
- `selection_colors.ts`: the lualine colors for the selection, from the compiled keymap in storage, in a style element per tree with text that lives as long as the session.
- `scroll_delta.ts`: how far a view scrolls to bring a box in.
- `copy_text.ts`: the clipboard write and the yank that follows it. Visual mode ends only if the session is still the one that started the copy.
- `start_point.ts`: the first and last character on screen, found by halving the text on character boxes, and where a new session starts with no hint: in the page's own selection if it is on screen, else the first visible text. A hint's element starts at its own text or the next text after it, which the model finds as it walks.
- `page_selection.ts`: the page's own selection as a span with its direction, read from the anchor and focus because a Range has none. A drag gives an anchor and a caret on the end where the mouse was released. A click gives nothing. A new visual session and a visual session that sees the page selection change take a drag whole. Caret mode starts at the end of a drag unless a search match stands.
- `find_match.ts`: the pure half of page search. A query becomes a literal search when it has no regex syntax and a capital, else a regex, both with smartcase (a capital makes it exact) and a typed space matching a line break. An invalid pattern, or one that could backtrack without end, falls back to an escaped plain-text search and is flagged. The scan runs in slices of 8 ms, so a newer keystroke drops an older scan. Pure.
- `find_paint.ts`: draws the matches with the CSS Custom Highlight API: one highlight for all, one for the current match, capped near 2,000 ranges, a window on both sides of the current match. Each tree with text (document, frame, shadow root) adopts a style sheet of its own, because a `::highlight()` rule reaches only its own tree. A frame's registry is reached through `wrappedJSObject`, since its window seen from this script answers with this script's own `CSS`. The colors are the visual mode pair for all matches and the caret pair for the current one. A painter owns its pair of highlight names: `/` search and the character find each have one, so one never clears the other.
- `find_mode.ts`: the life of a character find that shows its matches. It starts on a typed target and ends once: on Escape, on a mode change or session end, on a key of the other family, or on any other key. A count digit keeps it. The sink cannot tell a find key from another, so a key ends the find in a microtask unless the `caret.move` handler for a find key claimed it in the same key press. Pure, with the drawing, the scroll listener and the microtask passed in.
- `visible_range.ts`: which matches to draw: those inside the on-screen range padded by its own length on each side, capped near the current one. Pure.
- `registers.ts`: named text registers over `storage.local`, as vim has them. Register `/` holds the last search.
- `find_session.ts`: the search state. `begin` reads the model when `/` or `?` opens the line, `update` runs on each keystroke, and `end` closes the search. Enter keeps the highlights and Escape clears them, and both leave the page where it is, keep the query as the last search and keep the match as the place `n`, `N` and a new caret or visual session go on from (a later click wins over it). `jump` (`*` and `#`) sets the last search to a word or selection and goes to the match from the word. `n` and `N` step in or against the direction of the last search, which sits in register `/` (`registers.ts`, in `storage.local`, never written from a private window). Escape in normal mode clears the highlights through `find.clear`. The model is read again only when a tree it read has left the page, or when a `MutationObserver` saw nodes or text change in the page, its shadow roots or its frames (`watch_page`, which skips elements OasisFox adds itself).
- `main.ts`: the sinks, the `caret.move` and `visual.act` handlers and the drawing. It paints one range per tree, each into the selection of its own document. Before each step it adopts a page selection if a find, a drag or a click moved it (no mouse listener, so a drag takes effect at the next key), and builds the model again if a frame or shadow host it read has left the page. A pending `f` makes the sink take the next key as the target, and the last find lives here for `;` and `,`. After the target the visible matches of that character stay lit (`find_mode.ts`), and the same key family repeats the find. A session starts in the sink's `enter` and ends in its `exit`, unless the page only moves between caret and visual mode. A hint on a frame from another origin shows a notice.

The caret is a one-character selection, because Firefox paints no caret on a collapsed selection in page text.
