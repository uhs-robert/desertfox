# caret

The `caret` bundle (`caret.js`): caret mode, visual mode, line visual mode (`visual_line`) and page search.

- `motion.ts`: vim motions over a plain string, a position being the index of the character under the caret. Pure. It leaves out the screen line motions `j`, `k`, `0`, `^` and `$`. `find_char` is `f`, `t`, `F`, `T` and their repeats, over the whole text, and `find_char_matches` lists every match of the character.
- `text_model.ts`: the visible page text as one string plus a map from each character to a DOM position. An empty line made by a `<br>` maps to the `<br>` in its parent. The walk stops at 4 million characters and flags the model as truncated. It follows the rendered order into open and closed shadow roots, slots and same-origin frames, up to 4 frames deep. A frame from another origin is skipped, because the content script does not start there. The model lists the trees (documents and shadow roots) its text comes from. It also lists the empty shadow roots, empty frame documents and frame elements it met, which the search watches for late content. It cuts a span into one run per tree, because a Range or a style rule reaches into one tree only.
- `page_text.ts`: the one owner of the page text, shared by the caret session and page search. It holds the newest model and calls a model current while it is the newest, every tree it read is alive, no custom element it met gained a shadow root, and no page mutation or frame `load` came since the build. A `MutationObserver` watches the page and every tree of the model, the empty ones too, and skips elements DesertFox adds itself. Each check takes the observer's pending records, so a change made in the same task counts before its record arrives. A model never changes after its build: a rebuild makes a new one, and a holder carries a position over by DOM point (`carry`, which answers undefined for a node of a removed frame). With no session open and no search line or kept match, `release` stops the watching. A plain element that attaches a shadow root later fires no mutation and is missed until another change.
- `text_object.ts`: the objects `aw`, `iw`, `as` and `is` as a cursor. A line becomes alternating text and blank units (runs of one character class for words, `Intl.Segmenter` sentences), and the object is one unit or a unit and its blank neighbor. A selection grows forward by one more object. Pure.
- `selection_state.ts`: the caret and anchor indexes, one step of a motion in caret or visual mode, and the span a session selects. Line visual mode widens the span to the screen lines of both ends, with the line bounds passed in. Pure.
- `screen_line.ts`: the screen line motions and the scroll that brings one character in view, even inside a frame or a nested scroller, asked of `Selection.modify` because only layout knows where text wraps, and the box of one character in this script's window. `j` and `k` keep a goal x across lines and pick the nearest character on the next line by measuring boxes. `Selection.modify` stays in one document and stalls on a block shadow host, so where it stalls or the step crosses a frame or a block host, `j` and `k` take the model's next or previous line. An inline host in a wrapped paragraph keeps `Selection.modify`'s screen line.
- `selection_colors.ts`: the colors of the find highlights and the selection, read from the stored theme (`desertfox_theme`) because the page document has no tokens. The selection gets an adopted style sheet per tree with text that lives as long as the session: the `selection` role in both visual modes, a `mode_caret` cell with `bg_core` text in caret mode. Each repaint adopts the sheet again if the page dropped it. A theme read colors the trees of the last paint when it settles, so a rebuild during the read still gets the sheet.
- `selection_mirror.ts`: the one writer of the page selections in a session. `paint` draws a span as one range per tree, each into the selection of its own document, and first clears what its last paint left, in a frame the model no longer reads too. It keeps the ends of each selection as its paint left them, so a later change by someone else (a find, a drag, a click, a page script) shows when the next key compares them: `foreign_cursor_` turns that change into a cursor. Every `Selection.modify` runs inside `measure`, which puts the ranges back after it, so a measure never reads as an outside move. A search marks the selections when it stands on a match (`mark`) and gives the match up once one moved (`moved_since_`). It compares on demand and listens to no `selectionchange`, which Firefox fires late, for its own paints too. `clear` spares a focused contenteditable field's caret.
- `scroll_delta.ts`: how far a view scrolls to bring a box in.
- `copy_text.ts`: the clipboard write, and `copy_yank`, the one yank path of the caret, hints and page bundles: the clipboard, then the `register_yank` message that fills the unnamed register and the one `"<reg>` named. The black hole `_` copies nowhere. Visual mode ends only if the session is still the one that started the copy.
- `start_point.ts`: the first and last character on screen, found by halving the text on character boxes, and where a new session starts with no hint: in the page's own selection if it is on screen, else the first visible text. A hint's element starts at its own text or the next text after it, which the model finds as it walks.
- `page_selection.ts`: the page's own selection as a span with its direction, read from the anchor and focus because a Range has none. A drag gives an anchor and a caret on the end where the mouse was released. A click gives nothing. A new visual session and a visual session that sees the page selection change take a drag whole. Caret mode starts at the end of a drag unless a search match stands.
- `find_match.ts`: the pure half of page search. A query becomes a literal search when it has no regex syntax and a capital, else a regex, both with smartcase (a capital makes it exact) and a typed space matching a line break. An invalid pattern, or one that could backtrack without end (a repeated group that repeats or chooses, or the same atom with an unlimited repeat twice in a row such as `a*a*b`; identical atoms only, overlapping ones such as `.*a*b` are left to the time limit), falls back to an escaped plain-text search and is flagged. The user's own regex runs in the background (`find_scan`), which stops it after 300 ms. A timeout acts like a costly pattern: while typing the old results stay, and Enter, `n` or `N` search the text instead. Literal and escaped text run in the page in slices of 8 ms, so a newer keystroke drops an older scan. Pure.
- `adopted_sheets.ts`: one adopted style sheet per tree, built with the owning document's `CSSStyleSheet`, adopted again when the page drops it, removed on `clear`. The find highlights and the selection colors both use it.
- `find_paint.ts`: draws the matches with the CSS Custom Highlight API: one highlight for all, one for the current match, capped near 2,000 ranges, a window on both sides of the current match. Each tree with text (document, frame, shadow root) adopts a style sheet of its own, because a `::highlight()` rule reaches only its own tree. A frame's registry is reached through `wrappedJSObject`, since its window seen from this script answers with this script's own `CSS`. The colors are the `search_*` pair for all matches and the `search_current_*` pair for the current one, with no bold because `::highlight()` cannot set it. A painter owns its pair of highlight names: `/` search and the character find each have one, so one never clears the other.
- `find_mode.ts`: the life of a character find that shows its matches. It starts when `caret.find` runs and ends once: on Escape, on a mode change or session end, or when a caret command that is not a find runs (`main.ts` calls `end`). A key never ends it, because the target key reaches its handler through the background, after the sink saw the key. `is_live_` is the sink's `live_`: while it holds, the key flow turns a find key into a repeat (see `LIVE_KEY` in `prefix_tree.ts`). Pure, with the drawing and the scroll listener passed in.
- `visible_range.ts`: which matches to draw: those inside the on-screen range padded by its own length on each side, capped near the current one. Pure.
- `find_session.ts`: the search state. `begin` reads the model when `/` or `?` opens the line, `update` runs on each keystroke, and `end` closes the search. Enter keeps the highlights and Escape clears them, and both leave the page where it is, keep the query as the last search and keep the match as the place `n`, `N` and a new caret or visual session go on from (a later click wins over it). `jump` (`*` and `#`) sets the last search to a word or selection and goes to the match from the word. `n` and `N` step in or against the direction of the last search, which sits in register `/`, kept by the background register store (`register_read` and `register_write` messages, so a private window keeps its own). Escape in normal mode clears the highlights through `find.clear`. It reads its model from `page_text.ts`, so a step after a change to the page reads the page again and goes on from the match it stood on, carried over by DOM point.
- `main.ts`: the sinks, the `caret.mode`, `caret.move`, `caret.find`, `visual.act`, `visual.object` and `visual.open` handlers and the drawing. `caret.mode` is the one way into a caret mode from outside the bundle, so the mode is set only once its sink is in. It paints through `selection_mirror.ts`. Before each step it adopts a page selection if a find, a drag or a click moved it (no mouse listener, so a drag takes effect at the next key), and then reads the page again if `page_text.ts` calls its model stale. The adoption comes first, so a drag survives a page that changes without pause. The key layer reads the target of `f`, so `caret.find` gets it as a param, and the last find lives here for `;` and `,`. After the target the visible matches of that character stay lit (`find_mode.ts`). A session starts in the sink's `enter` and ends in its `exit`, unless the page only moves between caret and the visual modes. A search line opened from a session keeps it too. Line visual mode measures its line bounds with `Selection.modify` before each paint, and the session keeps the span it painted for `y`, `s`, `p`, `*` and `#`. A hint on a frame from another origin shows a notice.

The caret is a one-character selection, because Firefox paints no caret on a collapsed selection in page text.
