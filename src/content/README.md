# content

The content script. It runs at `document_start` in the top frame and in same-origin frames.

- `main.ts`: the capture listener, the storage read, messages and mode wiring. Not unit tested, it needs a DOM.
- `key_flow.ts`: decides per key token whether the page keeps the key, hands tokens to the sink of the current mode, runs `browser` chords, holds plain keys until the keymap is read or a bundle has loaded and replays them in order. Pure.
- `bundle_host.ts`, `bundles.ts`: load bundles on first use and keep what they register. A bundle is a script the background injects into this frame (`hints.js`, `caret.js`, `whichkey.js`, `cmdline.js`, `ui.js`). It registers a sink per mode and a handler per command, and enters its mode with `set_mode`, through `window.oasisfox_host`. A bundle can also call a handler of another bundle with `run_command`, which loads that bundle first (search does this between `caret.js` and `cmdline.js`). `run_command` answers an `Outcome` (`src/shared/messages.ts`), the handler's real one, which stays pending while the handler waits on the user. `bundles` is the one instance. A bundle may run twice, for example after a missed deadline, so its setup must be safe to repeat. `sink.exit()` may run after the sink has already cleaned up.
- `which_key_timer.ts`, `whichkey/` (`session.ts` drops answers that came too late, `panel.ts` draws): a half-typed sequence starts a timer (`which_key_delay_ms` from the compiled keymap, zero is off). The next key, a reset or a mode change cancels it and hides the panel. Backspace in a half-typed sequence drops its last key and shows the parent group, and at the first level it clears the sequence. Escape clears it at any depth. When it fires, the `whichkey` bundle asks the background for the keys that follow (`list_keys`) and draws them under a title that chains the group names (`+Go >> +Close tabs`), then rows of key, arrow and label and a footer, in a floating frame in the corner above the badge (`which_key_border` picks the corners). Backspace shows the parent panel at once, and a new keymap cancels the timer and hides the panel. Rows past what one column holds (at most 20, 22 px each, 96 px reserved) add columns, up to 4. Shown in normal, caret and visual mode. The timer is pure and unit tested, the panel needs a DOM.
- `cancelled_keys.ts`: the keys whose keydown was cancelled, so their keypress and keyup are cancelled too. Pure.
- `mode_state.ts`, `page_mode.ts`: the modes and the pass-next flag. `page_mode` is the one shared instance.
- `plan_steps.ts`, `invocation_args.ts`: split a leaf into ordered runs and apply a command's count rule. Pure.
- `scroll_target.ts`, `editable.ts`: pure helpers for scroll choice and focus.
- `run_content.ts`: runs one invocation, or a list in order, and answers an `Outcome` that never rejects: nothing returned is done, a throw is failed, and `cancelled` means the user left a wait. The caller shows a failure once.
- `handlers/`: one plain function per content command. `handler_map.ts` is the only id-to-code link. The definitions in `src/commands` import the same handler objects, so the count rule lives in one place.
- `surface.ts`, `toast.ts`: the closed shadow root and the message surface, for refusals and for error, warning, info and success notices. Only the `ui` bundle imports them.
- `ui_proxy.ts`, `ui/main.ts`: `show_toast` and `show_mode_label` as the rest of the script calls them. They ask the `ui` bundle (`ui.js`), which holds the toast and the badge, and a call made before it loads waits and runs after. Neither holds keys. The help page loads `ui.js` by script tag, because `executeScript` is refused there.
- `mode_label.ts`, `mode_indicator.ts`: the badge text (pure) and the badge (in the `ui` bundle), top frame only. It follows the `mode_indicator` setting and sits 8 px above the bottom edge. Its colors come from `mode_colors` in the compiled keymap, which the background cuts from the `palette` and `light_intensity` settings (the page picks dark or light from the system theme), so this bundle holds no palette table.

The key test reads `data-oasisfox-tree-read-ms` and `data-oasisfox-tree-ready-at-ms` on the document element.
