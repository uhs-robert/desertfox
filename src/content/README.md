# content

The content script. It runs at `document_start` in every frame. A subframe starts on its first focus (`start_content_once` in `handlers/focus.ts`). Until then its loaded flag `desertfox_content_loaded` holds the start, so `hint --all-frames` can start the frame from the hints bundle. This costs content.js 28 bytes, under admission clause C. Every frame asks the background for its keymap, already trimmed for the page's site rule, so the content script holds no rule logic.

A property name that ends in `_` is internal, and the build (`tools/build.mjs`, esbuild `mangleProps`) shortens it in every bundle with one shared cache. Add the `_` only to a name that stays inside the extension scripts. Never to one that crosses storage, a runtime message, a port, the manifest, a DOM attribute or CSS, a page or browser API, or a file on disk. The key test reads `desertfox_host.get_mode()` through the debugger, so that one method of the bundle API, `get_mode`, stays unmarked.

- `main.ts`: the capture listener, messages and mode wiring, and the `blur_on_load` window that blurs a field the page focuses as it loads (`p24_site_blur` tests it). Not unit tested, it needs a DOM.
- `strip_tracking.ts`, `strip_setting.ts`: the `strip_tracking_params` copy rule. `strip_tracking` drops the listed query parameters from a web address and leaves the rest byte for byte. Pure and import-free, used by the page and hints bundles and the background, never `content.js`. `strip_setting.ts` asks the background (`read_strip_patterns`) for the names to drop on a page address: the global list when the site's `strip_tracking` is on, else none.
- `link_list.ts`, `link_escape.ts`: the lines of a copied link list (Markdown, Org, plain, title) and the bracket escaping they use. Pure and DOM-free, shared by `hints/yank_links.ts` and the background `copy.tabs`; `is_web_address` is the one rule for which addresses count.
- `ask_keymap.ts`: asks the background for the page's keymap at start and on `tree_updated`. A rejected ask (the background has not registered its listener yet) is retried 30 times, 100 ms apart, and then the page gets the empty tree. The newest ask wins. Pure.
- `key_flow.ts`: decides per key token whether the page keeps the key (insert mode Escape in a field passes with the `escape_to_page` site setting, see `docs/design.md`), hands tokens to the sink of the current mode (with the key's physical Latin letter when `layout_fallback` is on), runs `browser` chords, holds plain keys until the keymap is read, a bundle has loaded or the command line has handed back the keys its frame got after the line ended, or a leaf of captured-key steps (`m`, `'`, backtick) or a leaf with a jump step (`gg`, `G`, `n`: the router records the place they leave) has run, outside fields (`holds_keys_after` in `run_leaf.ts`). A held key that the keymap then leaves unbound goes back to the page as a synthetic keydown on its original element (`replay_key.ts`), so page scripts see it. Its default action (scroll, Tab focus) is lost. Keys the command line hands back are not replayed to the page. The router checks the captured key, so the keys behind it would run first. A leaf of captured-key steps that mixes in a step that waits on the user does not hold. A leaf with a jump step holds whatever its other steps: hint mode skips the holds, so a pick there gets its keys, but keys typed before hint mode starts wait until the leaf ends. `page_hidden_` drops the captured-key hold and replays nothing. A macro replay holds keys the same way for its whole run (`replay_hold` in `main.ts`), and `drop_held_` empties the held keys when the replay fails or Escape stops it. In hint mode a new key skips the captured-key holds (`is_loading_(true)` in `bundle_host.ts`), so a pick inside a macro gets its labels, while the held keys still wait for the end. Held keys replay in order, the handed-back keys first. During a load it holds only the keys that can bind (`binds_after_` in the matcher) and gives every other key to the page at once, because a replayed key loses its default action (scroll, Tab focus). While a bundle that registers a sink loads, or a sink takes the current mode, every plain key waits, since the sink may take it. It also keeps some unbound keys from the page outside fields (`cancels_unbound_key`): `/` and `'` in the modes that do not give keys to the page or own them, so Firefox's Quick Find never starts, and every plain key but Tab, the function keys, Escape and the page scroll keys in the caret modes (`is_caret_mode`). Pure.
- `bundle_host.ts`, `bundles.ts`: load bundles on first use and keep what they register. A bundle is a script the background injects into this frame (`hints.js`, `caret.js`, `whichkey.js`, `cmdline.js`, `ui.js`, `page.js`, `text.js`, `editor.js`, `site_actions.js`). `media.js` is not one of them: the background injects it itself and it talks to the background alone (`media/README.md`). It registers a sink per mode and a handler per command, and enters its mode with `set_mode_`, through `window.desertfox_host`. A bundle can also call a handler of another bundle with `run_command_`, which loads that bundle first (search does this between `caret.js` and `cmdline.js`). The host also gives a bundle `scroll_box_`, the box the vertical scroll keys move, after it ends a smooth scroll in flight (that state lives in `content.js`). `run_command_` answers an `Outcome` (`src/shared/messages.ts`), the handler's real one, which stays pending while the handler waits on the user. `bundles` is the one instance. A bundle may run twice, for example after a missed deadline, so its setup must be safe to repeat. `sink.exit()` may run after the sink has already cleaned up. A mode with a sink is set only once its sink is in: the hints and cmdline bundles set their own modes, and a caret mode is set by the caret bundle's `caret.mode` handler, which `set_mode_` in the host calls when `caret.js` is not in yet. While `caret.js` loads, every other mode change (a focus move, a `set_mode` message, a bundle's `set_mode_`) waits behind it in order (`in_mode_order_`), so a sink sees enter and exit in the order the changes came. The badge, `get_mode` and the `mode_changed` report show a caret mode only once `caret.js` has set it.
- `whichkey/` (`gate.ts` ships in content.js, not the bundle, and decides which prefix changes reach the bundle. `timer.ts` runs the timer inside the bundle, `session.ts` drops answers that came too late, `panel.ts` draws): a half-typed sequence starts a timer (`which_key_delay_ms` from the compiled keymap, zero is off). The next key, a reset or a mode change cancels it and hides the panel. Backspace in a half-typed sequence drops its last key and shows the parent group, and at the first level it clears the sequence. Escape clears it at any depth. When it fires, the `whichkey` bundle asks the background for the keys that follow (`list_keys`) and draws them under a title that chains the group names (`+Go >> +Close tabs`), then rows of key, arrow and label and a footer, in a floating frame in the corner above the badge (`which_key_border` picks the corners). The delay applies only to the first panel: while one is up (the timer remembers that the session drew a nonempty one), each further prefix key redraws at once, as Backspace does. A prefix that exactly matches an entry of `which_key_skip` (carried in the compiled keymap) starts no delayed open, so its panel does not open after the delay. An instant redraw (Backspace, or a panel already up) ignores the list and still shows it. `?` lists only the first keys of the mode. A new keymap cancels the timer and hides the panel. Rows past what one column holds (at most 20, 22 px each, 96 px reserved) add columns, up to 4. Shown in normal, caret, visual, media, insert and hint mode. `<A-?>` opens the first-keys panel in each of them, but insert and hint mode show no panel after a pause. Ignore and the command line have no such key. In insert mode with no field focused the chord goes to the page. The timer is pure and unit tested, the panel needs a DOM.
- `player_box.ts`: the element that goes fullscreen for a media element, shared by the `fullscreen` hint action and the `media fullscreen` command. Pure.
- `replay_key.ts`: the synthetic keydown (and keyup) that hands a replayed key to its original element, and the `isTrusted` guards of the keypress and keyup listeners. Pure.
- `cancelled_keys.ts`: the keys whose keydown was cancelled, so their keypress and keyup are cancelled too. It also cancels a keyup whose keydown this frame never saw, so a page never acts on half a press that began in another frame, except in ignore mode and while DesertFox is off, where the page gets that keyup. Pure.
- `site_mode.ts`: the site mode in force, plain state. `main.ts` swaps the matcher tree to normal plus the mode's keys (`install_tree`) when it changes, and ends it on a keymap update, a mousedown, a mode change and a key the keymap does not cancel. `mode.site` and `mode.escape` set it.
- `mode_state.ts`, `page_mode.ts`: the modes and the pass-next flag. `page_mode` is the one shared instance. `fullscreen_step` is the pure rule that starts and ends the media mode with a fullscreen change, and hint and command line mode remember the mode they began in, so Escape and the end of a pick return to it.
- `mode_report.ts`: each frame reports its mode to the background on every change, at start, when its window gains focus and when its page is shown. Each report says whether the frame's own document holds the keyboard focus (`holds_own_focus`). The background answers the top frame with the mode of the child frame that holds the focus (`frame_mode`), and the top frame's badge shows that mode in place of its own. A top frame in ignore mode gets none and shows IGNORE, so a field in a frame does not hide ignore mode.
- `relay.ts`: a bundle in a subframe asks the background to run one of its handlers in the top frame or in another frame of the tab. The allow list and the direction of each handler are in `src/shared/relay.ts`. The command line, which-key and the toasts use it, so they draw in the top frame for a subframe that holds the keys.
- `hidden_frame.ts`: the size test for a hidden input frame, a child frame the user cannot see, which a page keeps to take typed text. In normal mode such a frame hands the focus to the document that holds it (`hand_focus_to_parent` in `handlers/page.ts`, called one tick after each mode report, and at once after Escape blurs the field), and `gi` in that document finds the frame's field (`handlers/focus_input.ts`). Pure.
- `invocation_args.ts`: applies a command's count rule. Pure.
- `scroll_target.ts`, `editable.ts`: helpers for scroll choice and focus. `editable.ts` holds the frame's `editable_add`, `editable_remove` and `editable_remove_unsized` rules, which `main.ts` sets from the page keymap reply. `pick_scroll_target` takes the frame's `scroll_selector` match first (`handlers/scroll.ts` holds the selector). The scan of the whole page that finds the largest scrolling box does not run on every key: `scroll_target` keeps its pick per axis in a weak reference and reuses it while the box is connected and still scrolls on that axis. A `focusin`, a `pointerdown` or a 1 s pause between scroll keys drops it. A bundle asks the host's `is_editable_` instead of its own copy.
- `scroll_box.ts`: whether an element is a box that scrolls (`candidate_of`), used by the scroll keys and the `scrollable` hint filter.
- `run_content.ts`: runs one invocation, or a list in order, and answers an `Outcome` that never rejects: nothing returned is done, a throw is failed, and `cancelled` means the user left a wait. The caller shows a failure once. `run_content_steps` runs a leaf of content steps in order, each after the one before has finished. A leaf with any background step skips it and goes to the router whole (`run_leaf_` in `main.ts`), which reads the active tab per step. A leaf of content steps sends a `record_step` message with its outcome when it ends (not for a held key's repeats), which the background keeps for `.`.
- `handlers/`: one plain function per content command. `handler_map.ts` is the only id-to-code link. The definitions in `src/commands` import the same handler objects, so the count rule lives in one place.
- `surface.ts`, `toast.ts`: the closed shadow root in a top-layer popover host (above modals) and the message surface, for refusals and for error, warning, info and success notices. `surface.ts` also fills each surface with its theme and user CSS sheets after the built-in style (see `shared/theme/apply.ts`), one storage read and one change listener per bundle. The lazy bundles import it, never `content.js`.
- `ui_proxy.ts`, `ui/main.ts`: `show_toast_` and `show_mode_label` as the rest of the script calls them. They ask the `ui` bundle (`ui.js`), which holds the toast and the badge, and a call made before it loads waits and runs after. Neither holds keys. In a subframe, `ui/main.ts` sends each toast to the top frame, and draws it in the subframe only when the top frame does not answer. In the top frame, `ui/frame_hide_watch.ts` checks the child frame that holds the focus every 300 ms while the background says one does (`frame_mode`), and takes the focus back when that frame turns transparent or shrinks. content.js turns it on through `ui.frame_watch`, so the bundle loads when a child frame first takes the focus. A frame of another site cannot see its own frame element, so the child cannot watch itself. The help page loads `ui.js` by script tag, because `executeScript` is refused there.
- `badge_state.ts`, `mode_indicator.ts`, `ui/mode_label.ts`: `badge_state` hands the `ui` bundle the mode, the pass-next flag, the setting, the recording name and the site mode label (only in normal mode, and it shows under `mode_indicator = not_normal` too), or nothing where no badge shows (hint and command line modes and a quiet setting, unless a macro records), so those cases load no bundle. `ui/mode_label.ts` words the text (pure, with `recording @a` added while a macro records). `mode_indicator.ts` draws the badge, top frame only. It shows the mode of the frame that holds the focus (see `mode_report.ts`). A child frame's pass-next flag does not show. It follows the `mode_indicator` setting and sits 8 px above the bottom edge. Its colors are the theme tokens `--desertfox-mode-<mode>` and `--desertfox-bg-core`, picked by a `data-mode` attribute, so the light variant follows the theme sheet that `surface.ts` adds.

`data-desertfox-tree-read-ms` on the document element is the one test hook allowed in `src/`. The key test reads it as the signal that the content script is ready.
