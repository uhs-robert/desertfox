# grab

The `grab` bundle (`grab.js`): keyboard drag. `hint --grab` (`;gg`) picks an element, then a target, and drives a drag between them. `hint --grab_swipe` (`;w`) picks a swipeable element and enters grab mode as a swipe: `h j k l` fling it (`l` shows the next slide), Escape ends it. `hint --grab_move` (`;Gg`) picks an element and enters grab mode, where `h j k l` move it, `[` and `]` halve and double the step, Enter drops it and Escape ends it (a range input and a draggable element go back first, a pointer drag releases where it is).

- `main.ts`: the `grab.mode` handler that takes a hint pick (the hints bundle leaves the element in `desertfox_pick_target`, as for the caret), the `grab.move`, `grab.step`, `grab.drop` and `grab.cancel` handlers, and the grab mode sink. The sink passes every key to the keymap and exists for `exit`, which every way out of the mode reaches, so a held drag always ends. `;gg` and `;Gg` pick from the draggable group (`hint --grab --draggable`); a source with no drag sign (a div thumb with the default cursor) is picked with `;ga`. The target hint of a grab is run again through `hint.run` with the `every` filter, so any element can take the drop.
- `drag.ts`: the synthetic input, in three routes chosen by the source. A draggable element (or one inside it) gets DragEvents with a new `DataTransfer`, because mouse events never start a native drag. A range input gets a value plus `input` and `change`. Any other element gets pointer and mouse events. `release` and `abort` always send the closing events (`pointerup` and `mouseup`, or `drop` and `dragend`, or `change`). `press` lands on the slider's thumb (`press_point`), so no slider jumps on grab. `abort` puts a range value back and ends an html5 drag with no drop, and releases a pointer drag where it is. `scale_step` sets the per-drag step of `[` and `]`.

- Swipe: `snap_scroll` scrolls a scroll-snap box by one view. Any other target gets `start_fling` and `fling`, a forced pointer-route drag of 60% of the box in 4 steps of 8 ms. The `swiping` element in `main.ts` makes `grab.move` fling instead of nudge, and `grab.drop` leave the mode.

Limits: the events are not trusted, so a page that checks `isTrusted` ignores the drag. A drag stays inside one frame. A drag to another tab or app needs real input through the host and is not built. A page that calls `setPointerCapture` with the synthetic pointer fails in its own code, and the drag goes on.
