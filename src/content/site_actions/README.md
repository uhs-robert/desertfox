# site_actions

The `site_actions` bundle (`site_actions.js`, its limit is in `MAX_BYTES` in `tools/build.mjs`). The content script loads it on the first press of a command that site rows bind to keys, so these handlers stay out of `content.js`.

- `send_key.ts`: the `page.send_key` handler. It sends a `keydown` and a `keyup` with a key name, a legacy key code and the modifier flags that are on (`ctrl`, `shift`, `alt`, `meta`) to the element the selector finds, or to the focused element. With `keypress` on it adds a `keypress` between them. It refuses when the selector matches nothing or does not parse. `send_key_queued` sends through one queue per page that keeps at least `KEY_PAIR_GAP_MS` (10 ms) between pairs, because Sheets applies only the first of several pairs that arrive in the same millisecond. The count arrives as the `times` param, and a call is one queue entry, so its steps all go out before the next call starts. The events are untrusted, so the content script ignores them and the key does not loop. The document and the event maker are parameters, so a test passes fakes. It holds the queue state of the page (the queue tail and the time of the last send) and is otherwise pure.
- `arrow.ts`: the `page.arrow` handler, bound by the shipped `arrow` site mode. Firefox ignores a script's arrow keys on its own controls, so it works on the focused element by kind: a select steps over disabled options, a range steps up or down, a radio gets a click on the next radio of its group (the browser checks it and fires `click`, `input` and `change`, which a script framework reads), and a select or range fires `input` and `change` itself. The body or no focus scrolls 50 px through the host. Any other element gets `send_key` arrows, which only page scripts read, and the page scrolls when it did not cancel the keydown. A count repeats the step inside one queue entry, one `KEY_PAIR_GAP_MS` apart. The focus lookup (deepest element through shadow roots), the scroll function and the event maker are parameters, so a test passes fakes.
- `clipboard.ts`: the `page.clipboard` handler. It focuses the target, runs `document.execCommand` for the action and counts the action as taken when the matching event fired (a capture listener on the document, and the return value is ignored), and refuses a target that did not take focus. A paste that fired no event falls back to `paste_through_clipboard_api`, which reads `navigator.clipboard` (rich data with `read`, else `readText`) and dispatches an untrusted `paste` event carrying it, and refuses when the page did not cancel that event. A cut or copy that fired nothing refuses. It is otherwise pure: the document and the fallback are parameters.
- `main.ts`: registers the handler with the host. Not unit tested, it needs a DOM.

The `page.item` handler is not here: it lives in the `item` bundle ([`../item/`](../item/README.md)), because the move and its box do not fit this bundle's size limit.
