# hints

The `hints` bundle (`hints.js`). The background injects it into a frame on the first `hint.run` or the first entry into `hint` mode.

- `main.ts`: registers the `hint` sink and the `hint.run` handler. `hint.run` enters hint mode at once, finds the visible elements, draws labels and waits for one to be typed. Keys typed while it finds elements wait and replay. Reads the `hint_letters` setting from the stored config status. With `rapid`, a pick keeps hint mode and builds the hints again, so deleted or moved elements stay right, and Escape ends it. With `text`, only links whose text holds it (ignoring case) get labels. One match runs at once and ends hint mode, also with `rapid`. None shows "No link matches ...". A custom selector that does not parse shows a notice.
- `candidates.ts`: one query per filter (`buttons` takes `button`, `[role=button]` and the button-like `input` types, enabled only), a selector and an optional test for what a selector cannot say (`prose` keeps the elements with a non-blank text node of their own, so a wrapper of spans gets no hint; `scrollable` keeps the boxes `is_scroll_box` accepts, see `../scroll_box.ts`), plus "weak" candidates for `all` and `clickable`: a pointer cursor where it starts (or on any `<a>` without href), and a `tabindex=-1` item with a click-like role or inside a menu or a roving group (a tabindex 0 sibling). A weak candidate gives way to a visible clickable element inside it or around it (checked after the visibility pass), so a page of pointer wrappers gets one hint per thing. A walk that reaches open and closed shadow roots and same-origin frames. A cross-origin frame gets no hints, because the content script does not start in a frame that cannot reach the top document.
- `visible.ts`: keeps what a person can click: inside every scrolling box, not hidden, and not under another element. Tries up to eight points per link (the middle of each line box, then the corners of the first), so a wrapped link or one part covered still counts. The boxes are clipped to the scrolling ancestors first (not body, html, or inline boxes, and each axis on its own), so a half scrolled item is probed on its shown half. A box with no area (also `display: contents`, which an IntersectionObserver ignores) falls back to its children's boxes and observes them. Tested in each parent document for a framed element. Reads the page only through `PageProbe`, so tests use a fake page.
- `labels.ts`, `pick.ts`: the label generator (prefix-free, built from the letters) and the typing rules. Pure.
- `actions.ts`: what a picked element gets: a click or focus. A click is the whole mouse sequence (pointerover, pointerenter, mouseover, pointerdown, mousedown, focus, pointerup, mouseup, then `click()`), so dropdowns that open on mousedown open. `dispatch_mouse_event` sends one of them and is the piece a hover action reuses. A field only takes focus. open in a place, copy the address (`copy`, the text for a non-link) or the text (`copy_text`), focus, delete. `focus` gives an element with no `tabindex` attribute `tabindex=-1` first (a page's own value stays) and, for anything but a field, flashes an outline for under a second, so `;s` shows which box a scroll key now moves. `caret` and `visual` hand the element to the caret bundle (see `caret/main.ts`, `start_session`) and ignore `rapid`.
- `view.ts`: labels in a closed shadow root. They use the which-key colors: `--oasisfox-secondary` text and `--oasisfox-accent` border on the `--oasisfox-bg-core` background.
- `follow.ts`: repositions the labels on the next animation frame after a scroll or resize in the top window or a frame window.

The registry never imports this folder. The command and its params sit in `src/commands/hint.ts`.
