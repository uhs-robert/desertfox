# hints

The `hints` bundle (`hints.js`). The background injects it into a frame on the first `hint.run` or the first entry into `hint` mode.

- `main.ts`: registers the `hint` sink and the `hint.run` handler. `hint.run` enters hint mode at once, finds the visible elements, draws labels and waits for one to be typed. Keys typed while it finds elements wait and replay. Reads the `hint_letters` and `hint_key_line` settings from the stored config status. With `rapid`, a pick keeps hint mode and builds the hints again, so deleted or moved elements stay right, and Escape ends it. With `text`, only links whose text holds it (ignoring case) get labels. One match runs at once and ends hint mode, also with `rapid`. None shows "No link matches ...". A custom selector that does not parse shows a notice. Each run first asks the background for the frame's `hint_add` and `hint_remove` (`read_hint_selectors`) and holds the keys typed meanwhile, so they reach hint mode. A selector of those that does not parse is skipped with one notice.
- `prompt_line.ts`: the `prompt` action (`;:`). `prompt_pick` reads the address of the pick (`element_address`, a refusal when there is none) and asks the host to open the command line with `<command> <address>`, through `host.run_command_("cmdline.open", ...)`, so keys typed while cmdline.js loads stay held for the line. `quote_for_line` single-quotes an address the line would split or misread (whitespace, quotes, a backslash, a leading `-` or `@`). The pick's answer is the line's, so it stays pending until Enter or Escape. `rapid` is off for it.
- `collect_copy.ts`: rapid `copy` and `copy_text`. `collect_pick` adds the text to the session's list unless it is there, and returns the whole list (one entry per line) and the toast words. `main.ts` copies the whole list on every pick, because Escape gives no user activation to write the clipboard.
- `candidates.ts`: one query per filter (`buttons` takes `button`, `[role=button]` and the button-like `input` types, enabled only), a selector and an optional test for what a selector cannot say (`prose` keeps the elements with a non-blank text node of their own, so a wrapper of spans gets no hint; `every` keeps any box with a size, except a wrapper of one element child and no text of its own (a link, button or label is exempt), so `;yc` and `;yh` pick the inner element; `scrollable` keeps the boxes `is_scroll_box` accepts, see `../scroll_box.ts`; `media` takes `video, audio` and `main.ts` skips the cover test for it; `images` keeps an `img`, an image button or a box with a CSS background image, from 24 px on both sides (`is_image`), and skips the cover test too; `frames` keeps `iframe` and `frame` from 24 px on both sides, never the command line frame (`is_pickable_frame`), and keeps the cover test), plus "weak" candidates for `all` and `clickable`. `with_site_selectors` adds the `hint_add` matches for `all`, `clickable` and `every` (marked `added`, so a weak wrapper gives way to one) and drops what sits in a `hint_remove` match for every filter but `custom`: a pointer cursor where it starts (or on any `<a>` without href), and a `tabindex=-1` item with a click-like role or inside a menu or a roving group (a tabindex 0 sibling). A weak candidate gives way to a visible clickable element inside it or around it (checked after the visibility pass), so a page of pointer wrappers gets one hint per thing. A walk that reaches open and closed shadow roots and same-origin frames. The walk stops at a frame of another site: that frame hints itself once the user focuses it and its own script starts.
- `visible.ts`: keeps what a person can click: inside every scrolling box, not hidden, and not under another element. Tries up to eight points per link (the middle of each line box, then the corners of the first), so a wrapped link or one part covered still counts. The boxes are clipped to the scrolling ancestors first (not body, html, or inline boxes, and each axis on its own), so a half scrolled item is probed on its shown half. A box with no area (also `display: contents`, which an IntersectionObserver ignores) falls back to its children's boxes and observes them. `anchor_box` gives the label the same fallback, and a link with no box gets a hidden label. Tested in each parent document for a framed element. Reads the page only through `PageProbe`, so tests use a fake page.
- `selector_of.ts`: the shortest unique CSS selector of an element for `copy_selector`. Pure: the caller passes a function that counts matches in the element's root. Skips ids and classes that look generated.
- `labels.ts`, `pick.ts`, `rank.ts`: the label generator (prefix-free, built from the letters), the typing rules and the text ranking. Pure. `pick.ts` has two modes. Label mode types a label. `/` enters text mode, where one-character keys and Space build a query, `rank.ts` orders the hints (whole word over prefix over substring, first word over later words, shorter text over longer), Tab and Shift-Tab move the active hint, Enter picks it, one match picks at once, and Backspace on empty text returns to label mode. In label mode Tab does nothing. Space in label mode makes the picker answer `rotate`, and `labels.ts` holds the pure part (`overlap_groups`, `rotate`). `main.ts` reads the hint texts (`text_of` in `candidates.ts`) on the first `/`, and every build starts in label mode. A pick that typed its last key waits 300 ms with hint mode open (`PICK_GRACE_MS`) and drops the keys that arrive, so the rest of the word does not run as commands. Enter picks at once, and Escape in the grace cancels the pick. `name_candidates` in `candidates.ts` is the one fallback chain for an element's name (text, aria-label, title, picture alt, input value except a password). Tab, Shift-Tab, Enter and Space are bound in the hint keymap to `hint.key` (`src/commands/hint_text.ts`) only so the content script holds them during the bundle load. `/` has a row for its which-key label only, because every one-character key is held already. `pick.ts` holds two modes. Label mode types a label. `/` enters text mode, where one-character keys and Space build a query, `rank.ts` orders the hints (`score_text`, `rank_items`: whole word over prefix over substring, first word over later words, shorter text over longer), Tab and Shift-Tab move the active hint, Enter picks it, one match picks at once, and Backspace on empty text returns to label mode. In label mode Tab does nothing. Space in label mode makes the picker answer `rotate`, and `labels.ts` has the pure part of it (`overlap_groups`, `rotate`). `main.ts` reads the hint texts (`text_of` in `candidates.ts`) on the first `/`. Every build starts in label mode.
- `inspect.ts`: the `inspect` action (`;o`). It sets `window.wrappedJSObject.__desertfox_pick` to the element and sends `inspect_pick`. The devtools page selects it and deletes the property. The content script deletes it itself when the background gives no answer or the send fails, and after 60 s. A script in a frame refuses, because the devtools eval runs in the top window. The action skips the cover test, so an overlaid element is a target. A closed toolbox gives the "press F12" toast and the pick waits 60 s in the background.
- `actions.ts`: what a picked element gets: a click, a focus, open in a place, copy the address (`copy`, the text for an element with no address, a refusal for a picture with none; `element_address` reads the element's own href, image or media source, never an ancestor's) the text (`copy_text`), the CSS selector (`copy_selector`, from `selector_of.ts`) or the outer HTML (`copy_html`), the picture (`copy_image`) or a saved file (`download`), both of which send the address to the background and never fetch it here (a missing answer from the background is a refusal), focus, delete, hover, and on media play or pause, mute and fullscreen (`player_box` in `../player_box.ts` finds the element to show). A click is the whole mouse sequence (pointerover, pointerenter, mouseover, mouseenter, pointerdown, mousedown, focus, pointerup, mouseup, then `click()`), so dropdowns that open on mousedown open. A cancelled pointerdown skips the mousedown, mouseup and focus, and a cancelled mousedown skips the focus, as in a browser. A field only takes focus. `dispatch_mouse_event` sends one event, with an optional click count `detail`, and is the piece the hover and double-click actions reuse. `double_click` (`;2`) sends the over and enter events, then two presses (the same press and release, `detail` 1 and 2) each followed by a dispatched `click`, then `dblclick`, and selects the word under the middle when that point is in a text node outside a field. `find_candidates` in `main.ts` drops links and their children, across shadow roots, for it. The word comes from `Intl.Segmenter` and is set as a range, so a point on a word start picks that word and a space picks nothing. `focus` gives an element with no `tabindex` attribute `tabindex=-1` first (a page's own value stays) and, for anything but a field, flashes an outline for under a second, so `;s` shows which box a scroll key now moves. `hover` (`hover.ts`) moves a pointer like a real one: pointerout and mouseout on the old element (with `relatedTarget`), leave only on the old element and ancestors that do not contain the new one, then over, enter (only on ancestors the pointer was not in), pointermove and mousemove from the middle of the new one. So hovering an item inside a hovered menu keeps the menu entered. Ancestors include the shadow host above a shadow root, and one point (the new element's middle, or where the old one was entered) serves the whole move. A click or double-click pick enters its target the same way, from the element the pointer was on, so the shadow host and menu above it get their enter events (without the move events), and the target becomes the hovered element, so the next pick or Escape leaves it and a second pick inside one menu enters the menu only once. A pick inside the hovered element makes the picked element the hovered one, so Escape still closes the menu. A pick that sends no entry (copy, delete) leaves it unentered, and a later hover of it sends the entry. A new hover, Escape (the `hint.unhover` handler, called from `mode.escape`), a hidden tab or another pick (toward its target) ends the hover. A removed element gets no events. Synthetic events do not set CSS `:hover`. `caret` and `visual` hand the element to the caret bundle (see `caret/main.ts`, `start_session`) and ignore `rapid`.
- `view.ts`: labels in a closed shadow root. A label is filled with `--desertfox-primary`, with a 1px `--desertfox-primary` border so its size stays the same, and its text is `--desertfox-bg-core`. The letters already typed show at 60% opacity. In text mode the active hint swaps the label colors and a box shows the typed text. `add_key_line_` draws the key line at the bottom right (words fixed in `KEY_LINE_LABELS` and `KEY_LINE_TEXT`, switched in `show_progress_`), in its own node because `show_message_` wipes the container. `main.ts` adds it unless the `hint_key_line` setting is false. `rotate_overlaps_` (Space) reads every shown label box, groups the overlapping ones and moves the top label of each group under the others. In text mode the active hint swaps the label colors and a box shows the typed text. `rotate_overlaps_` (Space) reads every shown label box, groups the overlapping ones and moves the top label of each group under the others.
- `headings.ts`: the headings of the page for the `heading` command and for `page.heading` (`]h`, `[h`). `step_heading` finds the headings with the same rules, `pick_heading_step` picks from the last jumped heading while it is on screen (one weak reference), else by the top of each heading from the view top (next is the first below it, previous the last above it). A count clamps and none is a notice and `scroll_to_top` moves. The `heading` command (`src/commands/heading.ts`) is the one the command line lists. `heading.list` reads the page and keeps a snapshot of the headings and their frames, `heading.go` jumps to one by its number or its text, and `heading.clear` drops the snapshot. The command line host calls the three (`src/cmdline/host.ts`). Headings are checked with `keep_present_` and not `keep_visible`: a box of real size that no scroll box clips and that `checkVisibility` (visibility and opacity) accepts (Firefox gives the content of a closed `<details>` a box, so a box test alone keeps it), wherever it sits on the page. A heading in a frame passes only when its frames pass the same rules. `heading.go` refuses with "That heading is gone" when the element left the page, and scrolls the heading and then each frame that holds it to the top, innermost first, touching nothing else.
- `follow_links.ts`: the link search of `page.follow` (`]]`, `[[`), run from `main.ts` with the `next_patterns` or `prev_patterns` setting. A link marked `rel` next or prev (`link`, `a` or `area` with an `href`, no box needed) wins, the first in page order. Otherwise the best link or button by text: an earlier pattern first, then a link over a button, then the shorter text. A text matches a pattern as a substring when it has at most four words, and a pattern of one or two characters (an arrow) must be the whole text. The text is the visible text, `aria-label`, `title` or the `value` of an input. Off-screen items count (`keep_present_found`, not the viewport test of hints). A `<link>` navigates by its address and anything else is picked like a hint of the same place. A `javascript:` or `data:` link refuses to open in another tab or window (`can_open_elsewhere`). The search reads the top page, shadow roots and same-origin frames. A frame of another site is a gap: its links stay out of reach, because the top page cannot read it.
- `focus_fields.ts`: the pick of `page.focus_field` (`]i`, `[i`). The controls are the `FORM_CONTROLS` selector, found by `collect` and kept by `keep_present_found` (off-screen ones count). `place_of` finds the start (focused control, else `host.last_blurred_()`, which the content script answers when the bundle runs, else the first control not above the view) and `pick_field` moves by the count and clamps, or answers `end`, which `main.ts` turns into a notice. The control is focused with `preventScroll` and then centered in each window that holds it, when not fully in view. `gi` does not use this list.
- `yank_links.ts`: the list of `copy.links` (it drops tracking parameters before it merges equal addresses) (`yL`, `yl`, `:copylinks`). The page scope takes the `links` query through `collect` and `keep_present_found`, the viewport scope takes `keep_visible_ones`. Only http, https, ftp and file addresses count, and a link to a fragment of the same page is dropped. The first link to an address wins, the list stops at 500, and the text falls back from the visible text to aria-label, title, image alt and the address. Formats are Markdown, Org and plain, one line per link. It escapes brackets with `../link_escape.ts`, which is pure and has no imports.
- `insert_text.ts`: types the keys a pick queued into the field it focused, through the shared writer in `../text/field_writer.ts`. A pick that focuses a field, and `]i`/`[i`, also mark it as the entry of typed text (`../text/entry.ts`).
- `follow.ts`: repositions the labels on the next animation frame after a scroll or resize in the top window or a frame window.

The registry never imports this folder. The command and its params sit in `src/commands/hint.ts`.
