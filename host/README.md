# host

The native-messaging hosts (the config host and the bridge host) and the script that installs them. Linux only. Design: `docs/design.md`, Native host.

- `desertfox-host`: Python 3.9+, stdlib only. Firefox starts it for one request and it exits after one reply: a 4-byte native-endian length, then UTF-8 JSON. Verbs: `read_config` and `write_autoconfig`. Its only write is `autoconfig.toml` in the config folder. `DESERTFOX_CONFIG_DIR` replaces the folder, for tests. The file set `read_config` returns mirrors `tools/build-config/source_files.ts`, minus `autoconfig.toml`.
- `install.sh`: `install.sh <version|main> [--channel main]`. A version fetches the host from that GitHub release and refuses to install on a checksum mismatch. `main` fetches from the main branch with no checksum. The script is one function called on its last line, so a cut-off download runs nothing. It writes both hosts and the `desertfox` command line to `$XDG_DATA_HOME/desertfox/` (a relative value is ignored, default `~/.local/share`), the manifests to `~/.mozilla/native-messaging-hosts/desertfox_host.json` and `desertfox_bridge.json`, and a symlink `~/.local/bin/desertfox` (left alone when a file that is not a link is there), and stops with an error without python3 3.9 or newer.
- `desertfox`: the command line for the bridge socket, see below.
- `test_host.py`, `test_install.py`, `test_cli.py`, `host_under_test.py`: run them with `just host-test`. The install tests use a temporary HOME and a stubbed `curl`, and never touch the real home folder or the network. `test_install.py` also runs `just release_publish` against a stubbed `gh`, and `just release_commit_push` against a local bare remote. `just release` commits and pushes the bump first, so the release tag targets that commit.

## Bridge host

- `desertfox-bridge`: Python 3.9+, stdlib only, native name `desertfox_bridge`. Unlike the config host it stays alive on a `connectNative` port while the extension has `bridge = true` and the `nativeMessaging` permission. It takes the lock, then says `{"ready": true, "host_version": 1}` once, and the extension trusts the port only after that. It takes two verbs from the extension, `mode` and `reply` (the answer to a request the host sent), and skips a malformed or oversized message.
- Files, all in `$XDG_RUNTIME_DIR/desertfox/` (created with mode 0700). The host writes nothing else.
  - `bridge.lock`: the first host to take its `flock` owns the socket and the state file. A second host waits 3 s for it, then exits with code 1 and says nothing on stdout. The kernel drops the lock when its holder dies.
  - `bridge.sock`: a Unix socket, mode 0600, made under a restrictive umask. A leftover file from a crashed host is replaced at start. A connection from another uid is closed. One JSON object per line in, one line out. Verbs: `ping` gives `{"ok": true}` and `state` gives `{"ok": true, "state": <snapshot or null>}`. `run` (`{"verb": "run", "command": "<command line>"}`) and `list` go to the extension, which decides what runs. The host sends `{"verb": "run", "request_id", "command"}` or `{"verb": "list", "request_id"}` on stdout and routes the reply that carries the same `request_id` back to the connection that asked. A run reply is cut to `ok` and `message` (500 characters at most), so no page data can pass. A `list` reply is `{"ok": true, "commands": [...]}`. Anything else gets `{"ok": false, "message": ...}`. Requests are capped at 64 KiB, idle connections close after 5 s, and at most 16 are open. Each connection gets 10 requests per second, and an excess request is answered with an error and goes no further. At most 16 requests wait on the extension, one waits 10 s at most, and every waiting request fails when the port closes.
  - `state.json`: `version` (2), `seq`, `host` (`pid`, `start`), `firefox`, `mode`. A normal window gives `firefox` as `window_id`, `private` and `mode` as `id`, `label`, `tab_id`. A private window gives `firefox` as `{"private": true}` and `mode` as `id` and `label` only. The extension sends no ids for a private window and the host drops them if it did. Writes go to a temp file in the same folder and are renamed. The host removes a leftover file at start and its own files on exit. The shell reader treats a dead or reused `pid` as no state.
- The installer puts both hosts in place (see above). Check `$XDG_RUNTIME_DIR/desertfox/state.json` after a key press in Firefox, with `bridge = true` in `settings.toml` (or `:set bridge true`) and the permission granted on the `:native.install` page.
- `desertfox` (the command line): `desertfox run <command> [args...]` runs one command in the focused Firefox window, `desertfox list [--json]` prints the allowed commands (command word, id, label and params, tab separated) and `desertfox state [--json]` prints the latest snapshot. A single argument to `run` is the command line as it is, several are quoted into one. It prints plain text, errors on stderr. Exit codes: 0 done, 1 refused or failed, 2 bad usage, 3 the bridge is not running. What may run is the extension's decision: the command's `bridge` field, a never-list and the one validator (see `docs/design.md`, Bridge host).
- `test_bridge.py`: real processes with a temporary `XDG_RUNTIME_DIR`: two hosts at once, a stale socket after a kill, atomic writes, the socket verbs, caps and rate limit, `run` and `list` routing between clients, and a client or the extension leaving mid-request. `test_cli.py` runs the command line against a fake socket and the real host. Run with `just host-test`.
